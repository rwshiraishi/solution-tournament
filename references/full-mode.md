# Full-mode reference — solution-tournament

Read this file when the mode verdict selects FULL, before Phase 1. Lightweight runs never need it. Every rule here has the same authority as SKILL.md prose; where the two disagree, THIS file governs for full-mode machinery and SKILL.md governs for shared rules — and the mismatch is a reported bug.

## Crossbreed rounds (full mode only — Phase 3 continues here)

- **Close** (≤ 1.0): crossbreed round. Maximum 3 scoring rounds — the initial round plus up to 2 crossbreed rounds.
  - Pool = z offspring (default 3) + the top 2 parents, who re-race as carried anchors.
  - Offspring pass the abbreviated skeptic pass (defined in Phase 1.5) and the DQ test before scoring. That pass may also remove a CARRIED ANCHOR whose premise the last round's scores undercut — the only route by which an anchor leaves the field.
  - Crossbreed rounds do NOT inherit Phase 1.5's regenerate-once machinery (offspring already are a regeneration): losing one offspring proceeds with the rest; losing more than one, or any anchor, makes the round a close pair on the survivors. A round that cannot field a real contest does not name a winner.
  - Each offspring names its inherited traits; one is a **mutation** (a single assumption perturbed); and at least one is seeded from the highest-ranked candidate that is NOT the pre-registered favorite, with the excluded mechanism named. The MATCH/NO-MATCH call is printed with one reason; on NO-MATCH, seed from the highest-ranked non-leader and name the leader's mechanism as excluded. The pre-registration goes to the RED-TEAM packet only (never the scorer's), and the match call joins the red-team's audit duty — moving the one self-refereed anti-favorite check off its own author without leaking the prior into scoring.
  - An offspring inheriting from a HYPOTHESIS-capped parent carries the same cap on the same dimension, shown in its row: crossbreeding is not a route for a disqualifying trait to re-enter untested.
- The INITIAL round has no re-scores, so its decisive gate rests on the fixed threshold alone — the matrix says so.
- After each crossbreed round, evaluate in this exact order — the FIRST matching rule wins:
  0. **Falsify this round's removals** (Phase 2.11, re-run per round): a crossbreed round's own removals — including a carried anchor removed by the abbreviated pass — are checked against this round's scores before any gate. A broken premise makes the round a close pair, exactly as in the initial round; anchor removal is most consequential here, so it is least exempt.
  **Rule 0.5 — compute NOISE before reading rules 1–5; its terminations fire first, otherwise it parameterizes rules 2 and 3:**
     a. Identify the CARRIED ANCHORS: the two parents that entered this round with unchanged text.
     b. For EACH anchor compute |current total − previous total| — a per-anchor re-score delta, never the gap between the two anchors.
     c. NOISE = the larger of those two deltas, in weighted-total points. Print BOTH deltas in the matrix, not just the maximum, so a wrong formula is visible to a reader.
     d. Usability and outcome — one three-way table, no overlap:

        | Cause | NOISE usable? | Outcome |
        |---|---|---|
        | Two unchanged-text re-scores, same weights, same pack version | YES | each gate uses its own effective threshold as defined in rules 2 and 3 — the table does not restate them, since a second formula here once contradicted rule 3's decisive bar |
        | Weights changed (redistribution or UNSCORED drop) or pack version bumped | NO | continue on FIXED thresholds, labeled "noise: weights/pack changed" — the round is still decidable, since the cause is a known intervention, not scoring instability |
        | Only one carried anchor survived (one sample) | NO | continue on FIXED thresholds, labeled "noise: one sample" |
        | An anchor's previous or current total contains a main-agent re-scored cell (SELF-SCORED recovery or DISPUTED replacement) | NO | continue on FIXED thresholds, labeled "noise: re-scored anchor" — part of that delta measures the main agent's own rewrite, not scorer instability, and unchanged TEXT is not unchanged SCORING CONDITIONS |
        | No carried anchor survived, or NOISE > 1.5 | NO | TERMINATE: close pair, reason printed — here nothing is known about this round's scoring stability |
        | **Precedence when rows co-occur** | — | **A terminating row always wins.** Exactly two conditions terminate: no surviving carried anchor, and NOISE > 1.5 |

     e. So exactly two conditions terminate the round: no surviving carried anchor, and NOISE > 1.5. Every other unusable-NOISE case falls back to fixed thresholds and continues.
     f. Otherwise every gate below must clear its fixed threshold AND NOISE.

  1. This slot is a pointer only: the terminating conditions live in Rule 0.5 and fire before this list is read, so they are deliberately not restated here.
  2. **Plateau test**: no offspring beat the higher-scoring CARRIED anchor (this round's totals) by more than max(0.5, NOISE) → stop; top two by current totals to Phase 4 together. Plateau outranks the decisive gate deliberately: an anchor that only widened its lead over weak offspring the same agent generated has been flattered, not tested.
  3. **Decisive gate**: margin > max(1.0, NOISE + 0.5) → that round's winner alone to Phase 4. The +0.5 keeps the decisive bar strictly above the plateau bar at every NOISE level; without it the two gates converge above NOISE 1.0, and the plateau rule's whole rationale (an anchor flattered by weak offspring has not been tested) lapses in exactly the high-instability rounds where flattery is likeliest.
  4. **Rounds exhausted** (after round 3): top two to Phase 4 together.
  5. Otherwise: next crossbreed round.
  After the branch is chosen (separately — succession is a computation, not a branch): the two highest-weighted-total candidates of this round, offspring included, become the next round's carried anchors — eligible totals only, since an INCOMPUTABLE candidate has no total to rank and therefore cannot be an anchor.


## Spike gate (full mode only — Phase 4 continues here)

- **Spike gate** (FULL-mode close races on code problems; lightweight never spikes):
  - Before building anything, write down for BOTH finalists: the assumption under test (from its premortem), the pass/fail criterion, and what production conditions the spike does NOT reproduce. Same criterion rigor for both.
  - Budget 2 attempts and ≤150 changed lines per spike (countable — wall-clock is not). A spike that exhausts its budget reports "risk confirmed expensive to derisk", which is itself evidence.
  - The MAIN agent builds both spikes; the red-team judges results and never builds. Build in the session scratchpad or a throwaway worktree, delete before Phase 5, never promote spike code.
  - A spike result outranks judgment about the specific assumption it tested and nothing else — and note what "grounded" does and does not mean here: the spike is externally grounded in what it EXERCISED and single-authored in what it REPORTS, because the result reaches the red-team as main-agent prose. So the raw command and its verbatim output are pasted into the decision record, letting a reader recompute the claim rather than trust its transcription. A cited standing FATAL is the only other artifact that can overrule the matrix, so the red-team's audit marks each spike's CONSTRUCTION as well as its result.
  - Declaring a problem non-spikeable requires naming what could not be built, in the output.


## One worked round (decisive, full mode)

Nothing here binds — it is the same rules executed once, so the order is visible instead of inferred.

1. **Phase 0.** Pack written to `pack.md`, 9 facts: 6 MEASURED (each naming a command or file), 3 ESTIMATED. Printed: `pack-v1 sha256 4f2a…`. Pre-registration: "I expect some form of write-through caching to win." Weights user-edited to 0.35 root-cause / 0.25 robustness / 0.20 maintainability / 0.20 risk (sum 1.0, provenance: user-edited). DQ test: "leaves the double-write in place; check: does the write path still fan out?"
2. **Phase 1.** Five candidates, axes named (slot #1 the obvious approach, one credible long shot). Cross-advocacy pass run and stated.
3. **Phase 1.5.** DQ applied to all five → candidate D removed (VERIFIED — cites the trace in pack-v1 AND the diagnosis demonstrated in session per Phase 0.6's execution bar: the failing test re-run, verbatim output in the record, before the verdict stood). Its falsification test must be entailed by the premise, so: candidate B retains ONE leg of the fan-out D was removed for (B took a PARTIAL verdict at the DQ step — mechanism fixed, residual path named in its row, HYPOTHESIS cap applied — which is why B is scored rather than removed), therefore the premise predicts B scores low on root-cause — and because B's root-cause row carries the HYPOTHESIS cap, the falsifier binds the scorer's ORIGINAL pre-cap value (the reachable quantity; the cap would make a post-cap ≥ 7 impossible and the test vacuous): the premise ENTAILS B's original root-cause value in [0,4] — that is the committed range, width 4.0, excluding more than half the scale, compliant — and per 2.11(b) the verdict FAILS if the matrix lands OUTSIDE it, so an original value of 5 or more contradicts the premise and makes D's removal a BROKEN REMOVAL PREMISE. The falsifier is reachable precisely because the range binds the pre-cap original: the cap at 4 would make any post-cap contradiction impossible. That test could fail, which is what makes it a test. Skeptic returns critiques, premortems, one filler verdict on E — citing a pack fact AND pre-committing its test: "candidate A's robustness row should score ≥ 7 if this fact holds" (checked at step 11: A scored 8, inside the entailed range, so E's removal stands falsifiably rather than by author's say-so). Two removals total → failed-generation rule fires → regenerate two slots once → both survive. Field frozen at 5, hashes printed per candidate. Verbatim field shown to the user.
4. **Phase 2.** One scorer (no architecture/data-integrity/failed-fix trigger). Return gate: (a) all 5 scored; (b) every dimension quotes a candidate-specific locator; (c) recomputed totals match within 0.05 — no ARITHMETIC CORRECTION. One citation is absent from the pack → cell STRUCK, no second scorer, re-score budget available → main agent re-scores, cell marked SELF-SCORED, that dimension's rank voided for the tiebreaker. ORDER check: no dimension dropped, so the deciding dimension prints once — "root-cause 0.35 × (7.9 − 5.8) = 0.735, nearest rival robustness 0.25 × (7.1 − 6.2) = 0.225; no drop: single computation". Removal falsification: B's original root-cause value was 3 — INSIDE the committed [0,4], so the premise stands and D's removal holds. Had it been 5 or more, the value would have fallen outside the committed range, the verdict would have failed, and the round demoted to a close pair. Totals: A 7.4, C 6.1, B 5.9, plus the two regenerated slots lower.
5. **Phase 3.** Initial round, so no NOISE — the matrix says "fixed threshold only". Field-size line: "field whole: 5 of 5 entering this gate — Rule F1's reduced-field wording does not apply, since removals were replaced by regeneration. Label accounting for the red-team's reconciliation check: 7 issued (5 original + 2 regenerated), 2 removed, 5 scored" — printed either way; wholeness is stated, never implied by absence. Margin 7.4 − 6.1 = 1.3 > 1.0 → decisive. Evidence floor: deciding dimension is root-cause (0.35 × the 2.1 score gap, the largest signed contribution). Pack-v1 has a MEASURED fact on it, and the gate does not fire on the tag alone — the fact is RE-RUN in session and both the command and its output go in the record: `rg -n "writeThrough\(" src/ | wc -l` → `3`, matching the pack's claim of three fan-out sites. Floor satisfied by execution on a COMMAND-warranted fact (the full-strength branch; a file-warranted re-read would have been attested, not executed); had nothing been re-runnable, the round would be a close pair instead. The margin sits exactly 0.3 above the gate (1.3 − 1.0), which is inside the 0.3 band → near-miss surfaced to the user with the matrix, the agent's own preference stated separately.
6. **Phase 4.** Winner red-teamed alone. Part 0: no MEASURED tag challenged, one fact flagged as wanting verification; Part 0.2: no outside-pack reasoning found; Part 0.5: names one absent approach, judged unable to win any dimension → no Phase 1 reopen. Two CONCERNs, no FATAL (both at the performance rung, likelihood medium — severity gate evaluated and PASSED: no data-loss item, no high-likelihood correctness item). Audit marks: premortems SUBSTANTIVE, citations SUBSTANTIVE, B's HYPOTHESIS cap SUBSTANTIVE — original root-cause 3 sits BELOW the cap of 4, so the cap binds nothing this round: magnitude 0.35 × max(0, 3 − 4) = 0.00, printed because the magnitude rule fires even when inert; pre-committed observable "residual retry path reachable via the legacy client; check: the un-migrated call site", pre-committed row+range A's robustness in [7,10] (width 3.0).
7. **Phase 5.** Plan mode, implement, tests run with command and verbatim output in the record. Fidelity gate maps the winner's axis to three named diff hunks. Repairs applied: none. Decision record written, INDEX line appended.
8. **Checklist lines**: `checklist: 9 of 9 · 4 of 4 · 6 of 6 · 6 of 6 · 7 of 7 (n/a lines: NOISE + anchor deltas, MATCH/NO-MATCH — no crossbreed; lightweight decisive confirmation — full mode) · 9 of 9 (n/a lines: declined-reopen — none declined; spike criteria + output — no spike) · 7 of 7 (n/a line: route-2 detection command — no route-2 clearing; includes the implementation-review verdict, returned by a fresh reviewer subagent)`. boxes that FIRED at Phase 3: 4 of 7 — 3 unconditional (the sweep line reports the 1.3-margin near-miss) plus the evidence-floor box — printed as 7 of 7 per the fixed-denominator rule, the other three as n/a lines. Where this trace disagrees with the applicability table, the TABLE governs and the trace is the bug.



## Late facts and pack versioning (full mode — subagents only)

The pack is frozen at the checkpoint. Later facts are allowed only when a subagent's OUTPUT requests one (subagents are single-shot and tool-less, so a request is a line in their report: "FACT REQUEST: ..."). The main agent then emits pack-v2 (then v3) with a fresh printed hash and a one-line diff, logs requester and reason, and re-spawns the affected subagent once against the NAMED version — a SKEPTIC request re-spawns the skeptic under the same rule, and the scorer and skeptic templates draw from ONE shared budget of 2 requests per tournament, not 2 each — at most 2 re-spawns; beyond that requests are declined and noted. Every version and hash appears in the record, every prompt names its version, and the matrix states which version each round used: there is no such thing as an unversioned pack edit.

## Red-team machinery (full mode)

- **The red-team is pack-bound, and that is a stated limit**: it reasons over the pack, so a flaw real in the code but absent from the pack cannot be FATAL — it degrades to CONCERN and transfers nothing. Escape hatch: when the red-team's Part 0 names a fact it would want verified, the MAIN agent may run READ-ONLY verification (read the file, run the existing test, query the log) — at most 2 per tournament, with declines printed like declined fact requests, since this path is selective by construction (bias channel 6) and feeds the only artifact that can overturn the matrix — and return the result as a pack-v2 fact, after which the red-team may escalate CONCERN to FATAL on it. If the verification instead REFUTES a pack fact that any scored cell cited, the consequence is not red-team-only: the round demotes to a close pair, because its matrix holds totals computed on withdrawn evidence. Same rule as spikes and Phase 5 tests: the raw command and its verbatim output go in the record BEFORE any escalation — this is bias channel 6 again (the main agent chooses what to verify and transcribes what the judge sees), feeding the only artifact that can overturn the matrix. An unverified Part 0 concern is a required matrix row, never prose — pack blind spots are otherwise invisible to the only mechanism that can overturn the matrix.
- **Absent-approach duty**: the red-team names one credible approach missing from the Phase 1 field, or states none exists. A named absent approach that could plausibly win a rubric dimension reopens Phase 1 once, charged to the tournament's single reopen counter — the field ceiling is the one bias no internal scoring can catch, so the only agent with fresh eyes is asked directly.
- **Evidence bar for overturning** (BINDING): Phase 2 demands a cited fact to move a score; overturning the whole result demands no less. A fatal-flaw verdict must cite a pack fact or a spike result. A flaw asserted without one is a CONCERN: surfaced to the user alongside both candidates when a close pair is in play, or with the winner's matrix when a decisive winner was red-teamed alone — either way it kills nothing and transfers nothing on the agent's say-so. If a cited fatal flaw stands, the runner-up (already red-teamed if the race was close) is checked the same way — and a runner-up promoted after a DECISIVE run's leader fell takes the core file's "Decisive winner falls" rule (stated there because it binds BOTH modes): the evidence floor on ITS OWN deciding dimension, because every gate so far fired for the dead leader, and nothing may reach implementation without a gate having fired for IT. "Finalist" includes a promoted runner-up. If every finalist is fatally flawed, stop and return the field with findings to the user.
- **Audit duty** (full mode): the red-team subagent also receives the premortems, score citations, every removal verdict (DQ and filler alike — the most consequential act in the process gets audited too), every HYPOTHESIS/PARTIAL cap with its pre-commitment and printed magnitude, and (if any) spike criteria and construction, and marks each SUBSTANTIVE or MECHANICAL. **MECHANICAL has consequences, not just visibility** — the audit binds hardest on the artifacts the file calls most consequential, not only on the cheap ones: a removal verdict or its falsification test marked MECHANICAL is treated as UNFALSIFIABLE (round demotes to a close pair, the removed candidate's verbatim text goes to the user or the record, identical to the auto-label route); a spike construction marked MECHANICAL loses its rank above the matrix for that round; a mechanical premortem is redone and logged. The entailment judgment is otherwise made by the removal's own author, and the red-team is the only outside reader of it. Its marks go in the output. This moves the honesty check off the agent that produced the artifacts.

## Full-mode machinery moved from the core (Phase 1/2 and call accounting)

These rules execute ONLY in full mode; the core file holds a pointer to each. They bind exactly as if they still appeared at the pointer's location.

- **Cross-advocacy pass** (DISCIPLINE, full mode only — lightweight skips it, since its unblinded scorer sees the generation reasoning regardless): after drafting all candidates, rewrite each one's mechanism as its strongest advocate would write it, and state in the output that this pass ran. Framing quality is the highest-bandwidth bias channel and no downstream mechanism can detect it; this is the honest-effort counter.
- **Incomplete skeptic return** (full mode only — LIGHTWEIGHT has no subagent and no return, so this rule lapses there exactly as Phase 2's return gate does): a short or malformed return gets ONE re-spawn (drawn from the shared completeness pool in Cost honesty); a second short return means its candidates carry "no premortem — ungraded risk" in the matrix and the round is demoted to a close pair.
- **Combine scorers** (Phase 2 step 7, full mode's two-scorer aggregation — lightweight has one self-scoring pass and no cells to combine, so ONLY the re-score budget line in the core applies there):
  - The cell shows BOTH raw scores and their mean; the mean enters the total. Spread ≥ 3 points flags DISPUTED.
  - **Precedence**: a cell that is both struck and DISPUTED resolves striking first, then re-examines for DISPUTED only if two values still exist.
  - **DISPUTED surfacing and consequence** — when the trigger below fires and a user is PRESENT, the disagreement is surfaced to them as ONE batched question (both raw scores, both rationales) BEFORE the mechanical consequence applies, and the user's answer stands; autonomously the consequence applies directly with the DISPUTED label. This is the "DISPUTED surfacing (≤1)" summand in the core file's interaction sum. **Consequence** (when the disagreement could move a gate — weight × spread ≥ 0.9; not 1.0, because the default top weight is 0.30 and 0.30 × the minimum flagging spread of 3 = 0.9, so a 1.0 trigger would be inert in the default configuration): one re-score against the pack, which REPLACES the cell rather than averaging into it. "Surviving spread" is measured between the re-score and the FARTHER original: still ≥ 3 → the cell takes the lower of the two originals and the round becomes a close pair regardless of margin; under 3 → the re-score stands alone and the round proceeds.
  - Below that trigger, DISPUTED is disclosure only. Derivation: max spread on a 0–10 scale is 10, so the trigger is unreachable exactly on dimensions weighted under 0.09. Past the budget, qualifying cells take the lower value directly.
  - Rank inversions between scorers are surfaced as disagreement, never smoothed.
- **Hard maximum 18 calls**: 1 skeptic + 1 regeneration skeptic + up to 2 abbreviated crossbreed skeptics + up to 6 scorers (2 × 3 rounds) + 1 abbreviated skeptic RESERVED for post-freeze field mutations (objection rewrites, user re-admissions) + 2 red-team + up to 2 fact-request re-spawns (further requests declined and noted) + up to 2 completeness-gate re-spawns, allocated by RESERVATION rather than priority, because claims arrive in phase order and a priority list cannot reach backward in time: the 2 COMPLETENESS slots are the pool in question: 1 is held for the red-team until Phase 4's return is complete, and the skeptic and scorers share the other 1 — and note the timing consequence plainly: the skeptic returns first, so after any skeptic re-spawn the shared slot is SPENT and a later malformed scorer return takes its partial outcome immediately. That is the expected case, not an anomaly; the pool is thin by design, because re-spawns are the channel through which a flaky subagent quietly consumes the budget. (The 2 red-team calls and 2 fact-request re-spawns are separate budgets and are not drawn from it.). With no slot available, a malformed return takes its named partial outcome immediately. DISPUTED and struck-cell re-scores are main-agent actions, not calls. Total: 1+1+2+1+6+2+2+2+1 = 18, the final 1 being the Phase 5 implementation reviewer — and note the core file's separate claim that the ceiling is 18 rather than 17 'for this reason', crediting the reserved abbreviated-skeptic slot: BOTH slots are in this sum and the total is 18 either way, but the 18th call is attributed differently in the two places, so read the enumeration here as authoritative on WHICH slot is which — a NAMED RESERVED slot, so the mandatory review can never find the ceiling already spent (a priority list cannot reach backward in time; a reservation can).

## Full-mode rules moved from the core (read with the pointer sections)

- **Who scores** (Phase 2 step 3): spawn a scoring subagent (`templates/scorer.md`) receiving ONLY the frozen pack plus candidates and premortems under neutral labels. TWO scorers whenever ANY full-mode trigger was architecture, data-integrity, or a failed prior fix; one otherwise. What the second same-model scorer buys, plainly: DISPUTED divergence and STRUCK-cell recovery — real but narrow, since correlated error passes both. No live choice exists between a second scorer and a spike (the scorer is mandated when triggered, unavailable otherwise), so no preference rule applies.
- **Interaction budget**: rubric checkpoint + verbatim field (two mandatory) + a terminal decision WHEN one arises (close pair or sole survivor goes to the user; a DECISIVE full run proceeds with no ask — subagent-scored, unlike lightweight's mandated confirmation) + at most ONE batched near-miss question + the pre-Phase-0 mode-uncertainty ask (≤1) + a Phase 2.9 redistribution assent (≤1) + a DISPUTED surfacing (≤1) + a declined-reopen decision (≤1) = 2 to 8. Total exchanges add user-initiated objections at one per LABEL ISSUED: Total = agent-initiated + L, L = n + regenerated slots (n=5 no removals: up to 13; the worked round's shape, L=7: up to 15). Recompute from the enumeration; never split the severity-gate override or survivor-floor decision into separate asks — each is the content of the terminal-decision exchange.
- **Red-team call precedence**: one packet covers a close pair ("in parallel" = both finalists in one call). The second call's claimants: the RUNNER-UP path outranks a Part 0 escalation (a standing FATAL means the winner is already disqualified). Second call already spent when a runner-up check becomes mandatory → that check cannot run: close pair to the user, NO WINNER autonomously — never an unchecked promotion.
- **Repetition counters, full-mode budget effect**: a Phase 0 reopen restarts the 18-call budget (36 for the tournament); a re-entered tournament may not reopen — its ceiling is 18 with no restart. Absolute worst case per problem: 36 + 18 = 54 calls. If that alarms you for this problem, recalibrate the mode before starting.
- **Autonomous honesty (full)**: pre-authorized autonomous full ends in NO WINNER on every close-pair, all-flawed, sole-survivor, and majority-OPINION branch — a large fraction of realistic runs — potentially spending the full budget to deliver a matrix and no implementation. That is the design. When the user is unreachable, prefer lightweight or defer.
- **Cost**: main-thread context stays near the lightweight figure (summaries, matrices, decisions only), but the subagents' context is the real bill and scales with the pack: up to 18 calls each carrying the full frozen pack → total ≈ 18 × (pack + candidates + premortems) ≈ 40–80k tokens with the pack under ~1,500 words (ESTIMATED). A pack twice that size doubles the tournament. Common path, as a literal sum: skeptic (1) + scorer (1) + red-team (1) + Phase 5 implementation reviewer (1) = 4; 5 at the two-scorer tier; 6–8 when a crossbreed round runs.

## Ledgers (full mode)

- **COUNTERS ledger**: instantiate at Phase 0 as one FIXED TEMPLATE line with every counter pre-listed at zero (copy the list verbatim, ": 0" each) — held state becomes a fill-in-the-blank print, not a remembered inventory. The authoritative counter list: reopen (1), re-entry (1), re-scores (2), completeness slots (2), fact requests (2), read-only verifications (2), red-team calls (2), spike attempts (2 per spike), scoring rounds (3), post-freeze mutations (1), reserved abbreviated-skeptic slot (1). Updated IN PLACE at every spend — a ledger rebuilt from memory at the end is where a forgotten spend hides. The skeleton (counter names + per-phase checklist-line set) is fixed by this file and printed verbatim, so a reader diffs the output's skeleton directly: a dropped counter or missing phase line is a reader-computable mismatch that does not route through the agent's sweep.
- **GATE-ORDER ledger**: one fixed line per ordered sequence — `gate-order <sequence-name>: <step-id> ✓ · ...` — exactly one tick per mandated step in mandated order, each tick carrying the ID of the artifact its step produced, a monotonic sequence number assigned in flow (emission order), and the matrix row for matrix-resident artifacts. Sequences: Phase 2 steps 0a–c, 6, 7, 8, 9, 10, 11 (step 8 ticks because it publishes the OPINION flags gating step 9; steps 1–5 produce no ordered artifact and no tick — ONE denominator) · the removal timing a–c · the drop-floor 1–4 · the crossbreed gate rules when a crossbreed round runs. Tick IN FLOW, interleaved in the running output among the artifacts they follow — a contiguous-block ledger is by definition backfilled: treat as attested, count ONE strike (SAC: layout evidence detects inconsistency, not a coherent backfiller). The ledger's LAST line prints the diff — "gate-order diff: N ticks / N artifact IDs matched" — so an absent tick is a count mismatch needing no sweep; an invented tick is visible only when its named artifact is not also invented. The FINAL ledger line prints each counter's spends annotated with phase and rule. Pre-commit each sequence's tick denominator at Exit Phase 0; a sequence that never fired prints "<sequence>: n/a — did not fire" and is excluded from the diff on both sides.
- Strike sources here (feeding SKILL.md's two-strike rule): a LATE REPAIR, an out-of-order tick, an absent tick, a box count below its applicable Y; an absent count line, absent gate-order diff line, entirely absent phase checklist line, or a tick count disagreeing with the pre-committed denominator for a fired sequence is an AUTOMATIC strike.

## Exit checklists (full mode)

Artifact inventories only — phases hold the rules. Print "checklist: X of Y" per phase, Y from the table; every non-firing conditional prints inline "n/a — <reason>" and counts as satisfied; each box tagged @flow (produced when its rule ran) or @late (produced at the exit check) — the tag is self-assigned (SAC); the absent-line automatic strike and the skeleton diff are the sweep-independent detections. A mismatch is a stop with a destination: name the missing artifact, produce it if the phase still can, else end under After NO WINNER with the gap recorded. A run DOWNGRADED full → lightweight mid-flight keeps THIS table: every now-unproduceable full-only box prints "n/a — downgraded at Phase X", so Y stays 48 and the downgrade is a diffable artifact.

- **Exit Phase 0**: pack file + tagged facts + printed hash (v1) · problem restatement · pre-registration sentence · normalized weights + provenance line · DQ falsifiable test · decision-record index read (or no-repo note) · COUNTERS + GATE-ORDER ledgers instantiated (opening lines printed, including each sequence's tick denominator) · mode verdict incl. user reachability · cap-inheritor line ("root-cause dimension present" or the named inheriting dimension).
- **Exit Phase 1**: n candidates each with named axis, 90–150w mechanism, assumptions, severity-rung breaks · obvious slot named · long-shot slot named · cross-advocacy statement.
