# Full-mode reference — solution-tournament

Read this file when the mode verdict selects FULL, before Phase 1. Lightweight runs never need it. Every rule here has the same authority as SKILL.md prose; where the two disagree, THIS file governs for full-mode machinery and SKILL.md governs for shared rules — and the mismatch is a reported bug.

## Crossbreed rounds (full mode only — Phase 3 continues here)

- **Close** (≤ 1.0): crossbreed round. Maximum 3 scoring rounds — the initial round plus up to 2 crossbreed rounds.
  - Pool = z offspring (default 3) + the top 2 parents, who re-race as carried anchors.
  - Offspring pass the abbreviated skeptic pass (defined in Phase 1.5) and the DQ test before scoring. That pass may also remove a CARRIED ANCHOR whose premise the last round's scores undercut — the only route by which an anchor leaves the field.
  - Crossbreed rounds do NOT inherit Phase 1.5's regenerate-once machinery (offspring already are a regeneration): losing one offspring proceeds with the rest; losing more than one, or any anchor, makes the round a close pair on the survivors. A round that cannot field a real contest does not name a winner.
  - Each offspring names its inherited traits; one is a **mutation** (a single assumption perturbed); and at least one is seeded from the highest-ranked candidate that is NOT the pre-registered favorite, with the excluded mechanism named. The MATCH/NO-MATCH call is printed with one reason; on NO-MATCH, seed from the highest-ranked non-leader and name the leader's mechanism as excluded. The pre-registration goes to the RED-TEAM packet only (never the scorer's), and the match call joins the red-team's audit duty — moving the one self-refereed anti-favorite check off its own author without leaking the prior into scoring.
  - An offspring inheriting from a HYPOTHESIS-capped parent carries the same cap on the same dimension, shown in its row: crossbreeding is not a route for a disqualifying trait to re-enter untested.
- The INITIAL round has no re-scores, so its decisive gate rests on the fixed threshold alone — the matrix says so.
- After each crossbreed round, evaluate in this exact order — the FIRST matching rule wins:
  0. **Falsify this round's removals** (Phase 2.11, re-run per round): a crossbreed round's own removals — including a carried anchor removed by the abbreviated pass — are checked against this round's scores before any gate. A broken premise makes the round a close pair, exactly as in the initial round; anchor removal is most consequential here, so it is least exempt.
  **Rule 0.5 — compute NOISE before reading rules 1–5; its terminations fire first, otherwise it parameterizes rules 2 and 3:**
     a. Identify the CARRIED ANCHORS: the two parents that entered this round with unchanged text.
     b. For EACH anchor compute |current total − previous total| — a per-anchor re-score delta, never the gap between the two anchors.
     c. NOISE = the larger of those two deltas, in weighted-total points. Print BOTH deltas in the matrix, not just the maximum, so a wrong formula is visible to a reader.
     d. Usability and outcome — one three-way table, no overlap:

        | Cause | NOISE usable? | Outcome |
        |---|---|---|
        | Two unchanged-text re-scores, same weights, same pack version | YES | each gate uses its own effective threshold as defined in rules 2 and 3 — the table does not restate them, since a second formula here once contradicted rule 3's decisive bar |
        | Weights changed (redistribution or UNSCORED drop) or pack version bumped | NO | continue on FIXED thresholds, labeled "noise: weights/pack changed" — the round is still decidable, since the cause is a known intervention, not scoring instability |
        | Only one carried anchor survived (one sample) | NO | continue on FIXED thresholds, labeled "noise: one sample" |
        | An anchor's previous or current total contains a main-agent re-scored cell (SELF-SCORED recovery or DISPUTED replacement) | NO | continue on FIXED thresholds, labeled "noise: re-scored anchor" — part of that delta measures the main agent's own rewrite, not scorer instability, and unchanged TEXT is not unchanged SCORING CONDITIONS |
        | No carried anchor survived, or NOISE > 1.5 | NO | TERMINATE: close pair, reason printed — here nothing is known about this round's scoring stability |
        | **Precedence when rows co-occur** | — | **A terminating row always wins.** Exactly two conditions terminate: no surviving carried anchor, and NOISE > 1.5 |

     e. So exactly two conditions terminate the round: no surviving carried anchor, and NOISE > 1.5. Every other unusable-NOISE case falls back to fixed thresholds and continues.
     f. Otherwise every gate below must clear its fixed threshold AND NOISE.

  1. (Pointer only — the terminating conditions live in Rule 0.5 and fire before this list is read; they are deliberately not restated here.)
  2. **Plateau test**: no offspring beat the higher-scoring CARRIED anchor (this round's totals) by more than max(0.5, NOISE) → stop; top two by current totals to Phase 4 together. Plateau outranks the decisive gate deliberately: an anchor that only widened its lead over weak offspring the same agent generated has been flattered, not tested.
  3. **Decisive gate**: margin > max(1.0, NOISE + 0.5) → that round's winner alone to Phase 4. The +0.5 keeps the decisive bar strictly above the plateau bar at every NOISE level; without it the two gates converge above NOISE 1.0, and the plateau rule's whole rationale (an anchor flattered by weak offspring has not been tested) lapses in exactly the high-instability rounds where flattery is likeliest.
  4. **Rounds exhausted** (after round 3): top two to Phase 4 together.
  5. Otherwise: next crossbreed round.
  After the branch is chosen (separately — succession is a computation, not a branch): the two highest-weighted-total candidates of this round, offspring included, become the next round's carried anchors — eligible totals only, since an INCOMPUTABLE candidate has no total to rank and therefore cannot be an anchor.


## Spike gate (full mode only — Phase 4 continues here)

- **Spike gate** (FULL-mode close races on code problems; lightweight never spikes):
  - Before building anything, write down for BOTH finalists: the assumption under test (from its premortem), the pass/fail criterion, and what production conditions the spike does NOT reproduce. Same criterion rigor for both.
  - Budget 2 attempts and ≤150 changed lines per spike (countable — wall-clock is not). A spike that exhausts its budget reports "risk confirmed expensive to derisk", which is itself evidence.
  - The MAIN agent builds both spikes; the red-team judges results and never builds. Build in the session scratchpad or a throwaway worktree, delete before Phase 5, never promote spike code.
  - A spike result outranks judgment about the specific assumption it tested and nothing else — and note what "grounded" does and does not mean here: the spike is externally grounded in what it EXERCISED and single-authored in what it REPORTS, because the result reaches the red-team as main-agent prose. So the raw command and its verbatim output are pasted into the decision record, letting a reader recompute the claim rather than trust its transcription. A cited standing FATAL is the only other artifact that can overrule the matrix, so the red-team's audit marks each spike's CONSTRUCTION as well as its result.
  - Declaring a problem non-spikeable requires naming what could not be built, in the output.


## One worked round (decisive, full mode)

Nothing here binds — it is the same rules executed once, so the order is visible instead of inferred.

1. **Phase 0.** Pack written to `pack.md`, 9 facts: 6 MEASURED (each naming a command or file), 3 ESTIMATED. Printed: `pack-v1 sha256 4f2a…`. Pre-registration: "I expect some form of write-through caching to win." Weights user-edited to 0.35 root-cause / 0.25 robustness / 0.20 maintainability / 0.20 risk (sum 1.0, provenance: user-edited). DQ test: "leaves the double-write in place; check: does the write path still fan out?"
2. **Phase 1.** Five candidates, axes named (slot #1 the obvious approach, one credible long shot). Cross-advocacy pass run and stated.
3. **Phase 1.5.** DQ applied to all five → candidate D removed (VERIFIED, cites the trace in pack-v1). Its falsification test must be entailed by the premise, so: candidate B retains ONE leg of the fan-out D was removed for (B took a PARTIAL verdict at the DQ step — mechanism fixed, residual path named in its row, HYPOTHESIS cap applied — which is why B is scored rather than removed), therefore the premise predicts B scores low on root-cause — and because B's root-cause row carries the HYPOTHESIS cap, the falsifier binds the scorer's ORIGINAL pre-cap value (the reachable quantity; the cap would make a post-cap ≥ 7 impossible and the test vacuous): if the scorer's original root-cause value for B is ≥ 7 — committed range [7,10], width 3.0, compliant — the premise is contradicted and D's removal is a BROKEN REMOVAL PREMISE. That test could fail, which is what makes it a test. Skeptic returns critiques, premortems, one filler verdict on E — citing a pack fact AND pre-committing its test: "candidate A's performance row should score ≥ 7 if this fact holds" (checked at step 11: A scored 8, inside the entailed range, so E's removal stands falsifiably rather than by author's say-so). Two removals total → failed-generation rule fires → regenerate two slots once → both survive. Field frozen at 5, hashes printed per candidate. Verbatim field shown to the user.
4. **Phase 2.** One scorer (no architecture/data-integrity/failed-fix trigger). Return gate: (a) all 5 scored; (b) every dimension quotes a candidate-specific locator; (c) recomputed totals match within 0.05 — no ARITHMETIC CORRECTION. One citation is absent from the pack → cell STRUCK, no second scorer, re-score budget available → main agent re-scores, cell marked SELF-SCORED, that dimension's rank voided for the tiebreaker. ORDER check: no dimension dropped, so the deciding dimension prints once — "root-cause 0.35 × (7.9 − 5.8) = 0.735, nearest rival robustness 0.25 × (7.1 − 6.2) = 0.225; no drop: single computation". Removal falsification: B's root-cause row scored 3 (under its cap), consistent with the premise that the shared fan-out leaves the root cause standing, so D's removal holds. Had B scored ≥ 7, the removal would have broken and the round demoted. Totals: A 7.4, C 6.1, B 5.9, plus the two regenerated slots lower.
5. **Phase 3.** Initial round, so no NOISE — the matrix says "fixed threshold only". Field-size line: "field whole: 5 of 5 originally issued" — printed either way; wholeness is stated, never implied by absence. Margin 7.4 − 6.1 = 1.3 > 1.0 → decisive. Evidence floor: deciding dimension is root-cause (0.35 × the 2.1 score gap, the largest signed contribution). Pack-v1 has a MEASURED fact on it, and the gate does not fire on the tag alone — the fact is RE-RUN in session and both the command and its output go in the record: `rg -n "writeThrough\(" src/ | wc -l` → `3`, matching the pack's claim of three fan-out sites. Floor satisfied by execution on a COMMAND-warranted fact (the full-strength branch; a file-warranted re-read would have been attested, not executed); had nothing been re-runnable, the round would be a close pair instead. The margin sits exactly 0.3 above the gate (1.3 − 1.0), which is inside the 0.3 band → near-miss surfaced to the user with the matrix, the agent's own preference stated separately.
6. **Phase 4.** Winner red-teamed alone. Part 0: no MEASURED tag challenged, one fact flagged as wanting verification; Part 0.2: no outside-pack reasoning found; Part 0.5: names one absent approach, judged unable to win any dimension → no Phase 1 reopen. Two CONCERNs, no FATAL (both at the performance rung, likelihood medium — severity gate evaluated and PASSED: no data-loss item, no high-likelihood correctness item). Audit marks: premortems SUBSTANTIVE, citations SUBSTANTIVE.
7. **Phase 5.** Plan mode, implement, tests run with command and verbatim output in the record. Fidelity gate maps the winner's axis to three named diff hunks. Repairs applied: none. Decision record written, INDEX line appended.
8. **Checklist lines**: `checklist: 9 of 9 · 4 of 4 · 6 of 6 · 6 of 6 · 7 of 7 (n/a lines: NOISE + anchor deltas, MATCH/NO-MATCH — no crossbreed; lightweight decisive confirmation — full mode) · 9 of 9 (n/a lines: declined-reopen — none declined; spike criteria + output — no spike) · 6 of 6 (n/a line: route-2 detection command — no route-2 clearing)`. boxes that FIRED at Phase 3: 4 of 7 — 3 unconditional (the sweep line reports the 1.3-margin near-miss) plus the evidence-floor box — printed as 7 of 7 per the fixed-denominator rule, the other three as n/a lines. Where this trace disagrees with the applicability table, the TABLE governs and the trace is the bug.



## Late facts and pack versioning (full mode — subagents only)

The pack is frozen at the checkpoint. Later facts are allowed only when a subagent's OUTPUT requests one (subagents are single-shot and tool-less, so a request is a line in their report: "FACT REQUEST: ..."). The main agent then emits pack-v2 (then v3) with a fresh printed hash and a one-line diff, logs requester and reason, and re-spawns the affected subagent once against the NAMED version — a SKEPTIC request re-spawns the skeptic under the same rule, and the scorer and skeptic templates draw from ONE shared budget of 2 requests per tournament, not 2 each — at most 2 re-spawns; beyond that requests are declined and noted. Every version and hash appears in the record, every prompt names its version, and the matrix states which version each round used: there is no such thing as an unversioned pack edit.

## Red-team machinery (full mode)

- **The red-team is pack-bound, and that is a stated limit**: it reasons over the pack, so a flaw real in the code but absent from the pack cannot be FATAL — it degrades to CONCERN and transfers nothing. Escape hatch: when the red-team's Part 0 names a fact it would want verified, the MAIN agent may run READ-ONLY verification (read the file, run the existing test, query the log) — at most 2 per tournament, with declines printed like declined fact requests, since this path is selective by construction (bias channel 6) and feeds the only artifact that can overturn the matrix — and return the result as a pack-v2 fact, after which the red-team may escalate CONCERN to FATAL on it. If the verification instead REFUTES a pack fact that any scored cell cited, the consequence is not red-team-only: the round demotes to a close pair, because its matrix holds totals computed on withdrawn evidence. Same rule as spikes and Phase 5 tests: the raw command and its verbatim output go in the record BEFORE any escalation — this is bias channel 6 again (the main agent chooses what to verify and transcribes what the judge sees), feeding the only artifact that can overturn the matrix. An unverified Part 0 concern is a required matrix row, never prose — pack blind spots are otherwise invisible to the only mechanism that can overturn the matrix.
- **Absent-approach duty**: the red-team names one credible approach missing from the Phase 1 field, or states none exists. A named absent approach that could plausibly win a rubric dimension reopens Phase 1 once, charged to the tournament's single reopen counter — the field ceiling is the one bias no internal scoring can catch, so the only agent with fresh eyes is asked directly.
- **Evidence bar for overturning** (BINDING): Phase 2 demands a cited fact to move a score; overturning the whole result demands no less. A fatal-flaw verdict must cite a pack fact or a spike result. A flaw asserted without one is a CONCERN: surfaced to the user alongside both candidates when a close pair is in play, or with the winner's matrix when a decisive winner was red-teamed alone — either way it kills nothing and transfers nothing on the agent's say-so. If a cited fatal flaw stands, the runner-up (already red-teamed if the race was close) is checked the same way — and a runner-up promoted after a DECISIVE run's leader fell takes the core file's "Decisive winner falls" rule (stated there because it binds BOTH modes): the evidence floor on ITS OWN deciding dimension, because every gate so far fired for the dead leader, and nothing may reach implementation without a gate having fired for IT. "Finalist" includes a promoted runner-up. If every finalist is fatally flawed, stop and return the field with findings to the user.
- **Audit duty** (full mode): the red-team subagent also receives the premortems, score citations, every removal verdict (DQ and filler alike — the most consequential act in the process gets audited too), and (if any) spike criteria and construction, and marks each SUBSTANTIVE or MECHANICAL. **MECHANICAL has consequences, not just visibility** — the audit binds hardest on the artifacts the file calls most consequential, not only on the cheap ones: a removal verdict or its falsification test marked MECHANICAL is treated as UNFALSIFIABLE (round demotes to a close pair, the removed candidate's verbatim text goes to the user or the record, identical to the auto-label route); a spike construction marked MECHANICAL loses its rank above the matrix for that round; a mechanical premortem is redone and logged. The entailment judgment is otherwise made by the removal's own author, and the red-team is the only outside reader of it. Its marks go in the output. This moves the honesty check off the agent that produced the artifacts.

## Full-mode machinery moved from the core (Phase 1/2 and call accounting)

These rules execute ONLY in full mode; the core file holds a pointer to each. They bind exactly as if they still appeared at the pointer's location.

- **Cross-advocacy pass** (DISCIPLINE, full mode only — lightweight skips it, since its unblinded scorer sees the generation reasoning regardless): after drafting all candidates, rewrite each one's mechanism as its strongest advocate would write it, and state in the output that this pass ran. Framing quality is the highest-bandwidth bias channel and no downstream mechanism can detect it; this is the honest-effort counter.
- **Incomplete skeptic return** (full mode only — LIGHTWEIGHT has no subagent and no return, so this rule lapses there exactly as Phase 2's return gate does): a short or malformed return gets ONE re-spawn (drawn from the shared completeness pool in Cost honesty); a second short return means its candidates carry "no premortem — ungraded risk" in the matrix and the round is demoted to a close pair.
- **Combine scorers** (Phase 2 step 7, full mode's two-scorer aggregation — lightweight has one self-scoring pass and no cells to combine, so ONLY the re-score budget line in the core applies there):
  - The cell shows BOTH raw scores and their mean; the mean enters the total. Spread ≥ 3 points flags DISPUTED.
  - **Precedence**: a cell that is both struck and DISPUTED resolves striking first, then re-examines for DISPUTED only if two values still exist.
  - **DISPUTED surfacing and consequence** — when the trigger below fires and a user is PRESENT, the disagreement is surfaced to them as ONE batched question (both raw scores, both rationales) BEFORE the mechanical consequence applies, and the user's answer stands; autonomously the consequence applies directly with the DISPUTED label. This is the "DISPUTED surfacing (≤1)" summand in the core file's interaction sum. **Consequence** (when the disagreement could move a gate — weight × spread ≥ 0.9; not 1.0, because the default top weight is 0.30 and 0.30 × the minimum flagging spread of 3 = 0.9, so a 1.0 trigger would be inert in the default configuration): one re-score against the pack, which REPLACES the cell rather than averaging into it. "Surviving spread" is measured between the re-score and the FARTHER original: still ≥ 3 → the cell takes the lower of the two originals and the round becomes a close pair regardless of margin; under 3 → the re-score stands alone and the round proceeds.
  - Below that trigger, DISPUTED is disclosure only. Derivation: max spread on a 0–10 scale is 10, so the trigger is unreachable exactly on dimensions weighted under 0.09. Past the budget, qualifying cells take the lower value directly.
  - Rank inversions between scorers are surfaced as disagreement, never smoothed.
- **Hard maximum 17 calls**: 1 skeptic + 1 regeneration skeptic + up to 2 abbreviated crossbreed skeptics + up to 6 scorers (2 × 3 rounds) + 1 abbreviated skeptic RESERVED for post-freeze field mutations (objection rewrites, user re-admissions) + 2 red-team + up to 2 fact-request re-spawns (further requests declined and noted) + up to 2 completeness-gate re-spawns, allocated by RESERVATION rather than priority, because claims arrive in phase order and a priority list cannot reach backward in time: the 2 COMPLETENESS slots are the pool in question: 1 is held for the red-team until Phase 4's return is complete, and the skeptic and scorers share the other 1 — and note the timing consequence plainly: the skeptic returns first, so after any skeptic re-spawn the shared slot is SPENT and a later malformed scorer return takes its partial outcome immediately. That is the expected case, not an anomaly; the pool is thin by design, because re-spawns are the channel through which a flaky subagent quietly consumes the budget. (The 2 red-team calls and 2 fact-request re-spawns are separate budgets and are not drawn from it.). With no slot available, a malformed return takes its named partial outcome immediately. DISPUTED and struck-cell re-scores are main-agent actions, not calls. Total: 1+1+2+1+6+2+2+2 = 17.
