# Solution Tournament

Generate → score → crossbreed → implement. The goal is a production-grade solution, not the first plausible one.

**Honestly:** one agent authors every artifact here, so no internal check can catch a favorite smuggled through framing. This is a discipline that raises the cost of choosing thoughtlessly, not an audit, and its output is not objective. This section describes; it binds nothing — rules live in their phases.

**Nine bias channels, none fully mitigated:**

| # | Channel | Partial counter |
|---|---|---|
| 1 | FRAMING QUALITY — the same agent writes every candidate's pitch | cross-advocacy pass; verbatim field shown to the user |
| 2 | SELF-SCORING — author grades own work | independent scorer subagents (full mode only) |
| 3 | PACK ERROR — a wrong pack fact yields a fully cited, confidently wrong winner | MEASURED/ESTIMATED tags; red-team pack interrogation |
| 4 | STRIKE AUTHORITY — main agent rules which citations are fake | STRUCK-cell visibility in the matrix |
| 5 | CORRELATED SCORER ERROR — same-model scorers wrong in the same direction: zero spread, no flag, decorated wrong matrix | NONE internally. Wider than scoring: the skeptic (who removes candidates) and red-team (whose FATAL overturns) are single agents with zero redundancy — more authority, less oversight, accepted in writing because duplicating them doubles cost while sharing priors. Only spikes and the user's read are external |
| 6 | SPIKE CONSTRUCTION AND REPORTING — the builder chooses how hard to try, AND transcribes the result the judge sees; spikes outrank the matrix | criteria written for both before either is built; red-team audits construction; raw command + verbatim output in the record |
| 7 | MODE SELECTION — lightweight disables more safeguards in one self-assessed sentence than most channels combined | mode verdict artifact (Calibration) |
| 8 | FIELD CEILING — nothing here can see a better approach that was never generated | the field-ceiling question, asked in both modes (full: red-team with fresh eyes, can reopen Phase 1; lightweight: self-administered, labeled) |
| 9 | PACKET INTEGRITY — subagents are ASKED not to use tools and to reason only from the pack; nothing sandboxes them. A scorer reasoning from outside knowledge while citing genuine pack lines is undetectable | citation striking catches fabricated citations only; red-team Part 0 asks whether any scoring rationale references material absent from the pack |

DISPUTED detects divergence, never shared error: a zero-spread cell is uncontradicted, not corroborated.

**Definitions used throughout:**

- **User present**: an interactive session where a question can reach the user (e.g. AskUserQuestion).
  UNANSWERED is mechanical, not felt, and it comes in two scopes that must not be confused: ROW-LOCAL (an ambiguous or partial reply, or a decline of THIS question → take that row's autonomous branch, labeled "user unreachable in practice", and the run CONTINUES — one mushy answer never terminates anything) versus RUN-LOCAL (the session ends, the question channel tool-errors, or the user explicitly declines further questions → the user is gone; re-evaluate the pre-flight abort).
  A single ambiguous answer is never RUN-LOCAL. Anything short of these events means the run WAITS; hesitation is not absence. Anything else is autonomous.
  Two kinds of run carry the top-line statement "every safeguard in this run was self-administered": every autonomous LIGHTWEIGHT run and every attended lightweight run (a pre-authorized autonomous FULL run instead prints "no user check; subagent independence only" — its scorers, skeptic, and red-team are subagents, which is narrow independence, not self-administration) — lightweight self-scores, self-skeptics, and self-red-teams, so a clean decisive lightweight output otherwise reads as corroborated when one agent authored all of it.
- **Autonomous STOP fallback**: STOP means write the field and findings into the decision record with NO WINNER and do not implement. One row per branch, no exceptions hidden in prose. **Where this table, a template, or a checklist disagrees with a phase's prose, the PHASE governs and the mismatch is reported as a bug in this file** — the table is a convenience index, not a second rulebook:

|---|---|---|

- **BINDING vs DISCIPLINE**: BINDING = violation is visible in the output to a reader who has this file (absence of a required artifact is only detectable by someone who knows it was required). BINDING comes in two grades, and unless a use says otherwise it means the weaker one: PRESENCE (the artifact exists and can be seen missing — most uses) versus CONTENT-VERIFIABLE (all such claims presume a READER holding this file who recomputes — in practice the user's few interactions, not the full box inventory, so "a reader can check" states an opportunity, never an event that necessarily happened) (a reader can check the artifact is TRUE, e.g. recomputing totals from printed cells, diffing pre/post-check totals, re-running a pasted command). A self-printed artifact's presence is checkable; its truth usually is not, and the labels must not blur that. DISCIPLINE = honest effort, unverifiable. Anything unlabeled is DISCIPLINE. Never present a DISCIPLINE step as a guarantee.

## Calibration: pick the mode first

- **Lightweight** (contained bug, single file, reversible): n=3, one round, no subagents, unblinded self-scoring with an anti-favorite pass — never called blind. Its removals receive NO audit: audit duty is full-mode, so no MECHANICAL demotion path exists in lightweight — self-authored removals stand unless step 11's falsification catches them, and that is the whole protection. Because it never crossbreeds, NO NOISE sample is ever available in this mode: its 1.0 decisive gate is an uncalibrated convention applied to self-produced scores, and margins within the Phase 3 band of the gate — on EITHER side of 1.0 — are near-misses; the band rule lives in Phase 3 and is not restated here. Everything else applies.
- **Full** (architecture, cross-cutting, high blast radius, failed prior fix, data-integrity): n=5, subagent scoring, up to 3 rounds.
- **Lightweight is the default.** Full mode needs an explicit trigger — and a trigger recorded PRESENT is SUFFICIENT, not merely necessary: any full-mode trigger present in the mode verdict artifact SELECTS full mode when a user is reachable, and running lightweight over a present trigger requires the user's quoted assent printed in that same artifact (bias channel 7 is the agent talking itself into the weaker mode; this sentence is its gate, not its description). **Mode verdict artifact** (BINDING): the output lists every full-mode trigger — architecture / cross-cutting change / high blast radius / failed prior fix / data-integrity stakes / user request — with a present-or-absent verdict and one line of evidence each, so a reader can contest the classification against the pack. It also states whether a user is reachable; when no user is reachable, the mode DROPS to lightweight — a rule, not a suggestion — unless the user pre-authorized autonomous full mode in text quoted into the artifact. A disjunction the agent resolves for itself is not a safeguard, and autonomous full mode ends in NO WINNER on most branches, so choosing it unprompted is choosing to spend up to 18 calls on a matrix and no decision. When genuinely unsure, ask — one sentence. **Pre-flight abort** (BINDING) — numbered sub-rules, no content change.
  (1) Evaluated at Phase 0 AND re-evaluated the moment a user becomes RUN-LOCAL unreachable mid-run — re-evaluated meaning the MID-RUN rule two bullets below applies (convert to rule-determined NO WINNER preserving artifacts), NEVER the pre-flight "do not generate" branch, which is Phase-0-only.
  (2) Both branches are stated here so a reader of this sentence alone cannot take the wrong one (before the next subagent call in full mode; at each phase boundary in lightweight, which has no calls to anchor to — a full-mode run that loses its user is heading for a rule-determined NO WINNER, and the remaining calls buy nothing): if the mode verdict records a DOWNGRADE to lightweight (no reachable user, no quoted pre-authorization) AND any full-mode trigger is present, the run is a guaranteed STOP by rule, so do not generate at all. A PRE-AUTHORIZED autonomous full run is NOT aborted — it is not a guaranteed STOP, since a decisive margin still carries a winner to Phase 4 and implementation; it proceeds, and ends in NO WINNER only on the branches already listed. Emit the mode verdict, the triggers, and "tournament declined: this configuration terminates in STOP by rule", then take the minimal provisional intervention under After NO WINNER. Aborting saves the MARGINAL spend only — the ~5–10k run plus its generation and scoring — because the load is already read by the time this rule fires; that is the same sunk-cost reasoning the skip floor uses, applied to this file's own accounting. Spending even that marginal cost to arrive at a predetermined dead end is the calibration failure this file names everywhere else.
- **The user can always stop it.** "Just patch it" is an instruction, not a debate opening: record the field so far, comply, label what the tournament had and had not established. Every anti-exit rule binds the AGENT only.
- **Downgrade when the problem deflates; never self-exit once the field exists — and mid-run RUN-LOCAL loss of the user does NOT abort: it converts the run to a rule-determined NO WINNER that preserves every earned artifact and hands back the field and matrix per After NO WINNER; the pre-flight "do not generate at all" applies ONLY at Phase 0, before a field exists.** In Phase 0, a trivial problem means exit and just fix it, noting why. From Phase 1 on, exit is not the agent's call: scoring the field is cheap, and "this deflated" is indistinguishable from "my favorite is the obvious one." Downgrading full → lightweight after Phase 1 is constrained the same way exit is: it must be announced with its reason, it PRESERVES every independent artifact already earned (returned subagent scores stay in the matrix; an already-run skeptic's verdicts stand), and the close-pair route still goes to the user when present — a downgrade forfeits future independence, never past independence.

## Phase 0: Evidence and rubric BEFORE candidates

Order is mandatory: pack → rubric → checkpoint → generation. Criteria or evidence chosen after seeing candidates become rationalizations for a favorite.

1. **Pack first** (BINDING): problem statement, the code and interfaces it touches, scale numbers, deadlines, constraints.
   - Every non-quote fact is tagged MEASURED (naming its command, file, or trace) or ESTIMATED (DISCIPLINE — the tag is self-assigned, and naming a command is not running it; a fact mislabeled MEASURED can promote a CONCERN to a FATAL); a score or FATAL resting solely on an ESTIMATED fact says so in the matrix. The red-team must challenge at least one MEASURED tag or state that every one names a re-runnable command, and must report explicitly when the pack contains ZERO MEASURED facts. **Evidence floor** (BINDING), with each gate bound to the evidence that actually bears on it:
- A **decisive gate** — numbered sub-rules, split for readability with no content change: (1) requires at least one MEASURED fact on its DECIDING DIMENSION — the dimension whose SIGNED weighted contribution to the leader's margin is largest (computed as weight × (leader's score − runner-up's score), never (weight × leader) − runner-up); when the field holds ONE candidate — a sole survivor, or a post-FATAL field after the rival fell — the two-candidate formula is undefined and the ONE-CANDIDATE selector applies instead: the highest-weighted dimension scoring below 5, else the highest-weighted dimension (the sole-survivor floor's convention, defined HERE so the Survivor floor and "Decisive winner falls" import it rather than each improvising); dimensions where the leader scores lower are ineligible, so the floor can never be satisfied by evidence that argues against the winner. If two contribute equally, both need a fact.
  (1.5) SCORE PROVENANCE gates too, not just the fact: if the deciding dimension holds a SELF-SCORED recovery, a DISPUTED replacement, or a HYPOTHESIS-capped cell FOR THE LEADER, the decisive gate does not fire — close pair (NO WINNER autonomously) — because a margin resting on a main-agent-authored cell must not read identically to one resting on returned scores; the provenance of every cell on the deciding dimension prints in the evidence-floor artifact.
  (2) At least ONE of those MEASURED facts must be RE-RUN IN SESSION before the gate fires — and the re-run has a defined form for EVERY tag warrant Phase 0 permits: a command-warranted fact re-runs its named command; a file- or trace-warranted fact re-runs by RE-READING the cited location (file:line or trace excerpt) in session, with the tag recording the exact location re-read and the re-read text quoted verbatim — and be honest about the difference: a re-read of a location the agent already read this session is ATTESTED-NOT-EXECUTED (it will CONFIRM in nearly every realistic case; quote-and-compare is transcription, not testing), so a decisive gate whose deciding dimension rests ONLY on file/trace-warranted facts already read this session does not fire — close pair — unless at least one such location is being read for the FIRST time in session or a command-warranted fact is on the dimension; only the command branch is execution in the full sense — CONFIRMS/CONTRADICTS/AMBIGUOUS apply to the re-read exactly as to command output, and a cited location that no longer exists demotes the fact to ESTIMATED.
  (3) The command or location used must be THE ONE THE TAG NAMED, not a substitute the agent prefers — and the structural reason tags are hard to tailor is ORDER: the pack and its commands are frozen BEFORE candidates exist and before pre-registration, so a command cannot be tailored to a WRITTEN candidate that does not yet exist — though order cannot block tailoring to a HELD prior (the pre-registration sentence exists precisely because a favorite lives in the agent's head before Phase 1), so in lightweight that residual is DISCIPLINE;
  (4) what remains DISCIPLINE is most of the command's informativeness — with ONE checkable constraint carved out of it: the printed command must reference an identifier, path, or value named in the pack fact it re-runs, and a re-run whose output would read identically whether the pack claim were true or false is recorded as FAILING the floor (the identifier constraint is checkable from the printed command; the identical-either-way counterfactual is the AUTHOR'S judgment and stays attested — one checkable, one attested, labeled as such) (the same agent chose the fact and would choose the command, and a near-tautological stand-in passes any gate);
  (5) a named command that no longer exists or cannot run demotes the fact to ESTIMATED and the gate does not fire — the tag is self-assigned and "naming a command is not running it", so a decisive gate resting only on labels is a gate resting on the agent's own bookkeeping. Run it and paste the command and verbatim output in the record — same caveat spikes carry: the main agent chooses which fact to re-run and transcribes the result, so this is grounded in what was executed and single-authored in what is reported. And the run can DISAGREE — that is the point of running it: if the output contradicts the pack's MEASURED claim, the fact is demoted to ESTIMATED, pack-v2 is emitted with the diff, the gate does not fire, and the round is a close pair (NO WINNER autonomously); output that is AMBIGUOUS — neither cleanly confirming nor refuting — is treated as CONTRADICTS for gate purposes, since the adjudicator authored both the claim and the command. A gate that only recognizes confirming output is a label with extra steps. A re-run CARRIES across rounds within one tournament while the deciding dimension is unchanged; a round whose deciding dimension differs needs its own re-run, because the old evidence bears on the old margin. If nothing on the deciding dimension can be re-run, the gate does not fire: the round is a close pair, NO WINNER autonomously — the same shape the zero-MEASURED pack and the failed responsiveness test already take. An agent-judged "impossible" that still fires the gate would be the label-not-a-gate failure this file names two paragraphs above. Failing the floor entirely, the round is a close pair labeled "no MEASURED fact on the deciding dimension" — and in an AUTONOMOUS run of EITHER mode it is NO WINNER, not a close pair the agent then resolves on its own findings. Same reasoning as the zero-MEASURED pack and the failed responsiveness test: a label is not a gate, and the three branches share one failure shape, so they share one outcome. In an AUTONOMOUS run, a pack with zero MEASURED facts anywhere routes to NO WINNER outright, never to a labeled close pair that lightweight then resolves on self-authored findings — every other zero-evidence branch ends in NO WINNER, and a label is not a gate.
- A **FATAL** requires a MEASURED fact on the dimension THE FLAW ATTACKS, not on the margin's deciding dimension — a data-loss kill needs data-loss evidence, and a maintainability measurement licenses nothing about data loss. Failing that it is a CONCERN. And a FATAL carries the SAME re-run obligation as the decisive gate — the artifact that can overturn the entire matrix does not get a lower bar than the gate it overturns: the MEASURED fact the FATAL rests on must be RE-RUN IN SESSION (the tag's named command, verbatim output shown) before the FATAL stands; AMBIGUOUS output is CONTRADICTS, and a command that no longer executes leaves nothing re-runnable — the FATAL demotes to CONCERN. EXCEPT when nothing is re-runnable because the AGENT HAS NO EXECUTION TOOL: a FATAL defanged by the environment rather than by its evidence routes the round to a close pair (user decides; NO WINNER autonomously) — the flaw was never tested, and an untested kill-claim must not decay into a politely recorded row just because the environment cannot run commands. In lightweight, where the same agent wrote the pack and administers the red-team, this execution requirement is the only part of a FATAL that is not self-attestation.
- The **sole-survivor 5.0 floor** is a decisive gate with no second candidate: its deciding dimension is the highest-weighted dimension scoring below 5 (equal weights break to the LOWER score, then alphabetically by rubric name — the same terminal-tiebreak convention every other selector carries); when the survivor scores ≥5 everywhere, it is simply the highest-weighted dimension — the floor is never inapplicable, because an unopposed winner on an all-guesses pack is exactly the case it exists to catch. The citation apparatus otherwise runs perfectly on the agent's own guesses and produces a fully cited winner grounded in nothing.
   - Write the pack to a file and print its SHA-256 BEFORE the first candidate appears. **No execution tool** (BINDING): an agent that cannot run commands or compute hashes prints "hash unavailable — no execution tool" rather than ANY value — an emitted hex string that was never computed is fabrication, the exact label-without-mechanism failure this file exists to prevent — records ZERO re-runnable facts, and treats every decisive gate as failing the evidence floor: close pair to the user, NO WINNER autonomously, same loud stop as the zero-MEASURED pack (no filesystem → print the pack verbatim in the output and hash that text, saying so — the Phase 5 record's fallback); the decision record carries the pack verbatim so any reader can recompute. This detects an INCONSISTENT record, not a dishonest author — an agent that swaps the pack and reprints the hash produces a flawless single-authored document. The hash binds the record together; it does not certify the process.
   - The pack is frozen at the checkpoint. FULL mode: subagents may request late facts under the versioning protocol in `references/full-mode.md` (FACT REQUEST lines, pack-v2/v3 with printed hashes, capped re-spawns). LIGHTWEIGHT: no subagents exist to request anything — the pack the checkpoint froze is the pack, and discovering it is inadequate mid-run is a Phase 0 reopen or NO WINNER, never a quiet edit.
2. Restate the problem in one paragraph, including how the current approach fails.
3. **Pre-register the expected winner** (DISCIPLINE — recorded, but self-reported and unverifiable): one sentence — "before generating, I expect some form of X to win." Recorded in the output and decision record; excluded from every SCORER and SKEPTIC prompt, but SUPPLIED to the red-team packet ONLY when a crossbreed round ran — the MATCH/NO-MATCH audit is the sole reason the red-team needs the prior, and on a non-crossbreed run the packet line reads "pre-registration withheld: no MATCH/NO-MATCH call to audit", so the only verdict that can overturn the matrix stays prior-blind whenever knowing the prior buys nothing. When supplied, the leakage cost is booked: those finalist verdicts are not prior-blind, accepted because auditing the anti-favorite seed requires knowing the favorite. Its value: the agent must articulate its prior, and the user can compare it against the framing in the verbatim field. A match with the winner is uninformative alone (the prior is misreportable), so no scrutiny asymmetry attaches.
4. Define 4–6 scoring dimensions. Defaults (adjust per problem): root-cause resolution 30%, robustness/production-readiness 25%, maintainability/simplicity 20%, performance/cost 15%, implementation risk/reversibility 10%. Weights always sum to 1.0; after any user reweighting, normalize back to 1.0 and show the normalized weights — every threshold in this file assumes that normalization.
5. **Rubric checkpoint** (BINDING when a user is present): show the user the dimensions and ask them to rank or reweight — an approval of pre-filled weights is consent to defaults, not an expression of values, and the output must say which it got ("weights: user-edited" vs "weights: defaults, user-approved" vs "weights: defaults, autonomous run"). Skipping the checkpoint requires pre-authorization that names tournaments specifically, quoted in the output — ambient autonomy settings do not qualify. Weights freeze for the whole tournament; mid-tournament changes happen only at the user's initiative, and then both the before and after matrices are shown.
6. **Disqualification rule** (artifact BINDING; uniformity DISCIPLINE — the per-candidate results are visible, identical application is not falsifiable from the output):
   - Name the symptom as a falsifiable test: "this candidate leaves <observable root cause> in place; check: <what to look at>". Apply it to every candidate and show each result.
   - **DQ pre-commitment** (optional, but it is the ONLY thing that lets an autonomous-lightweight removal survive Phase 2.11(c)) — the rule lives here beside the test it extends, but its MOMENT is the Phase 1.5 removal step, when the DQ verdict is recorded and surviving candidates exist to name (at Phase 0 there is no field yet): at that step the author MAY pre-commit a SURVIVING candidate's row and the score range the removal's premise entails there, under the same width rule as 2.11(b) — the range must exclude at least half the 0–10 scale and name the matrix result that would falsify it. This is the pre-commitment 2.11(c) checks; without it, an autonomous-lightweight DQ removal is NO WINNER by rule, which is the intended default, not an accident. If the pre-committed target is itself dropped by a later filler verdict in the same Phase 1.5 pass, the author may RE-POINT the pre-commitment ONCE to another surviving candidate — re-pointing is printed with both targets, and a second loss of target makes the removal UNFALSIFIABLE as usual.
   - **VERIFIED diagnosis** (reproduction, trace, log, or measurement in the pack — cite it): a candidate that leaves the root cause fully in place is REMOVED from the field before ranking, n shrinks. Never scored 0. Every VERIFIED removal also prints ONE line — "PARTIAL considered and rejected: <the residual path checked for, and the observable showing it absent>" — so the VERIFIED-vs-PARTIAL call, the judgment inside the file's most consequential act, is a visible artifact a reader can contest rather than an invisible classification.
   - **PARTIAL verdict** (the candidate fixes the mechanism but leaves a named residual path): NOT removed. It takes the HYPOTHESIS cap on the root-cause dimension and the residual path is named in its matrix row. Ambiguous cases resolve to PARTIAL by rule, never by judgment — removal happens before scoring and is unrecoverable within the round, and Phase 2.11 cannot falsify it. BUT the cap itself is now bound (it is outcome-sized: at default weights a cap can move a rival by weight × (original − 4) — MORE than the decisive gate): a HYPOTHESIS or PARTIAL cap must pre-commit, when applied, the residual path's OBSERVABLE plus a surviving candidate's row and range under 2.11(b)'s width rule; an un-pre-committed cap whose magnitude weight × (original − 4) exceeds the round's margin demotes the round to a close pair (NO WINNER in autonomous lightweight), and every cap's magnitude prints beside it in the matrix. In full mode each HYPOTHESIS/PARTIAL cap joins the red-team audit duty.
   - **HYPOTHESIS diagnosis**: the rule removes no one. The candidate's root-cause dimension score is CAPPED AT 4 (if the rubric has no root-cause dimension, Phase 0 names which dimension inherits the cap). The cap is applied by the MAIN agent to returned scores — never in the scorer prompt, where naming the suspect would anchor its other dimensions — flagged in the matrix with the hypothesis and the scorer's original value. Ranks on the capped dimension are VOID: that dimension contributes no rank to the tiebreaker, which renormalizes over the rest, so a capped candidate never wins a tie on a rank the cap was meant to neutralize. With two scorers the cap applies to EACH RAW SCORE before the mean is taken (3 and 8 become 3 and 4, mean 3.5 — not a 4.0 cap on the mean), because the cap states what each judge's read of that candidate may be worth, not what their average may be; both originals are shown.
   - Removed candidates appear in the final matrix as REMOVED rows with the test, the cited evidence, and the VERIFIED/HYPOTHESIS call; their full text goes to the red-team packet so the removal is audited by someone other than its author (FULL mode; lightweight has no other author — there, step 11's falsification and the user's objection route are the whole protection, and this sentence promises nothing more).
   - **Precedence when the combined removal pass lands** (identical wording in Phase 1.5): ZERO survivors takes the Phase 0 reopen branch and never the regenerate branch — the diagnosis or rubric is wrong, so reopen Phase 0 once, and a second wipeout ends the tournament with the field, the rule, and NO WINNER. The regenerate and sole-survivor rules apply only when at least one candidate survives.
   - Timing: three ordered steps at the Phase 1.5 boundary — (a) apply the DQ test to all candidates and record verdicts; (b) run the batched skeptic on the full field, removed text included for context; (c) count DQ removals and filler verdicts together and take the removal branch.
7. Read prior decision records: `docs/decisions/NNNN-*.md` via the `docs/decisions/INDEX.md` one-line-per-record index (skip with a note when there is no repo). Records are dated claims: before carrying a rejection forward, verify its blocker still exists.

## Phase 1: Divergent generation (n candidates)

- Each candidate differs from every other on a **named structural axis** (architecture, data model, dependency, algorithm class, where-the-logic-lives). Slot #1 is the obvious approach, named as such. At least one candidate is a credible long shot — the test: could it plausibly win one rubric dimension outright? A field of paraphrases is a failed generation: regenerate once; if the problem genuinely has fewer than n distinct axes, run with what exists (minimum 2) and say so — and if fewer than 2 credible axes exist, the problem is NOT tournamentable: exit under the skip floor with the reason printed, generating no field at all (every field-size floor in this file terminates somewhere; this is where this one does).
- Per candidate: mechanism, what it assumes, what breaks it — **90–150 words each** (countable, checkable; "equal length" is not). **Candidate hashes** (RECORD-BINDING — binds the record to itself, not the author; see the caveat below): when the field is frozen at the end of Phase 1.5 (post-revision, post-removal), print each surviving candidate's mechanism-text SHA-256 next to its label. The same hashes appear in the scorer packet, in the verbatim field shown to the user, and in the decision record. Same caveat as the pack hash, and it matters more here: this detects transcription drift between the shown and recorded text, NOT a dishonest author — one agent prints both the text and its hash, and no reader ever sees the packet a subagent actually received, so a substituted candidate with a re-printed hash is undetectable. Framing quality is the highest-bandwidth bias channel, the user is its only real detector, and this mechanism helps the user hold one version of the text rather than proving anything.
- **Cross-advocacy pass** (full mode only): rule text in `references/full-mode.md` — lightweight skips it, since its unblinded scorer sees the generation reasoning regardless.
- "What breaks it" names a rung on a fixed severity ladder — data loss / correctness / performance / effort — so severity is comparable across candidates rather than rhetorical.

## Phase 1.5: Skeptic pass (before scoring)

- **Incomplete skeptic return** (full mode only — LIGHTWEIGHT has no subagent and no return, so this rule lapses there exactly as Phase 2's return gate does): rule text, including the re-spawn and the demotion consequence, in `references/full-mode.md`.
- **One batched skeptic call** (fresh subagent in full mode — see `templates/skeptic.md`; in lightweight mode, write all critiques and premortems before assigning any score — ordering discipline, not independence): attacks ALL candidates in one pass and authors, for each, critique → revision guidance → premortem. The skeptic, not the generator, writes every premortem, in one call, holding severity comparable across candidates: each premortem (≤80 words) names its failure class from the severity ladder plus a likelihood and a detection point ("would surface at integration"), so scorers grade the risk, not the vividness of the story.
- **Filler verdict** (BINDING): a candidate with no plausible path to winning ANY dimension is DROPPED before scoring.
  - The verdict text appears in the final matrix as a DROPPED row: a culled field must be visible, never silent. In lightweight mode every DROPPED and REMOVED row also carries "self-authored removal" — the skeptic there is the generator wearing a different hat.
  - Removal precedence (DQ removals and filler verdicts count together as one number): ZERO survivors takes the Phase 0 reopen branch and never the regenerate branch (Phase 0.6); the rules here apply only when at least one candidate survives. Then FIRST the failed-generation rule — more than one removal in the combined pass means regenerate the culled slots once, and regenerated slots get the DQ test plus an **abbreviated skeptic pass** — defined once, here: critique + premortem + filler verdict for the new candidates only, no revision round, no re-critique of surviving candidates. Phase 3's crossbreed offspring use this same definition. A second collapse — ANY removal of a regenerated slot, either type — means stop and show the user both fields with the verdicts.
  - Only past that rule does the sole-survivor rule apply — and it is reached by one field shape only: a two-candidate field (Phase 1 found fewer than n real axes, or a prior round reduced it) losing exactly one candidate, since more than one removal triggers regeneration and any removal of a regenerated slot stops the run. Kept because that shape is legal and its outcome must be defined, not because it is common: a lone survivor is still SCORED solo against the rubric (scoring one candidate is nearly free and produces the matrix). It proceeds to Phase 4 only at a weighted total ≥ 5.0, carries the line "sole survivor — ran unopposed", and a present user confirms it as a decision. Below 5.0, or in any autonomous run, an unopposed survivor is NO WINNER: report the field, do not implement.
- **Revision**: each survivor gets one strengthening pass that may not change its named axis. Whether a proposed fix crosses the axis is the skeptic's call, made in the batched call with the axis named — not the generator's call afterward.
- **Show the user the field** (BINDING when a user is present): at the end of Phase 1.5, output the candidates' mechanism texts and premortems verbatim (not summaries), each with its SHA-256 as printed at freeze. Framing bias is visible to a human reading the raw text and invisible to every mechanism inside the skill. **Objection branch** (BINDING when a user is present): showing the field is pointless without a route to act on it. A stated objection to a candidate's framing ("C is described unfairly", "you buried B's real strength") forces ONE rewrite of that candidate's mechanism text with its named axis unchanged, a re-freeze with new hashes, and a printed FRAMING OBJECTION row naming the objection and what changed — and the REWRITTEN mechanism text is RE-SHOWN to the objecting user verbatim with its new hash (the user contested this exact text's framing; a diff summary is not verification), a re-show that consumes no new interaction WITHIN its exchange: it is the closing half of the objection exchange already open. Objection exchanges themselves are USER-initiated and sit OUTSIDE the interaction sums (which count agent-initiated asks) — bounded at one per candidate, so a user exercising every objection adds at most n−1 exchanges, stated here so the ranges stay literal sums of what the agent spends. One objection per candidate — but Objection branch, numbered with no content change: (1) USER FRAMING OBJECTIONS are EXEMPT from the post-freeze mutation budget — the user is channel 1's only real detector, and a safeguard that costs the user their decisive result is a safeguard with a disincentive built in, this file's own rule;
  (2) each objection rewrite still takes the DQ test and abbreviated pass — in full mode the FIRST uses the reserved abbreviated-skeptic slot and any further objection takes a SELF-ADMINISTERED abbreviated pass labeled as such (never a spawn beyond the call ceiling, never a demotion); in lightweight every pass was self-administered already.
  (3) The mutation budget (one per run, either mode) caps AGENT-initiated mutations only: regenerating beyond the once-per-run rule and crossbreed offspring edits. A RE-ADMISSION is a USER act — the user outranks a single skeptic verdict exactly as they outrank a framing, so it is EXEMPT from this budget alongside framing objections; it still takes the DQ test and abbreviated pass (reserved slot first, then labeled self-administered), and the exemption is printed on the re-admitted candidate's row. Regenerated slots are NOT post-freeze mutations — regeneration happens inside Phase 1.5 and the freeze occurs AFTER it, so the ordinary two-removal cull regenerates without touching this budget (a regenerated slot still takes its DQ test and abbreviated pass as Phase 1.5 requires). The rewrite may strengthen, never re-scope. **Field-mutation rule, stated once for every route**: ANY candidate whose text changes or that enters the field after the freeze — an objection rewrite, a user re-admission, a regenerated slot, a crossbreed offspring — takes the DQ test and the abbreviated skeptic pass (critique + premortem + filler verdict) before scoring, and is re-frozen with a new hash.
  A mutated candidate that its own DQ test or abbreviated pass then REMOVES shrinks the field with ONE consequence, named here so it cannot be confused with the second-collapse STOP (which applies only to Phase 1.5's original removal passes): the round demotes to a close pair, or to the sole-survivor rule / NO WINNER if fewer than two remain; a post-freeze removal is never silent. A mutated candidate scored against a stale premortem is scored on inputs the field was not, which is this file's own definition of a silent wrong answer. One abbreviated skeptic slot is RESERVED for exactly this route (see the call budget: the ceiling is 18, not 17, for this reason), so exercising the user's objection or re-admission — the file's most emphasized exogenous check — does not demote the round on the FIRST post-freeze mutation (a second one can — see the fallback below); a safeguard that costs the user their decisive result is a safeguard with a disincentive built in. In LIGHTWEIGHT — which has no call ledger to denominate this in — the budget is counted directly: ONE AGENT-INITIATED post-freeze mutation per run (user re-admissions and user objections are BOTH exempt — the budget caps only the agent's own edits; regeneration precedes the freeze and is exempt; the same one-slot budget as full mode, because self-authorship being total is a reason for a tighter leash, never a looser one), self-administered and labeled; a second agent-initiated mutation demotes the round to a close pair. USER framing objections do NOT touch this budget in either mode — the exemption in Phase 1.5 governs, and a second user objection proceeds exempt, never demotes. In FULL mode, only when the reserved slot is ALREADY spent (a second mutation in one run) does the fallback fire: the candidate scores carrying "no premortem — ungraded risk" and the round demotes to a close pair, matching the incomplete-return consequence. Re-admission may push the scored field above the mode's n — permitted, scored as-is, and noted in the matrix ("field: n+1 after re-admission"); a larger field costs scoring effort, never validity. Re-admission does NOT recompute the removal-count branch — that branch was decided on the field as culled, and re-admission is a user override of one verdict, not a re-run of the pass. The same route covers REMOVALS: a user who contests a REMOVED or DROPPED row re-admits that candidate into scoring (labeled "re-admitted by user objection"; a HYPOTHESIS-grade DQ concern travels with it as the cap) — the user can end the whole tournament, so a fortiori they outrank a single skeptic verdict, and the only exogenous check must be able to reach the most consequential act, not just the prose around it. In autonomous runs the verbatim field goes in the decision record instead, and the output records that no objection route ran — the only real detector of the highest-bandwidth bias channel was absent.

## Phase 2: Adversarial scoring (independent only in full mode)

Not "blind": label-shuffling removes authorship and ordering effects, but nothing hides which candidate is the conventional one, and scorers share the generator's model priors — their agreement is consensus, not evidence. The mechanisms below raise the cost of vibes; they do not turn scores into measurements.

**Scoring procedure — run in this order.**

0. **Return gate** — three sub-steps, in order:
   - **(a) Completeness**: every label sent was scored and every required field is present.
   - **(b) Responsiveness**: each scored dimension quotes a candidate-specific locator — a mechanism element, assumption, or premortem clause unique to THAT candidate, such that the sentence would be false pasted under another candidate's row. The locator is quoted in the matrix so a reader can apply the paste test; the agent's own application of it is DISCIPLINE. It detects generic text reused across rows; it cannot detect a candidate-specific quote attached to a generic judgment, which is the subtler hollow shape — so it raises the floor rather than closing the failure.
   - **(c) Recompute and correct**: recompute every weighted total from the returned cells before any gate reads one — this is the single number every branch depends on and it arrives from a subagent. A discrepancy > 0.05 means the recomputation stands and prints as an ARITHMETIC CORRECTION row; a discrepancy on either of the top two rows — the top two of the CORRECTED ordering, since the recomputation stands — demotes the round to a close pair.
   - Failures: a short or malformed return gets ONE re-spawn (see the reservation rule in Cost honesty); a second short return is "incomplete scoring" → close pair. A failed locator test → close pair labeled "unresponsive scoring" — and in an AUTONOMOUS LIGHTWEIGHT run that close pair is NOT resolvable by the same agent on its own findings (that would make the test a label and nothing else, in the configuration where it matters most): the run ends NO WINNER — matching its three sibling zero-evidence branches; a disjunction the agent resolves for itself is not a safeguard, so there is no second option.
   - **Mode note**: LIGHTWEIGHT has no return, so (a) and the ARITHMETIC CORRECTION row and "incomplete scoring" lapse — but the DEMOTION does not — and to keep it from penalizing disclosure (a silent fix is invisible, so a rule that punishes reporting selects for hiding), lightweight RECOMPUTES the post-check total from the printed cells in a separate pass and prints both totals per row — and the binding check is a READER recomputing from the printed cells, not the printed pair itself, which one computation printed twice would satisfy vacuously. Label the consequence honestly too: under self-computation the discrepancy demotion will essentially never fire from the agent's side — in lightweight it is a READER-triggered rule, disclosure plus a hook for the user, not a live self-check. A discrepancy on either of the top two rows still makes the round a close pair. (b) and (c) still bind — a self-scorer writes generic rationale as easily as a subagent, and the responsiveness test matters MOST where author and scorer are the same agent — though state what it delivers there honestly: autonomously its failure is self-declared, and what a reader actually gets is the quoted locator to paste-test, not a self-triggered stop.

1. **Scale**: 0–10 per dimension (2 = serious deficiency, 5 = adequate with real concerns, 8 = strong with minor concerns). **Weighted total = Σ(weight × score)**, weights summing to 1.0, so totals and margins live on the 0–10 scale.
2. **Margin, defined once**: the difference between the TOP TWO weighted totals in whatever comparison the current gate names — decisive gates use the round's best two; the plateau gate uses best offspring vs the carried anchor. The **carried anchors** are the two parents that entered the current round; the plateau comparison uses whichever scores higher in the CURRENT round (both totals shown). Next-round succession is a separate end-of-round computation in Phase 3.
3. **Who scores**: full mode spawns a scoring subagent (`templates/scorer.md`) receiving ONLY the frozen pack plus candidates and premortems under neutral labels. Two scorers whenever ANY full-mode trigger was architecture, data-integrity, or a failed prior fix; one otherwise. What the second same-model scorer buys, plainly: DISPUTED divergence and STRUCK-cell recovery — real but narrow, since correlated error passes both. When the choice is a second scorer or a spike, note: no live choice exists between a second scorer and a spike — the scorer is mandated when triggered and unavailable otherwise — so no preference rule applies. Lightweight mode self-scores unblinded, says so in the output, and follows the same numbered procedure as a scorer subagent — the procedure as stated in THIS file is complete for lightweight; templates/ are full-mode spawn material and lightweight never loads them — including the forced 1..n ranking, which the tiebreaker in step 10 needs and which matters MORE here (n=3 self-scoring is exactly where 7–8 clustering happens) — writing the strongest case AGAINST each candidate before assigning any number.
4. **Label order**: candidates are ordered by the frozen mechanism-text SHA-256s from Phase 1.5, which are also listed in the scorer packet so the scored text is bound to the shown text. DISCIPLINE: this removes incidental generation-order effects; it cannot resist deliberate authorship, since the agent writes the hashed text.
5. **Cite before scoring**: for each dimension, state which pack facts bear on it — the same fact set for all candidates — then score against them with quote + locator. A cherry-picked true fact still serves a prior, so this raises the cost of vibes; it does not make scores follow from evidence.
6. **Verify citations** (main agent, on return):
   - A citation absent from the pack STRIKES the cell. Struck cells are marked STRUCK in the matrix with the fabricated citation quoted, in both scorer modes — and in LIGHTWEIGHT the mark reads "STRUCK (self-verified against a self-authored pack)", since there the same agent wrote the pack, the citation, and the verdict on it.
   - Striking VOIDS that scorer's ranks on that dimension; the tiebreaker renormalizes over the remaining dimensions, exactly as the HYPOTHESIS cap does. A SELF-SCORED recovery does NOT restore the rank — the rank was formed on a value that no longer exists, and the replacement was authored by the main agent. **Floor**, mirroring the dimension-drop floor: if fewer than 2 dimensions retain live ranks, the tiebreaker is unavailable and the round is a close pair (user decides, or NO WINNER autonomously) rather than renormalizing over nothing. No tie is decided by a rank whose score no longer exists.
   - Recovery, in order — and ANY recovered value on a HYPOTHESIS-capped dimension re-applies the cap before entering the total, with both values printed (a replacement is not a returned score, but the cap binds the candidate, not the score's provenance): take the other scorer's value if one survives → else re-score (main agent, marked SELF-SCORED — in LIGHTWEIGHT it reads "SELF-SCORED (rewrite, not repair: same agent authored the pack, the citation, and the strike)") if re-score budget remains → else mark the cell UNSCORED and drop that dimension for EVERY candidate, renormalizing the rubric uniformly, then make the round a close pair. **Floor on dropping** — four ordered steps, mirroring the all-OPINION rule:
     1. Identify candidates with COMPLETE pre-drop rows. Fewer than two → close pair; the floor is not attempted.
     2. Compute the deciding dimension on the PRE-drop matrix over those candidates only (dropping renormalizes and would otherwise redefine the thing being protected; the candidate that triggered the drop has an UNSCORED cell and no total to rank).
     3. Block the drop if it would leave fewer than 3 surviving dimensions, or would remove that deciding dimension.
     4. When blocked: the round is a close pair, no further dimension may be dropped, and that candidate's weighted total prints as INCOMPUTABLE — never an imputed number, since an invented value is exactly the silent wrong answer this file forbids. A candidate with an INCOMPUTABLE total is NOT eligible for top-two selection by total — there is no number to rank it with, and inventing one is the failure this rule exists to prevent. If that leaves fewer than two eligible candidates, the round is NO WINNER autonomously, or goes to the user with the full matrix when one is present. Ordering among an eligible close pair falls to the tiebreaker over surviving dimensions; if that cannot separate them either, the choice goes to the user, or NO WINNER autonomously. (The floor makes zero surviving dimensions unreachable, since Phase 0 mandates 4–6 and dropping stops at 3.) A tournament deciding on one surviving dimension while printing a full matrix is this file's own definition of a silent wrong answer. Never renormalize one candidate alone: redistributing its weakest dimension's weight onto its strengths inflates its total against rivals scored on the full rubric, and totals feed the top-two selection, the tiebreak band, and the plateau comparison as if they were commensurable. A voided score never silently reverts to the struck value.
7. **Combine scorers**:
   - Two-scorer cell aggregation, DISPUTED flagging and its ≥ 0.9 weight×spread consequence, struck/DISPUTED precedence, and rank-inversion surfacing are FULL-MODE machinery: rules in `references/full-mode.md`. Lightweight has one self-scoring pass and no cells to combine; only the re-score budget below applies there.
   - **Re-score budget**: 2 main-agent re-scores per tournament, shared across both paths (struck-cell recovery and DISPUTED). A Phase 0 reopen restarts the call budget but NOT this one — the re-score path is how independent scoring reverts to self-scoring, and a reopen is not a reason to double the self-scored cell count. The matrix prints the count of main-agent-scored cells — the channel through which independent scoring reverts to self-scoring must be visible.
8. **OPINION**: a score with no citable fact is OPINION at full weight; a cell counts as OPINION only if both scorers marked it — a deliberate unanimity gate in the two-scorer tier, because one grounded citation IS evidence for the cell and a split verdict should not weaken a dimension the way a unanimous one does; the cost, stated plainly, is that the redistribution lever and the ≥0.25 stop demand unanimity exactly in the highest-stakes tier, and a split cell prints "OPINION (1 of 2)" so the partial doubt is visible even though it does not count. With a SINGLE scorer (lightweight, or the one-scorer full tier), that scorer's mark alone makes the cell OPINION, so the safeguard never silently switches off in the most common configuration. Declining to cite is a weight lever, so a majority-OPINION dimension is a FINDING in the matrix, never a silent mechanic.
9. **Redistribution** — applying to any majority-OPINION dimension, with a hard autonomous stop at weight ≥ 0.25 (stated here in the prose, not only in the branch table, so the precedence rule can see it); one of exactly THREE exceptions to the Phase 0 weight freeze — the others being a user-initiated mid-tournament reweight (Phase 0.5) and the UNSCORED dimension-drop (Phase 2.6), which is permitted even in lightweight and autonomous runs because it removes a dimension uniformly for every candidate rather than selectively reweighting toward one. All three make NOISE unusable for the following round under the "weights changed" clause: a majority-OPINION dimension's weight may be redistributed proportionally (renormalize to 1.0) ONLY with the user's explicit assent, forbidden in lightweight and autonomous runs — two explicit autonomous cases, so the governing prose is the clear version: at weight ≥ 0.25 the run STOPS (NO WINNER, the branch-table row); below 0.25 the dimension keeps full weight and the round is a close pair labeled "majority-OPINION at decisive weight", stated here rather than left to inference — and forbidden past ONE dimension per tournament. Once applied it persists for all remaining rounds so cross-round comparisons stay under one weight set; both weight sets appear in the record. If EVERY dimension is majority-OPINION, the pack cannot support scoring: NO WINNER this round — reopen the pack if the single reopen counter is unspent, otherwise end. Not a choice: the counter decides.
10. **Ties**: when totals land within 0.3 points, the tiebreaker is **weighted mean rank** = Σ(weight × rank), lower wins (with two scorers, the mean of their weighted mean ranks). Forced ranking (1..n, no ties) exists to break 7–8 clustering; ranks never enter the total. A surviving tie routes like any close margin in the current mode.
11. **Falsify the removals** (after scores exist) — five sub-rules, each with its consequence stated once:
    a. **Domination-argument filler verdicts**: fail if the named dominator was scored and did not win that dimension. A failed argument is a BROKEN REMOVAL PREMISE (see e).
    b. **Cited-fact filler verdicts**: must have pre-committed, at removal time, a SURVIVING candidate's row and the score range the fact's implication ENTAILS there — and the range must EXCLUDE at least half the 0–10 scale (compute it: the committed range's width on the 0–10 interval must be ≤ 5.0 — a "0–6" commitment is 6.0 wide, visibly non-compliant) and name the matrix result that would falsify it, by rule rather than judgment — and the named falsifying result must be REACHABLE on that row: a falsifier sitting above a HYPOTHESIS cap, on a struck cell, or on a dropped dimension can never occur, and a test that cannot fail is not a test — on a capped row the range binds the scorer's ORIGINAL pre-cap value (both print by the cap rule), which is the reachable quantity; an unreachable falsifier makes the verdict UNFALSIFIABLE by rule with the existing consequence: the removal's author also authors the range, and a wide-enough range is a test by nothing. A range failing the width rule makes the verdict UNFALSIFIABLE (existing close-pair consequence). The verdict fails if the matrix lands outside the committed range. No pre-commitment → UNFALSIFIABLE (see d). Post-hoc contradiction-checking by the verdict's own author is not a test.
    c. **DQ removals**: UNFALSIFIABLE BY DEFAULT (a removed candidate has no matrix row) — and in AUTONOMOUS LIGHTWEIGHT, where step 11 is the only protection on the most consequential act, an un-pre-committed DQ removal is NO WINNER outright rather than a self-resolved close pair: the removing agent does not also get to be the only check on the removal — unless the removal pre-committed a surviving candidate's row and entailed range (Phase 0.6); those are checked as in (b).
    d. **UNFALSIFIABLE** (any route, including a named target later dropped or lost in regeneration): the removal stands, but the round routes to a close pair — the same consequence on every removal path — WITH one uniform tightening: in AUTONOMOUS LIGHTWEIGHT, an UNFALSIFIABLE removal of ANY kind (un-pre-committed DQ, un-pre-committed filler verdict, or a width-rule failure) is NO WINNER outright, never a self-resolved close pair, because on every one of those paths the removing agent would otherwise be the only check on its own removal. The same event resolves identically on every path, including this one.
    e. **BROKEN REMOVAL PREMISE**: the removal stands (re-scoring mid-stream would unfreeze the field), but the round demotes to a close pair, the dropped candidate's verbatim text goes to the user or the record with the finding, and no decisive result may be claimed on a field culled on a false premise.

- Show the full matrix — including DROPPED and REMOVED rows — never just the winner.

Bands: per-threshold, carried as the band value beside each name in the Exit Phase 3 enumeration — the single authoritative source; none are restated here.
  (2) Measure against the EFFECTIVE threshold actually applied — max(1.0, NOISE + 0.5) for decisive and max(0.5, NOISE) for plateau, the same formulas rules 2 and 3 use (a stale copy here once measured proximity against a gate that was never applied); the initial round's decisive gate is the fixed 1.0.
  (3) Be plain about what selects: with 0.3-wide bands on 0–10 gates, near-miss identification fires on MOST realistic runs — the band is a coarse filter and the ranked cap below is the real selector; a "near-miss" therefore signals "worth a look", not "statistically exceptional". At most TWO near-misses per run reach the user, batched into a single question and ranked by a computable key — PROXIMITY = |value − effective threshold| ÷ that threshold's band (the band value printed beside its name in the Exit Phase 3 enumeration — not restated here); smaller is closer — WITHIN a class. Two classes exist and dimension-bearing near-misses outrank dimensionless ones at ANY proximity (a margin near a gate deserves the user's attention before a counter sitting on its threshold, which is common and low-information): first all dimension-bearing near-misses ordered by PROXIMITY then higher weight (quantities carrying no single dimension weight — e.g. the decisive margin — skip the weight key and fall through to phase order; class membership per threshold is NOT decided here: the [D]/[X] token beside each name in the Exit Phase 3 enumeration is the sole authoritative assignment), then dimensionless ones ([X] in the Exit Phase 3 enumeration) ordered by PROXIMITY, and any remaining tie breaks by phase order, earliest first — then alphabetically by threshold name as printed in the Exit Phase 3 enumeration, so no tie survives and "fully determined" is true as written.
  (4) Worked selection: margin at PROXIMITY 0.9, DISPUTED spread at 0.6, removal counter at 0.0 → the spread and the margin surface (dimension-bearing, closest first), the counter is recorded and threshold-decided. The ORDERING of identified near-misses is fully determined — two agents holding the same identified set surface the same two. Which quantities get identified as near-misses at all is DISCIPLINE: it depends on the agent checking each threshold, and no mechanism verifies the DISTANCES were honestly computed — the NAME list itself IS diffable against the Exit Phase 3 enumeration, so a silently omitted threshold is visible; what stays unverified is the arithmetic under each printed name. The two surfaced are therefore derivable and contestable rather than chosen; the rest are recorded and threshold-decided with the "unreviewed" label — an unbounded interruption count is not a budget, and the published interaction ranges assume this cap.
  (5) Surfacing is identical in wording whichever side the favorite is on, with the agent's own preference stated separately so the user can discount it; autonomously, record the near-miss with both sides flagged, take the threshold's outcome, and label it "decided by threshold, unreviewed". Near the line, judgment decides, not arithmetic.

## Phase 4: Red-team, spikes, and audit

Routing: a decisive winner is red-teamed alone; a close pair (by any route — see Phase 3) is red-teamed in one packet covering both finalists. Fresh subagent in full mode (`templates/red-team.md`); in lightweight mode the MAIN agent runs the red-team questions itself — SELF-ADMINISTERED, and any decision resting on those findings (including the autonomous lightweight close call) says the findings were self-authored.

- **Full-mode red-team machinery** — the pack-bound limit and its read-only escape hatch, the absent-approach duty, the evidence bar for FATAL, and the audit duty with MECHANICAL consequences — lives in `references/full-mode.md`. LIGHTWEIGHT self-administers the standing questions below, labels the findings self-authored, and has no audit: step 11's falsification is the whole protection on its removals.
- **Spike gate** (FULL mode only): criteria-before-build, budgets, isolation, reporting caveats — in `references/full-mode.md`. Lightweight never spikes.
- **FATAL re-check on return** (BINDING, both modes; the actor is the MAIN agent, exactly as the HYPOTHESIS cap names its actor): every FATAL in a returned (or self-administered) red-team report is re-checked by the main agent against Phase 0's FATAL bar — a MEASURED fact on the dimension the flaw attacks, re-run in session. A FATAL citing a SPIKE result instead satisfies this re-check when the spike's raw command and verbatim output are in the record — a spike IS an in-session run, and demanding a pack re-run of it would nullify the artifact built to settle close races; a FATAL citing a pack fact takes the re-run obligation. THIS sentence governs over any evidence-bar wording in the full-mode file or templates. A FATAL failing its applicable check prints as CONCERN with the demotion reason on its row; the template's own evidence language is weaker than this bar on purpose (a subagent cannot re-run pack commands), so the demotion duty sits here, not in the packet.
- **Severity gate** (BINDING, both modes) — numbered sub-rules, split for readability with no content change: (1) the severity ladder is not just for comparability — it GATES. A standing CONCERN or premortem against the candidate about to be implemented at the DATA-LOSS rung (ANY likelihood) or the CORRECTNESS rung at HIGH likelihood — where rung and likelihood come from the FINDING'S AUTHOR (the red-team return or the premortem), never assigned by the main agent after it knows which candidate it intends to implement; a CONCERN returned without a rung is treated as DATA-LOSS, full stop, in full mode — the author is a completed single-shot return and cannot be asked (no re-spawn line covers re-runging); in lightweight the self-author supplies the rung at write time or the same DATA-LOSS default stands.
  (2) In LIGHTWEIGHT the separation clause has NO FORCE — the red-team is the main agent, so rung and likelihood are self-assigned by the same party that selects the winner; the gate's row prints "severity rung self-assigned (lightweight)", and in AUTONOMOUS lightweight an unrunged CONCERN stays DATA-LOSS and cannot be re-runged by the same agent — it clears only by route 2's named test command — DEMOTES a decisive result to a close pair (user decides; NO WINNER autonomously) — and on a round that is ALREADY a close pair, the gate still binds: a DATA-LOSS-rung standing concern on the finalist selected for implementation must clear one of the routes below before Phase 5 REGARDLESS of how the round arrived, else NO WINNER — with ONE exception, consistent with the close-pair rule's user supremacy: a PRESENT user may accept an uncleared data-loss concern as a LABELED OVERRIDE ("user accepted <concern> uncleared" printed on the decision row); autonomously there is no override and NO WINNER stands (a gate whose consequence evaporates on one arrival path is a label on that path).

  (4) Two clearing routes, because an absence-proof by command is rarely constructible: (1) the pack carries a re-run MEASURED fact showing the named mechanism absent, or (2) the implementation plan names a MITIGATION for the exact mechanism plus its pre-production DETECTION POINT — which must be a NAMED TEST COMMAND, existing or committed to in Phase 5, not a prose assurance — printed on the gate's row. Route 2 is SELF-ATTESTED in BOTH modes — the main agent authors the mitigation in full mode too, the red-team never writes one — and its row carries that label in both; the named test command, not the author, is what keeps it above a label, the same execution bar the FATAL re-check and evidence floor carry. An item whose premortem names no pre-production detection point cannot clear by route 2 — undetectable-until-production is what the gate exists to stop.
  (5) Without this rule the file's own top severity class could reach production as a politely recorded row; a data-loss concern that gates nothing is a label.
- Standing questions: What happens at 10x? In 6 months, context forgotten? Which single assumption, if false, kills it — and how would we detect that early? Is any part a bandaid wearing a suit (special cases, silenced warnings, magic constants, "temporary" flags)? - **Close-pair terminal rule** (BINDING): when both finalists survive red-team and spikes do not discriminate (both pass, both fail, or no spikes ran), the tournament has separated all it can: the choice goes to the USER with both red-team reports — and a USER-selected finalist is EXEMPT from the Survivor floor (the user outranks every internal gate; that is this file's design, not an oversight), with the exemption LABELED on the decision row: "selected by user; no evidence-floor gate fired for this finalist", plus the re-run that WOULD have cleared the floor printed beside it so the user can request it before confirming, the spike criteria and results, and the final matrix. Autonomous: NO WINNER per the uniform fallback — a full-mode close pair is never resolved by the agent's unaided preference. A discriminating spike result or a standing FATAL selects the survivor.

## Output format

Every tournament ends with: the rubric (weights + provenance), pre-registration vs. outcome, the per-round matrix (all candidates, DROPPED and REMOVED rows included, OPINION flags and any weight redistribution visible), the decision trail, red-team findings with audit marks, then the implementation. Never present only the winner.

Final self-check (DISCIPLINE — self-administered and labeled as such): reread the artifacts once for box-filling. For EVERY finalist that reached Phase 4 — symmetric, so repair cannot ratchet the winner's record above the field's — a mechanical premortem, an uncited score, or an empty red-team pass is redone AND logged: a "repairs applied" line in the matrix lists each redone artifact, whose it was, and why (correction and disclosure are not in tension; a repaired record with no repair log is the process's own silent-failure channel). For candidates eliminated before Phase 4, disclosure alone suffices. An output with no weakness labels has not been vetted; it has been self-reviewed, which catches obvious lapses and not systematic ones.

## Cost honesty

In full mode, deliberation stays in subagents; only summaries, matrices, and decisions return to the main thread (lightweight mode has no subagents and pays its cost in main-thread context — see the cost table). Decision records ≤1 page plus the verbatim-candidates appendix. Every numeric constant in this file is a convention chosen to be countable, not a measured value — and this section deliberately does NOT restate them (the same rule the Operator spine follows, for the same reason: a stale copy here once contradicted the phase that owns the number). Each constant lives in exactly one phase; read it there; the countable costs logged per record are what could eventually justify moving them.

## After NO WINNER

Every NO WINNER exit hands the caller: the field (all candidates verbatim), the matrix as far as it got, the findings, and the specific rule that stopped the run. The underlying problem may still be stabilized with a minimal intervention explicitly labeled provisional and tracked as debt — the no-bandaid rule forbids silent bandaids, not declared stopgaps. The tournament may be re-entered exactly once, and only when the pack gains new evidence — which makes re-entry REACHABLE only from stops that name missing evidence (a Phase 5 test failure, a route-2 detection failure, mid-implementation infeasibility, a fidelity mismatch) and UNREACHABLE by design from stops that name none (the two-strike termination, a second-collapse STOP, any PARTIAL EXECUTION terminal): those end the run, full stop, and this sentence is where that is stated rather than discovered. "New evidence" means a reproduction, a measurement, or a user decision — specifically the thing the stopping rule named as missing.

## When NOT to run this

- **Active incident with live user impact**: stabilize first with the smallest safe intervention, labeled as temporary; tournament the durable fix immediately after, with the incident as Phase 0 evidence. A tournament during the fire is process harming users.
- **The user already decided**: implementing a named choice is not a competition. Note disagreement once if warranted, then build.
- **Trivially reversible changes** (undoable in under a minute, no data touched): just fix it.
- **Anything below the fixed-load floor** — and this OUTRANKS the proactive bandaid triggers: a 20-line special case for a reported input fires the trigger and clears the floor, and the floor wins. Run the tournament on a small bandaid only when a prior fix for the same symptom already failed, which is the trigger the floor does not override: compare against the MARGINAL cost, not the total. The token floor is not the only floor: a lightweight run also costs roughly TWO DOZEN distinct artifacts (pack, tags, hashes, candidates, premortems, matrix, sweeps, ledgers, record), and for a bug whose entire fix plus test is smaller than that artifact list — a five-line change with an existing failing test — the artifact count is the wrong trade even when the line/file floor is technically cleared: fix it and say why. By the time you are reading this rule the load (~27–39k lightweight) is already spent and is not recoverable by declining; what remains is ~5–10k for lightweight or ~40–80k for full, which also reads references/full-mode.md (size per the Cost table — not restated here), plus the interaction sum for the selected mode (see Cost honesty — not restated here). Judging against 20k overstates the cost of proceeding by 2–4x and declines tournaments that clear the real bar — the mirror of the stale-word-count bias named above, and the more common of the two, since it applies on every invocation rather than only after this file changes. If the fix itself is smaller than that — countable version: one or two files touched, under ~100 changed lines, a test already exists or is trivial to add, and no failed prior attempt — wall-clock is the unit this file rejects everywhere else, so do not use it here either — the tournament costs more than the mistake it prevents. Just fix it and say why the tournament was skipped. Attention is the scarcer resource: a tournament that interrupts the user twice to settle a ten-minute change has already lost.
- **Special cases that are the correct domain model**: a distinct code path for a genuinely distinct case (leap years, admin users, the empty cart) is design, not bandaging. The bandaid trigger means special-casing a REPORTED FAILING INPUT to dodge its root cause, not modeling real domain structure.
- **Directional or go/no-go decisions**: that is `council`, not a tournament.

- **Full**: main-thread context stays near the lightweight figure (summaries, matrices, decisions only), but the subagents' own context is the real bill and it scales with the pack: every one of up to 18 calls (the ceiling — the estimate is computed against it) carries the full frozen pack, so total ≈ 18 × (pack + candidates + premortems).
