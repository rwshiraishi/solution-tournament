# Solution Tournament

Generate → score → crossbreed → implement. The goal is a production-grade solution, not the first plausible one.

**Honestly:** one agent authors every artifact here, so no internal check can catch a favorite smuggled through framing. This is a discipline that raises the cost of choosing thoughtlessly, not an audit, and its output is not objective. This section describes; it binds nothing — rules live in their phases.

**Nine bias channels, none fully mitigated:**

| # | Channel | Partial counter |
|---|---|---|
| 1 | FRAMING QUALITY — the same agent writes every candidate's pitch | cross-advocacy pass; verbatim field shown to the user |
| 2 | SELF-SCORING — author grades own work | independent scorer subagents (full mode only) |
| 3 | PACK ERROR — a wrong pack fact yields a fully cited, confidently wrong winner | MEASURED/ESTIMATED tags; red-team pack interrogation |
| 4 | STRIKE AUTHORITY — main agent rules which citations are fake | STRUCK-cell visibility in the matrix |
| 5 | CORRELATED SCORER ERROR — same-model scorers wrong in the same direction: zero spread, no flag, decorated wrong matrix | NONE internally. Wider than scoring: the skeptic (who removes candidates) and red-team (whose FATAL overturns) are single agents with zero redundancy — more authority, less oversight, accepted in writing because duplicating them doubles cost while sharing priors. Only spikes and the user's read are external |
| 6 | SPIKE CONSTRUCTION AND REPORTING — the builder chooses how hard to try, AND transcribes the result the judge sees; spikes outrank the matrix | criteria written for both before either is built; red-team audits construction; raw command + verbatim output in the record |
| 7 | MODE SELECTION — lightweight disables more safeguards in one self-assessed sentence than most channels combined | mode verdict artifact (Calibration) |
| 8 | FIELD CEILING — nothing here can see a better approach that was never generated | the field-ceiling question, asked in both modes (full: red-team with fresh eyes, can reopen Phase 1; lightweight: self-administered, labeled) |
| 9 | PACKET INTEGRITY — subagents are ASKED not to use tools and to reason only from the pack; nothing sandboxes them. A scorer reasoning from outside knowledge while citing genuine pack lines is undetectable | citation striking catches fabricated citations only; red-team Part 0 asks whether any scoring rationale references material absent from the pack |

DISPUTED detects divergence, never shared error: a zero-spread cell is uncontradicted, not corroborated.

**Definitions used throughout:**

- **User present**: an interactive session where a question can reach the user (e.g. AskUserQuestion). UNANSWERED is mechanical, not felt, and it comes in two scopes that must not be confused: ROW-LOCAL (an ambiguous or partial reply, or a decline of THIS question → take that row's autonomous branch, labeled "user unreachable in practice", and the run CONTINUES — one mushy answer never terminates anything) versus RUN-LOCAL (the session ends, the question channel tool-errors, or the user explicitly declines further questions → the user is gone; re-evaluate the pre-flight abort). A single ambiguous answer is never RUN-LOCAL. Anything short of these events means the run WAITS; hesitation is not absence. Anything else is autonomous. Two kinds of run carry the top-line statement "every safeguard in this run was self-administered": every autonomous run, and EVERY lightweight run regardless of user presence — lightweight self-scores, self-skeptics, and self-red-teams, so a clean decisive lightweight output otherwise reads as corroborated when one agent authored all of it.
- **Autonomous STOP fallback**: STOP means write the field and findings into the decision record with NO WINNER and do not implement. One row per branch, no exceptions hidden in prose. **Where this table, a template, or a checklist disagrees with a phase's prose, the PHASE governs and the mismatch is reported as a bug in this file** — the table is a convenience index, not a second rulebook:

| Branch | User present | Autonomous |
|---|---|---|
| Second collapse (removal of a regenerated slot) | show both fields, user decides | STOP |
| Both-wipeout by disqualification (2nd time) | NO WINNER, unconditionally — show field + rule | NO WINNER |
| Every dimension majority-OPINION | NO WINNER this round — reopen the pack if the single reopen counter is unspent, otherwise end — the counter decides, not a choice (Phase 2.9; the pack cannot support scoring, so there is nothing for a user to decide) | same |
| Any majority-OPINION dimension | FULL mode with user assent: redistribute per Phase 2.9. Otherwise (lightweight, user declines, or a second dimension after one redistribution): the dimension keeps full weight and the round is a close pair labeled "majority-OPINION at decisive weight" | STOP at weight ≥ 0.25 (threshold lives in Phase 2.9); below that, close pair — NO WINNER in autonomous full mode, and per the lightweight close-call rule otherwise |
| Every finalist fatally flawed | show findings, user decides | STOP |
| Fatal-flaw claim without a citation | CONCERN, not FATAL: it kills nothing and the result proceeds unchanged (a winner stands; a close pair goes to its terminal rule), concern shown | same — proceed with the concern recorded |
| Unopposed sole survivor | ≥ 5.0: user confirms. Below 5.0: NO WINNER regardless of user presence (Phase 1.5) | STOP |
| Full-mode close pair red-team + spikes cannot separate | user picks | STOP |
| Lightweight close call | user picks | re-run one MEASURED fact on the CONTESTED DIMENSION (largest absolute weighted gap between the finalists, ties to higher weight), then decide on self-authored findings + reversibility, label "unreviewed" — EXCEPT an evidence-floor failure, a zero-MEASURED pack, a failed responsiveness test, a majority-OPINION dimension at weight ≥ 0.25, or a BROKEN REMOVAL PREMISE, each of which is NO WINNER |
| Autonomous lightweight on a problem carrying ANY full-mode trigger (architecture, data-integrity, high blast radius, failed prior fix) | n/a — a user is present, so full mode was available | ABORTED PRE-FLIGHT: emit the mode verdict, the triggers, and the declination. No field is generated, so there is no matrix to report — see Calibration's pre-flight abort, which fires before Phase 1. The forced downgrade puts the highest-stakes problems in the weakest configuration; every other high-stakes autonomous branch ends in NO WINNER, and so does this one |
| Near-miss within its band of an effective gate (0.3 on 0–10 quantities, 0.2 on NOISE, 1 on integer counters) | surface, user may override | threshold decides, label "unreviewed" |
| Plateau-uninformative / unusable NOISE / no carried anchor / broken removal premise | — | NOT a stop: routes to Phase 4 as a close pair, where the close-pair row above governs |

- **BINDING vs DISCIPLINE**: BINDING = violation is visible in the output to a reader who has this file (absence of a required artifact is only detectable by someone who knows it was required). BINDING comes in two grades, and unless a use says otherwise it means the weaker one: PRESENCE (the artifact exists and can be seen missing — most uses) versus CONTENT-VERIFIABLE (a reader can check the artifact is TRUE, e.g. recomputing totals from printed cells, diffing pre/post-check totals, re-running a pasted command). A self-printed artifact's presence is checkable; its truth usually is not, and the labels must not blur that. DISCIPLINE = honest effort, unverifiable. Anything unlabeled is DISCIPLINE. Never present a DISCIPLINE step as a guarantee.

## Calibration: pick the mode first

- **Lightweight** (contained bug, single file, reversible): n=3, one round, no subagents, unblinded self-scoring with an anti-favorite pass — never called blind. Its removals receive NO audit: audit duty is full-mode, so no MECHANICAL demotion path exists in lightweight — self-authored removals stand unless step 11's falsification catches them, and that is the whole protection. Because it never crossbreeds, NO NOISE sample is ever available in this mode: its 1.0 decisive gate is an uncalibrated convention applied to self-produced scores, and a margin between 1.0 and 1.3 is a near-miss under the Phase 3 band. Everything else applies.
- **Full** (architecture, cross-cutting, high blast radius, failed prior fix, data-integrity): n=5, subagent scoring, up to 3 rounds.
- **Lightweight is the default.** Full mode needs an explicit trigger. **Mode verdict artifact** (BINDING): the output lists every full-mode trigger — architecture / cross-cutting change / high blast radius / failed prior fix / data-integrity stakes / user request — with a present-or-absent verdict and one line of evidence each, so a reader can contest the classification against the pack. It also states whether a user is reachable; when no user is reachable, the mode DROPS to lightweight — a rule, not a suggestion — unless the user pre-authorized autonomous full mode in text quoted into the artifact. A disjunction the agent resolves for itself is not a safeguard, and autonomous full mode ends in NO WINNER on most branches, so choosing it unprompted is choosing to spend up to 17 calls on a matrix and no decision. When genuinely unsure, ask — one sentence. **Pre-flight abort** (BINDING), evaluated at Phase 0 AND re-evaluated the moment a user becomes RUN-LOCAL unreachable mid-run (before the next subagent call in full mode; at each phase boundary in lightweight, which has no calls to anchor to — a full-mode run that loses its user is heading for a rule-determined NO WINNER, and the remaining calls buy nothing): if the mode verdict records a DOWNGRADE to lightweight (no reachable user, no quoted pre-authorization) AND any full-mode trigger is present, the run is a guaranteed STOP by rule, so do not generate at all. A PRE-AUTHORIZED autonomous full run is NOT aborted — it is not a guaranteed STOP, since a decisive margin still carries a winner to Phase 4 and implementation; it proceeds, and ends in NO WINNER only on the branches already listed. Emit the mode verdict, the triggers, and "tournament declined: this configuration terminates in STOP by rule", then take the minimal provisional intervention under After NO WINNER. Aborting saves the MARGINAL spend only — the ~5–10k run plus its generation and scoring — because the load is already read by the time this rule fires; that is the same sunk-cost reasoning the skip floor uses, applied to this file's own accounting. Spending even that marginal cost to arrive at a predetermined dead end is the calibration failure this file names everywhere else.
- **The user can always stop it.** "Just patch it" is an instruction, not a debate opening: record the field so far, comply, label what the tournament had and had not established. Every anti-exit rule binds the AGENT only.
- **Downgrade when the problem deflates; never self-exit once the field exists.** In Phase 0, a trivial problem means exit and just fix it, noting why. From Phase 1 on, exit is not the agent's call: scoring the field is cheap, and "this deflated" is indistinguishable from "my favorite is the obvious one." Downgrading full → lightweight after Phase 1 is constrained the same way exit is: it must be announced with its reason, it PRESERVES every independent artifact already earned (returned subagent scores stay in the matrix; an already-run skeptic's verdicts stand), and the close-pair route still goes to the user when present — a downgrade forfeits future independence, never past independence.

## Phase 0: Evidence and rubric BEFORE candidates

Order is mandatory: pack → rubric → checkpoint → generation. Criteria or evidence chosen after seeing candidates become rationalizations for a favorite.

1. **Pack first** (BINDING): problem statement, the code and interfaces it touches, scale numbers, deadlines, constraints.
   - Every non-quote fact is tagged MEASURED (naming its command, file, or trace) or ESTIMATED (DISCIPLINE — the tag is self-assigned, and naming a command is not running it; a fact mislabeled MEASURED can promote a CONCERN to a FATAL); a score or FATAL resting solely on an ESTIMATED fact says so in the matrix. The red-team must challenge at least one MEASURED tag or state that every one names a re-runnable command, and must report explicitly when the pack contains ZERO MEASURED facts. **Evidence floor** (BINDING), with each gate bound to the evidence that actually bears on it:
- A **decisive gate** requires at least one MEASURED fact on its DECIDING DIMENSION — the dimension whose SIGNED weighted contribution to the leader's margin is largest (computed as weight × (leader's score − runner-up's score), never (weight × leader) − runner-up); dimensions where the leader scores lower are ineligible, so the floor can never be satisfied by evidence that argues against the winner. If two contribute equally, both need a fact. At least ONE of those MEASURED facts must be RE-RUN IN SESSION before the gate fires — and the command run must be THE ONE THE TAG NAMED, not a substitute the agent prefers (the same agent chose the fact and would choose the command, and a near-tautological stand-in passes any gate); a named command that no longer exists or cannot run demotes the fact to ESTIMATED and the gate does not fire — the tag is self-assigned and "naming a command is not running it", so a decisive gate resting only on labels is a gate resting on the agent's own bookkeeping. Run it and paste the command and verbatim output in the record — same caveat spikes carry: the main agent chooses which fact to re-run and transcribes the result, so this is grounded in what was executed and single-authored in what is reported. And the run can DISAGREE — that is the point of running it: if the output contradicts the pack's MEASURED claim, the fact is demoted to ESTIMATED, pack-v2 is emitted with the diff, the gate does not fire, and the round is a close pair (NO WINNER autonomously); output that is AMBIGUOUS — neither cleanly confirming nor refuting — is treated as CONTRADICTS for gate purposes, since the adjudicator authored both the claim and the command. A gate that only recognizes confirming output is a label with extra steps. A re-run CARRIES across rounds within one tournament while the deciding dimension is unchanged; a round whose deciding dimension differs needs its own re-run, because the old evidence bears on the old margin. If nothing on the deciding dimension can be re-run, the gate does not fire: the round is a close pair, NO WINNER autonomously — the same shape the zero-MEASURED pack and the failed responsiveness test already take. An agent-judged "impossible" that still fires the gate would be the label-not-a-gate failure this file names two paragraphs above. Failing the floor entirely, the round is a close pair labeled "no MEASURED fact on the deciding dimension" — and in an AUTONOMOUS run of EITHER mode it is NO WINNER, not a close pair the agent then resolves on its own findings. Same reasoning as the zero-MEASURED pack and the failed responsiveness test: a label is not a gate, and the three branches share one failure shape, so they share one outcome. In an AUTONOMOUS run, a pack with zero MEASURED facts anywhere routes to NO WINNER outright, never to a labeled close pair that lightweight then resolves on self-authored findings — every other zero-evidence branch ends in NO WINNER, and a label is not a gate.
- A **FATAL** requires a MEASURED fact on the dimension THE FLAW ATTACKS, not on the margin's deciding dimension — a data-loss kill needs data-loss evidence, and a maintainability measurement licenses nothing about data loss. Failing that it is a CONCERN.
- The **sole-survivor 5.0 floor** is a decisive gate with no second candidate: its deciding dimension is the highest-weighted dimension scoring below 5; when the survivor scores ≥5 everywhere, it is simply the highest-weighted dimension — the floor is never inapplicable, because an unopposed winner on an all-guesses pack is exactly the case it exists to catch. The citation apparatus otherwise runs perfectly on the agent's own guesses and produces a fully cited winner grounded in nothing.
   - Write the pack to a file and print its SHA-256 BEFORE the first candidate appears (no filesystem → print the pack verbatim in the output and hash that text, saying so — the Phase 5 record's fallback); the decision record carries the pack verbatim so any reader can recompute. This detects an INCONSISTENT record, not a dishonest author — an agent that swaps the pack and reprints the hash produces a flawless single-authored document. The hash binds the record together; it does not certify the process.
   - The pack is frozen at the checkpoint. FULL mode: subagents may request late facts under the versioning protocol in `references/full-mode.md` (FACT REQUEST lines, pack-v2/v3 with printed hashes, capped re-spawns). LIGHTWEIGHT: no subagents exist to request anything — the pack the checkpoint froze is the pack, and discovering it is inadequate mid-run is a Phase 0 reopen or NO WINNER, never a quiet edit.
2. Restate the problem in one paragraph, including how the current approach fails.
3. **Pre-register the expected winner** (DISCIPLINE — recorded, but self-reported and unverifiable): one sentence — "before generating, I expect some form of X to win." Recorded in the output and decision record; excluded from every SCORER and SKEPTIC prompt, but SUPPLIED to the red-team packet ONLY when a crossbreed round ran — the MATCH/NO-MATCH audit is the sole reason the red-team needs the prior, and on a non-crossbreed run the packet line reads "pre-registration withheld: no MATCH/NO-MATCH call to audit", so the only verdict that can overturn the matrix stays prior-blind whenever knowing the prior buys nothing. When supplied, the leakage cost is booked: those finalist verdicts are not prior-blind, accepted because auditing the anti-favorite seed requires knowing the favorite. Its value: the agent must articulate its prior, and the user can compare it against the framing in the verbatim field. A match with the winner is uninformative alone (the prior is misreportable), so no scrutiny asymmetry attaches.
4. Define 4–6 scoring dimensions. Defaults (adjust per problem): root-cause resolution 30%, robustness/production-readiness 25%, maintainability/simplicity 20%, performance/cost 15%, implementation risk/reversibility 10%. Weights always sum to 1.0; after any user reweighting, normalize back to 1.0 and show the normalized weights — every threshold in this file assumes that normalization.
5. **Rubric checkpoint** (BINDING when a user is present): show the user the dimensions and ask them to rank or reweight — an approval of pre-filled weights is consent to defaults, not an expression of values, and the output must say which it got ("weights: user-edited" vs "weights: defaults, user-approved" vs "weights: defaults, autonomous run"). Skipping the checkpoint requires pre-authorization that names tournaments specifically, quoted in the output — ambient autonomy settings do not qualify. Weights freeze for the whole tournament; mid-tournament changes happen only at the user's initiative, and then both the before and after matrices are shown.
6. **Disqualification rule** (artifact BINDING; uniformity DISCIPLINE — the per-candidate results are visible, identical application is not falsifiable from the output):
   - Name the symptom as a falsifiable test: "this candidate leaves <observable root cause> in place; check: <what to look at>". Apply it to every candidate and show each result.
   - **VERIFIED diagnosis** (reproduction, trace, log, or measurement in the pack — cite it): a candidate that leaves the root cause fully in place is REMOVED from the field before ranking, n shrinks. Never scored 0.
   - **PARTIAL verdict** (the candidate fixes the mechanism but leaves a named residual path): NOT removed. It takes the HYPOTHESIS cap on the root-cause dimension and the residual path is named in its matrix row. Ambiguous cases resolve to PARTIAL by rule, never by judgment — removal happens before scoring and is unrecoverable within the round, and Phase 2.11 cannot falsify it.
   - **HYPOTHESIS diagnosis**: the rule removes no one. The candidate's root-cause dimension score is CAPPED AT 4 (if the rubric has no root-cause dimension, Phase 0 names which dimension inherits the cap). The cap is applied by the MAIN agent to returned scores — never in the scorer prompt, where naming the suspect would anchor its other dimensions — flagged in the matrix with the hypothesis and the scorer's original value. Ranks on the capped dimension are VOID: that dimension contributes no rank to the tiebreaker, which renormalizes over the rest, so a capped candidate never wins a tie on a rank the cap was meant to neutralize. With two scorers the cap applies to EACH RAW SCORE before the mean is taken (3 and 8 become 3 and 4, mean 3.5 — not a 4.0 cap on the mean), because the cap states what each judge's read of that candidate may be worth, not what their average may be; both originals are shown.
   - Removed candidates appear in the final matrix as REMOVED rows with the test, the cited evidence, and the VERIFIED/HYPOTHESIS call; their full text goes to the red-team packet so the removal is audited by someone other than its author (FULL mode; lightweight has no other author — there, step 11's falsification and the user's objection route are the whole protection, and this sentence promises nothing more).
   - **Precedence when the combined removal pass lands** (identical wording in Phase 1.5): ZERO survivors takes the Phase 0 reopen branch and never the regenerate branch — the diagnosis or rubric is wrong, so reopen Phase 0 once, and a second wipeout ends the tournament with the field, the rule, and NO WINNER. The regenerate and sole-survivor rules apply only when at least one candidate survives.
   - Timing: three ordered steps at the Phase 1.5 boundary — (a) apply the DQ test to all candidates and record verdicts; (b) run the batched skeptic on the full field, removed text included for context; (c) count DQ removals and filler verdicts together and take the removal branch.
7. Read prior decision records: `docs/decisions/NNNN-*.md` via the `docs/decisions/INDEX.md` one-line-per-record index (skip with a note when there is no repo). Records are dated claims: before carrying a rejection forward, verify its blocker still exists.

## Phase 1: Divergent generation (n candidates)

- Each candidate differs from every other on a **named structural axis** (architecture, data model, dependency, algorithm class, where-the-logic-lives). Slot #1 is the obvious approach, named as such. At least one candidate is a credible long shot — the test: could it plausibly win one rubric dimension outright? A field of paraphrases is a failed generation: regenerate once; if the problem genuinely has fewer than n distinct axes, run with what exists (minimum 2) and say so.
- Per candidate: mechanism, what it assumes, what breaks it — **90–150 words each** (countable, checkable; "equal length" is not). **Candidate hashes** (RECORD-BINDING — binds the record to itself, not the author; see the caveat below): when the field is frozen at the end of Phase 1.5 (post-revision, post-removal), print each surviving candidate's mechanism-text SHA-256 next to its label. The same hashes appear in the scorer packet, in the verbatim field shown to the user, and in the decision record. Same caveat as the pack hash, and it matters more here: this detects transcription drift between the shown and recorded text, NOT a dishonest author — one agent prints both the text and its hash, and no reader ever sees the packet a subagent actually received, so a substituted candidate with a re-printed hash is undetectable. Framing quality is the highest-bandwidth bias channel, the user is its only real detector, and this mechanism helps the user hold one version of the text rather than proving anything.
- **Cross-advocacy pass** (DISCIPLINE, full mode only — lightweight skips it, since its unblinded scorer sees the generation reasoning regardless): after drafting all candidates, rewrite each one's mechanism as its strongest advocate would write it, and state in the output that this pass ran. Framing quality is the highest-bandwidth bias channel and no downstream mechanism can detect it; this is the honest-effort counter.
- "What breaks it" names a rung on a fixed severity ladder — data loss / correctness / performance / effort — so severity is comparable across candidates rather than rhetorical.

## Phase 1.5: Skeptic pass (before scoring)

- **Incomplete skeptic return** (full mode only — LIGHTWEIGHT has no subagent and no return, so this rule lapses there exactly as Phase 2's return gate does): a short or malformed return gets ONE re-spawn (drawn from the shared completeness pool in Cost honesty); a second short return means its candidates carry "no premortem — ungraded risk" in the matrix and the round is demoted to a close pair.
- **One batched skeptic call** (fresh subagent in full mode — see `templates/skeptic.md`; in lightweight mode, write all critiques and premortems before assigning any score — ordering discipline, not independence): attacks ALL candidates in one pass and authors, for each, critique → revision guidance → premortem. The skeptic, not the generator, writes every premortem, in one call, holding severity comparable across candidates: each premortem (≤80 words) names its failure class from the severity ladder plus a likelihood and a detection point ("would surface at integration"), so scorers grade the risk, not the vividness of the story.
- **Filler verdict** (BINDING): a candidate with no plausible path to winning ANY dimension is DROPPED before scoring.
  - The verdict text appears in the final matrix as a DROPPED row: a culled field must be visible, never silent. In lightweight mode every DROPPED and REMOVED row also carries "self-authored removal" — the skeptic there is the generator wearing a different hat.
  - Removal precedence (DQ removals and filler verdicts count together as one number): ZERO survivors takes the Phase 0 reopen branch and never the regenerate branch (Phase 0.6); the rules here apply only when at least one candidate survives. Then FIRST the failed-generation rule — more than one removal in the combined pass means regenerate the culled slots once, and regenerated slots get the DQ test plus an **abbreviated skeptic pass** — defined once, here: critique + premortem + filler verdict for the new candidates only, no revision round, no re-critique of surviving candidates. Phase 3's crossbreed offspring use this same definition. A second collapse — ANY removal of a regenerated slot, either type — means stop and show the user both fields with the verdicts.
  - Only past that rule does the sole-survivor rule apply — and it is reached by one field shape only: a two-candidate field (Phase 1 found fewer than n real axes, or a prior round reduced it) losing exactly one candidate, since more than one removal triggers regeneration and any removal of a regenerated slot stops the run. Kept because that shape is legal and its outcome must be defined, not because it is common: a lone survivor is still SCORED solo against the rubric (scoring one candidate is nearly free and produces the matrix). It proceeds to Phase 4 only at a weighted total ≥ 5.0, carries the line "sole survivor — ran unopposed", and a present user confirms it as a decision. Below 5.0, or in any autonomous run, an unopposed survivor is NO WINNER: report the field, do not implement.
- **Revision**: each survivor gets one strengthening pass that may not change its named axis. Whether a proposed fix crosses the axis is the skeptic's call, made in the batched call with the axis named — not the generator's call afterward.
- **Show the user the field** (BINDING when a user is present): at the end of Phase 1.5, output the candidates' mechanism texts and premortems verbatim (not summaries), each with its SHA-256 as printed at freeze. Framing bias is visible to a human reading the raw text and invisible to every mechanism inside the skill. **Objection branch** (BINDING when a user is present): showing the field is pointless without a route to act on it. A stated objection to a candidate's framing ("C is described unfairly", "you buried B's real strength") forces ONE rewrite of that candidate's mechanism text with its named axis unchanged, a re-freeze with new hashes, and a printed FRAMING OBJECTION row naming the objection and what changed. One objection per candidate; the rewrite may strengthen, never re-scope. **Field-mutation rule, stated once for every route**: ANY candidate whose text changes or that enters the field after the freeze — an objection rewrite, a user re-admission, a regenerated slot, a crossbreed offspring — takes the DQ test and the abbreviated skeptic pass (critique + premortem + filler verdict) before scoring, and is re-frozen with a new hash. A mutated candidate scored against a stale premortem is scored on inputs the field was not, which is this file's own definition of a silent wrong answer. One abbreviated skeptic slot is RESERVED for exactly this route (see the call budget: the ceiling is 17, not 16, for this reason), so exercising the user's objection or re-admission — the file's most emphasized exogenous check — never demotes the round as a budgeting side effect; a safeguard that costs the user their decisive result is a safeguard with a disincentive built in. In LIGHTWEIGHT — which has no call ledger to denominate this in — the budget is counted directly: TWO post-freeze mutations per run, self-administered and labeled; the third demotes the round to a close pair, so the anti-mutation backstop exists in the mode where self-authorship is total. In FULL mode, only when the reserved slot is ALREADY spent (a second mutation in one run) does the fallback fire: the candidate scores carrying "no premortem — ungraded risk" and the round demotes to a close pair, matching the incomplete-return consequence. Re-admission may push the scored field above the mode's n — permitted, scored as-is, and noted in the matrix ("field: n+1 after re-admission"); a larger field costs scoring effort, never validity. Re-admission does NOT recompute the removal-count branch — that branch was decided on the field as culled, and re-admission is a user override of one verdict, not a re-run of the pass. The same route covers REMOVALS: a user who contests a REMOVED or DROPPED row re-admits that candidate into scoring (labeled "re-admitted by user objection"; a HYPOTHESIS-grade DQ concern travels with it as the cap) — the user can end the whole tournament, so a fortiori they outrank a single skeptic verdict, and the only exogenous check must be able to reach the most consequential act, not just the prose around it. In autonomous runs the verbatim field goes in the decision record instead, and the output records that no objection route ran — the only real detector of the highest-bandwidth bias channel was absent.

## Phase 2: Adversarial scoring (independent only in full mode)

Not "blind": label-shuffling removes authorship and ordering effects, but nothing hides which candidate is the conventional one, and scorers share the generator's model priors — their agreement is consensus, not evidence. The mechanisms below raise the cost of vibes; they do not turn scores into measurements.

**Scoring procedure — run in this order.**

0. **Return gate** — three sub-steps, in order:
   - **(a) Completeness**: every label sent was scored and every required field is present.
   - **(b) Responsiveness**: each scored dimension quotes a candidate-specific locator — a mechanism element, assumption, or premortem clause unique to THAT candidate, such that the sentence would be false pasted under another candidate's row. The locator is quoted in the matrix so a reader can apply the paste test; the agent's own application of it is DISCIPLINE. It detects generic text reused across rows; it cannot detect a candidate-specific quote attached to a generic judgment, which is the subtler hollow shape — so it raises the floor rather than closing the failure.
   - **(c) Recompute and correct**: recompute every weighted total from the returned cells before any gate reads one — this is the single number every branch depends on and it arrives from a subagent. A discrepancy > 0.05 means the recomputation stands and prints as an ARITHMETIC CORRECTION row; a discrepancy on either of the top two rows — the top two of the CORRECTED ordering, since the recomputation stands — demotes the round to a close pair.
   - Failures: a short or malformed return gets ONE re-spawn (see the reservation rule in Cost honesty); a second short return is "incomplete scoring" → close pair. A failed locator test → close pair labeled "unresponsive scoring" — and in an AUTONOMOUS LIGHTWEIGHT run that close pair is NOT resolvable by the same agent on its own findings (that would make the test a label and nothing else, in the configuration where it matters most): the run ends NO WINNER — matching its three sibling zero-evidence branches; a disjunction the agent resolves for itself is not a safeguard, so there is no second option.
   - **Mode note**: LIGHTWEIGHT has no return, so (a) and the ARITHMETIC CORRECTION row and "incomplete scoring" lapse — but the DEMOTION does not — and to keep it from penalizing disclosure (a silent fix is invisible, so a rule that punishes reporting selects for hiding), lightweight prints BOTH the pre-check and post-check totals for every row so a reader can diff them. A discrepancy on either of the top two rows still makes the round a close pair. (b) and (c) still bind — a self-scorer writes generic rationale as easily as a subagent, and the responsiveness test binds HARDEST where author and scorer are the same agent.

1. **Scale**: 0–10 per dimension (2 = serious deficiency, 5 = adequate with real concerns, 8 = strong with minor concerns). **Weighted total = Σ(weight × score)**, weights summing to 1.0, so totals and margins live on the 0–10 scale.
2. **Margin, defined once**: the difference between the TOP TWO weighted totals in whatever comparison the current gate names — decisive gates use the round's best two; the plateau gate uses best offspring vs the carried anchor. The **carried anchors** are the two parents that entered the current round; the plateau comparison uses whichever scores higher in the CURRENT round (both totals shown). Next-round succession is a separate end-of-round computation in Phase 3.
3. **Who scores**: full mode spawns a scoring subagent (`templates/scorer.md`) receiving ONLY the frozen pack plus candidates and premortems under neutral labels. Two scorers whenever ANY full-mode trigger was architecture, data-integrity, or a failed prior fix; one otherwise. What the second same-model scorer buys, plainly: DISPUTED divergence and STRUCK-cell recovery — real but narrow, since correlated error passes both. When the choice is a second scorer or a spike, note: no live choice exists between a second scorer and a spike — the scorer is mandated when triggered and unavailable otherwise — so no preference rule applies. Lightweight mode self-scores unblinded, says so in the output, and follows the same numbered procedure as a scorer subagent — including the forced 1..n ranking, which the tiebreaker in step 10 needs and which matters MORE here (n=3 self-scoring is exactly where 7–8 clustering happens) — writing the strongest case AGAINST each candidate before assigning any number.
4. **Label order**: candidates are ordered by the frozen mechanism-text SHA-256s from Phase 1.5, which are also listed in the scorer packet so the scored text is bound to the shown text. DISCIPLINE: this removes incidental generation-order effects; it cannot resist deliberate authorship, since the agent writes the hashed text.
5. **Cite before scoring**: for each dimension, state which pack facts bear on it — the same fact set for all candidates — then score against them with quote + locator. A cherry-picked true fact still serves a prior, so this raises the cost of vibes; it does not make scores follow from evidence.
6. **Verify citations** (main agent, on return):
   - A citation absent from the pack STRIKES the cell. Struck cells are marked STRUCK in the matrix with the fabricated citation quoted, in both scorer modes — and in LIGHTWEIGHT the mark reads "STRUCK (self-verified against a self-authored pack)", since there the same agent wrote the pack, the citation, and the verdict on it.
   - Striking VOIDS that scorer's ranks on that dimension; the tiebreaker renormalizes over the remaining dimensions, exactly as the HYPOTHESIS cap does. A SELF-SCORED recovery does NOT restore the rank — the rank was formed on a value that no longer exists, and the replacement was authored by the main agent. **Floor**, mirroring the dimension-drop floor: if fewer than 2 dimensions retain live ranks, the tiebreaker is unavailable and the round is a close pair (user decides, or NO WINNER autonomously) rather than renormalizing over nothing. No tie is decided by a rank whose score no longer exists.
   - Recovery, in order — and ANY recovered value on a HYPOTHESIS-capped dimension re-applies the cap before entering the total, with both values printed (a replacement is not a returned score, but the cap binds the candidate, not the score's provenance): take the other scorer's value if one survives → else re-score (main agent, marked SELF-SCORED — in LIGHTWEIGHT it reads "SELF-SCORED (rewrite, not repair: same agent authored the pack, the citation, and the strike)") if re-score budget remains → else mark the cell UNSCORED and drop that dimension for EVERY candidate, renormalizing the rubric uniformly, then make the round a close pair. **Floor on dropping** — four ordered steps, mirroring the all-OPINION rule:
     1. Identify candidates with COMPLETE pre-drop rows. Fewer than two → close pair; the floor is not attempted.
     2. Compute the deciding dimension on the PRE-drop matrix over those candidates only (dropping renormalizes and would otherwise redefine the thing being protected; the candidate that triggered the drop has an UNSCORED cell and no total to rank).
     3. Block the drop if it would leave fewer than 3 surviving dimensions, or would remove that deciding dimension.
     4. When blocked: the round is a close pair, no further dimension may be dropped, and that candidate's weighted total prints as INCOMPUTABLE — never an imputed number, since an invented value is exactly the silent wrong answer this file forbids. A candidate with an INCOMPUTABLE total is NOT eligible for top-two selection by total — there is no number to rank it with, and inventing one is the failure this rule exists to prevent. If that leaves fewer than two eligible candidates, the round is NO WINNER autonomously, or goes to the user with the full matrix when one is present. Ordering among an eligible close pair falls to the tiebreaker over surviving dimensions; if that cannot separate them either, the choice goes to the user, or NO WINNER autonomously. (The floor makes zero surviving dimensions unreachable, since Phase 0 mandates 4–6 and dropping stops at 3.) A tournament deciding on one surviving dimension while printing a full matrix is this file's own definition of a silent wrong answer. Never renormalize one candidate alone: redistributing its weakest dimension's weight onto its strengths inflates its total against rivals scored on the full rubric, and totals feed the top-two selection, the tiebreak band, and the plateau comparison as if they were commensurable. A voided score never silently reverts to the struck value.
7. **Combine scorers**:
   - The cell shows BOTH raw scores and their mean; the mean enters the total. Spread ≥ 3 points flags DISPUTED.
   - **Re-score budget**: 2 main-agent re-scores per tournament, shared across both paths (struck-cell recovery and DISPUTED). A Phase 0 reopen restarts the call budget but NOT this one — the re-score path is how independent scoring reverts to self-scoring, and a reopen is not a reason to double the self-scored cell count. The matrix prints the count of main-agent-scored cells — the channel through which independent scoring reverts to self-scoring must be visible.
   - **Precedence**: a cell that is both struck and DISPUTED resolves striking first, then re-examines for DISPUTED only if two values still exist.
   - **DISPUTED consequence** (when the disagreement could move a gate — weight × spread ≥ 0.9; not 1.0, because the default top weight is 0.30 and 0.30 × the minimum flagging spread of 3 = 0.9, so a 1.0 trigger would be inert in the default configuration): one re-score against the pack, which REPLACES the cell rather than averaging into it. "Surviving spread" is measured between the re-score and the FARTHER original: still ≥ 3 → the cell takes the lower of the two originals and the round becomes a close pair regardless of margin; under 3 → the re-score stands alone and the round proceeds.
   - Below that trigger, DISPUTED is disclosure only. Derivation: max spread on a 0–10 scale is 10, so the trigger is unreachable exactly on dimensions weighted under 0.09. Past the budget, qualifying cells take the lower value directly.
   - Rank inversions between scorers are surfaced as disagreement, never smoothed.
8. **OPINION**: a score with no citable fact is OPINION at full weight; a cell counts as OPINION only if both scorers marked it — a deliberate unanimity gate in the two-scorer tier, because one grounded citation IS evidence for the cell and a split verdict should not weaken a dimension the way a unanimous one does; the cost, stated plainly, is that the redistribution lever and the ≥0.25 stop demand unanimity exactly in the highest-stakes tier, and a split cell prints "OPINION (1 of 2)" so the partial doubt is visible even though it does not count. With a SINGLE scorer (lightweight, or the one-scorer full tier), that scorer's mark alone makes the cell OPINION, so the safeguard never silently switches off in the most common configuration. Declining to cite is a weight lever, so a majority-OPINION dimension is a FINDING in the matrix, never a silent mechanic.
9. **Redistribution** — applying to any majority-OPINION dimension, with a hard autonomous stop at weight ≥ 0.25 (stated here in the prose, not only in the branch table, so the precedence rule can see it); one of exactly THREE exceptions to the Phase 0 weight freeze — the others being a user-initiated mid-tournament reweight (Phase 0.5) and the UNSCORED dimension-drop (Phase 2.6), which is permitted even in lightweight and autonomous runs because it removes a dimension uniformly for every candidate rather than selectively reweighting toward one. All three make NOISE unusable for the following round under the "weights changed" clause: a majority-OPINION dimension's weight may be redistributed proportionally (renormalize to 1.0) ONLY with the user's explicit assent, forbidden in lightweight and autonomous runs — where it is unavailable, the dimension keeps full weight and the round is a close pair labeled "majority-OPINION at decisive weight", stated here rather than left to inference — and forbidden past ONE dimension per tournament. Once applied it persists for all remaining rounds so cross-round comparisons stay under one weight set; both weight sets appear in the record. If EVERY dimension is majority-OPINION, the pack cannot support scoring: NO WINNER this round — reopen the pack if the single reopen counter is unspent, otherwise end. Not a choice: the counter decides.
10. **Ties**: when totals land within 0.3 points, the tiebreaker is **weighted mean rank** = Σ(weight × rank), lower wins (with two scorers, the mean of their weighted mean ranks). Forced ranking (1..n, no ties) exists to break 7–8 clustering; ranks never enter the total. A surviving tie routes like any close margin in the current mode.
11. **Falsify the removals** (after scores exist) — five sub-rules, each with its consequence stated once:
    a. **Domination-argument filler verdicts**: fail if the named dominator was scored and did not win that dimension. A failed argument is a BROKEN REMOVAL PREMISE (see e).
    b. **Cited-fact filler verdicts**: must have pre-committed, at removal time, a SURVIVING candidate's row and the score range the fact's implication ENTAILS there — and the range must EXCLUDE at least half the 0–10 scale and name the matrix result that would falsify it, by rule rather than judgment: the removal's author also authors the range, and a wide-enough range is a test by nothing. A range failing the width rule makes the verdict UNFALSIFIABLE (existing close-pair consequence). The verdict fails if the matrix lands outside the committed range. No pre-commitment → UNFALSIFIABLE (see d). Post-hoc contradiction-checking by the verdict's own author is not a test.
    c. **DQ removals**: UNFALSIFIABLE BY DEFAULT (a removed candidate has no matrix row) — and in AUTONOMOUS LIGHTWEIGHT, where step 11 is the only protection on the most consequential act, an un-pre-committed DQ removal is NO WINNER outright rather than a self-resolved close pair: the removing agent does not also get to be the only check on the removal — unless the removal pre-committed a surviving candidate's row and entailed range (Phase 0.6); those are checked as in (b).
    d. **UNFALSIFIABLE** (any route, including a named target later dropped or lost in regeneration): the removal stands, but the round routes to a close pair — the same consequence on every removal path, so the same event never resolves differently by path.
    e. **BROKEN REMOVAL PREMISE**: the removal stands (re-scoring mid-stream would unfreeze the field), but the round demotes to a close pair, the dropped candidate's verbatim text goes to the user or the record with the finding, and no decisive result may be claimed on a field culled on a false premise.

Bands: 0.3 on any 0–10 scale quantity (decisive margin, plateau delta, the 5.0 sole-survivor floor, the 3-point DISPUTED spread, the 0.3 tiebreak band itself, weight×spread 0.9), 0.2 on NOISE (including the 1.5 ceiling), and one unit on any integer counter (removals, rounds, attempts, re-spawns). Two classes exist and dimension-bearing near-misses outrank dimensionless ones at ANY proximity (a margin near a gate deserves the user's attention before a counter sitting on its threshold, which is common and low-information): first all dimension-bearing near-misses ordered by PROXIMITY then higher weight (quantities carrying no single dimension weight — the decisive margin, the 5.0 floor — skip the weight key and fall through to phase order), then dimensionless ones (NOISE, the 1.5 ceiling, integer counters) ordered by PROXIMITY, and any remaining tie breaks by phase order, earliest first. The ORDERING of identified near-misses is fully determined — two agents holding the same identified set surface the same two. Which quantities get identified as near-misses at all is DISCIPLINE: it depends on the agent checking each threshold, and no mechanism verifies the sweep was complete. The two surfaced are therefore derivable and contestable rather than chosen; the rest are recorded and threshold-decided with the "unreviewed" label — an unbounded interruption count is not a budget, and the published interaction ranges assume this cap. Surfacing is identical in wording whichever side the favorite is on, with the agent's own preference stated separately so the user can discount it; autonomously, record the near-miss with both sides flagged, take the threshold's outcome, and label it "decided by threshold, unreviewed". Near the line, judgment decides, not arithmetic.

## Operator spine (traversal order; every rule lives in the section pointed to)

No thresholds are restated here — a stale copy once contradicted the rules it summarized. The order decision points arrive, each with its governing section: 1. ## Output format

Every tournament ends with: the rubric (weights + provenance), pre-registration vs. outcome, the per-round matrix (all candidates, DROPPED and REMOVED rows included, OPINION flags and any weight redistribution visible), the decision trail, red-team findings with audit marks, then the implementation. Never present only the winner.

Final self-check (DISCIPLINE — self-administered and labeled as such): reread the artifacts once for box-filling. For EVERY finalist that reached Phase 4 — symmetric, so repair cannot ratchet the winner's record above the field's — a mechanical premortem, an uncited score, or an empty red-team pass is redone AND logged: a "repairs applied" line in the matrix lists each redone artifact, whose it was, and why (correction and disclosure are not in tension; a repaired record with no repair log is the process's own silent-failure channel). For candidates eliminated before Phase 4, disclosure alone suffices. An output with no weakness labels has not been vetted; it has been self-reviewed, which catches obvious lapses and not systematic ones.

## Cost honesty

In full mode, deliberation stays in subagents; only summaries, matrices, and decisions return to the main thread (lightweight mode has no subagents and pays its cost in main-thread context — see the cost table). Decision records ≤1 page plus the verbatim-candidates appendix. Every numeric constant in this file is a convention chosen to be countable, not a measured value — and this section deliberately does NOT restate them (the same rule the Operator spine follows, for the same reason: a stale copy here once contradicted the phase that owns the number). Each constant lives in exactly one phase; read it there are conventions chosen to be countable, not measured constants; the countable costs logged per record are what could eventually justify moving them.

## After NO WINNER

Every NO WINNER exit hands the caller: the field (all candidates verbatim), the matrix as far as it got, the findings, and the specific rule that stopped the run. The underlying problem may still be stabilized with a minimal intervention explicitly labeled provisional and tracked as debt — the no-bandaid rule forbids silent bandaids, not declared stopgaps. The tournament may be re-entered exactly once, and only when the pack gains new evidence (a reproduction, a measurement, a user decision) that the stopping rule named as missing.

## When NOT to run this

- **Active incident with live user impact**: stabilize first with the smallest safe intervention, labeled as temporary; tournament the durable fix immediately after, with the incident as Phase 0 evidence. A tournament during the fire is process harming users.
- **The user already decided**: implementing a named choice is not a competition. Note disagreement once if warranted, then build.
- **Trivially reversible changes** (undoable in under a minute, no data touched): just fix it.
- **Anything below the fixed-load floor** — and this OUTRANKS the proactive bandaid triggers: a 20-line special case for a reported input fires the trigger and clears the floor, and the floor wins. Run the tournament on a small bandaid only when a prior fix for the same symptom already failed, which is the trigger the floor does not override: compare against the MARGINAL cost, not the total. By the time you are reading this rule the load (~19–26k lightweight) is already spent and is not recoverable by declining; what remains is ~5–10k for lightweight or ~40–80k for full, which also reads references/full-mode.md (~4–6k), plus 2–6 interruptions. Judging against 20k overstates the cost of proceeding by 2–3x and declines tournaments that clear the real bar — the mirror of the stale-word-count bias named above, and the more common of the two, since it applies on every invocation rather than only after this file changes. If the fix itself is smaller than that — countable version: one or two files touched, under ~100 changed lines, a test already exists or is trivial to add, and no failed prior attempt — wall-clock is the unit this file rejects everywhere else, so do not use it here either — the tournament costs more than the mistake it prevents. Just fix it and say why the tournament was skipped. Attention is the scarcer resource: a tournament that interrupts the user twice to settle a ten-minute change has already lost.
- **Special cases that are the correct domain model**: a distinct code path for a genuinely distinct case (leap years, admin users, the empty cart) is design, not bandaging. The bandaid trigger means special-casing a REPORTED FAILING INPUT to dodge its root cause, not modeling real domain structure.
- **Directional or go/no-go decisions**: that is `council`, not a tournament.

**Cost to expect** (countable units; every number here is a convention, not a measurement). The fixed load, measured post-split (`wc -c`/`wc -w`, 2026-08-08; recount on every material edit — every previous estimate erred optimistic): LIGHTWEIGHT loads this file only, 11.9k words / 74k chars ≈ 19–26k tokens at 2.8–4.0 chars/token (markdown tables and symbols tokenize denser than prose; plan on the top of the band). FULL additionally reads `references/full-mode.md` (2.7k words ≈ 4–6k tokens) and the templates at spawn time. The split exists so the default mode stops paying for machinery it never executes, before a single candidate exists — the largest single line item for lightweight — and note what that means: roughly 66–84% of a lightweight tournament's token cost is the fixed load (19/(19+10) to 26/(26+5); computed from 19–26k against a 5–10k run — compute it from the current figures, do not trust this parenthetical to stay fresh), and that load includes shared core, not only full-mode machinery. That is a design defect with a known remedy (split this file so lightweight loads a short core and full mode is a linked extension, then recount the skip floor against the smaller load), not a law of nature. It is recorded here rather than fixed because the split is a large refactor and this file's own history shows large refactors introduce more defects than they remove; do it deliberately, not incidentally. And name the fidelity risk, not just the price: an agent that cannot hold this file's NINE counters — reopen (1), re-entry (1), re-scores (2), completeness slots (2), fact requests (2), read-only verifications (2), red-team calls (2), spike attempts (2 per spike), scoring rounds (3) — and its ordered gates WILL drop steps. Instantiate the COUNTERS ledger at Phase 0 as one printed line and update it IN PLACE at every spend — maintained state, not output-time reconstruction, because a ledger rebuilt from memory at the end is exactly where a forgotten spend hides. A reader sees a missing counter either way. A **GATE-ORDER ledger** sits beside it: one printed line per ordered sequence (Phase 2 steps 0a–c, 6, 7, 9, 10, 11 · the removal timing a–c · the drop-floor 1–4 · full-mode gate rules when loaded), ticked in place as each step executes, and the FINAL ledger line prints each counter's spends annotated with the phase and rule that spent them — so a reader can diff spends against the artifacts those rules produce, one content-verifiable property on an otherwise self-attested tally, and dropped steps are invisible. **Degraded-execution branch**, with a trigger that is computable once a mismatch is PRINTED — the sweep that prints it is DISCIPLINE, so this narrows the judgment, it does not remove it: it fires on TWO STRIKES in one run — a strike being a LATE REPAIR, an OUT-OF-ORDER tick, or an ABSENT tick on the GATE-ORDER ledger (the ledger prints each ordered step's tick in sequence, so a reader can diff the printed order against the mandated one without trusting the agent's sweep) — a LATE REPAIR being a box produced only at the phase-exit check rather than in flow, printed as "repaired late: <box>" on that phase's checklist line. This event survives the checklist stop (which repairs or terminates each individual mismatch): a repaired run continues, but two late repairs mean the agent is producing artifacts by checklist-prompt rather than by executing the rules that generate them — the losing-the-thread signature. An unrepairable box still terminates immediately under After NO WINNER, as the checklist rule says. A run that trips the two-strike count TERMINATES where it stands — no restart, no re-derivation, no continuing under a lighter ruleset: emit whatever artifacts already exist, label the output "PARTIAL EXECUTION: full ruleset not held", and take the close-pair-to-user terminal (NO WINNER autonomously). A trip at Phase 4 does not un-run Phases 0–3; it stops the run from claiming their conclusions. A labeled partial beats an unlabeled "complete" with silently dropped rules. The user's attention is the least-budgeted resource here: lightweight asks for 2–5 interactions — and note that an un-pre-committed DQ removal routes UNFALSIFIABLE to a close pair, so the close-pair-to-user interaction is the EXPECTED case in most lightweight runs that remove anyone, not the tail (rubric checkpoint, verbatim field, a close-pair or sole-survivor decision when one arises, and up to ONE batched near-miss question (two near-misses share it: one interruption, not two) — the arithmetic, not an assurance), full mode 3–8 — universal near-miss surfacing means several thresholds can trip in one run, and each trip is an interruption. If that count feels high for the problem, the mode choice is wrong. Every one is a real interruption; the terminal safeguard is a person:

- **Lightweight**: 0 subagent calls, but ALL deliberation lands in the main thread. Countable artifacts: 3 candidates × (90–150w mechanism + assumptions + breaks) + 3 critiques + 3 premortems (≤80w) + ~5 dimensions × 3 cited scores + matrix + red-team questions ≈ 2,000–3,500 words of output, so roughly 5–10k tokens of context including the reasoning around it (ESTIMATED — derived from the word bands above, not measured). Refusing to guess would be honest; refusing to bound is not useful. To keep it honest, lightweight skips the cross-advocacy pass (its scorer sees the generation reasoning anyway) and NEVER spikes: a symmetric spike comparison costs two builds, and a problem worth two builds has left the "contained and reversible" class. A lightweight close pair resolves per Phase 3's LIGHTWEIGHT row — deliberately not restated here, because a paraphrase of that row once dropped its re-run obligation.
- **Full**: main-thread context stays near the lightweight figure (summaries, matrices, decisions only), but the subagents' own context is the real bill and it scales with the pack: every one of up to 17 calls (the ceiling — the estimate is computed against it) carries the full frozen pack, so total ≈ 17 × (pack + candidates + premortems). Keep the pack under ~1,500 words for that reason — at that size full mode costs roughly 40–80k tokens across all calls (ESTIMATED, same derivation style as the rest). A pack twice that size doubles the tournament. 4 subagent calls on the common path (skeptic + scorer + red-team, +1 scorer at the two-scorer tier); 6–8 when a crossbreed round runs. Derived from the branch structure, not surveyed — no usage data exists yet.
- **Hard maximum 17 calls**: 1 skeptic + 1 regeneration skeptic + up to 2 abbreviated crossbreed skeptics + up to 6 scorers (2 × 3 rounds) + 1 abbreviated skeptic RESERVED for post-freeze field mutations (objection rewrites, user re-admissions) + 2 red-team + up to 2 fact-request re-spawns (further requests declined and noted) + up to 2 completeness-gate re-spawns, allocated by RESERVATION rather than priority, because claims arrive in phase order and a priority list cannot reach backward in time: the 2 COMPLETENESS slots are the pool in question: 1 is held for the red-team until Phase 4's return is complete, and the skeptic and scorers share the other 1 — and note the timing consequence plainly: the skeptic returns first, so after any skeptic re-spawn the shared slot is SPENT and a later malformed scorer return takes its partial outcome immediately. That is the expected case, not an anomaly; the pool is thin by design, because re-spawns are the channel through which a flaky subagent quietly consumes the budget. (The 2 red-team calls and 2 fact-request re-spawns are separate budgets and are not drawn from it.). With no slot available, a malformed return takes its named partial outcome immediately. DISPUTED and struck-cell re-scores are main-agent actions, not calls. Total: 1+1+2+1+6+2+2+2 = 17.

  Red-team call precedence, stated separately: one packet covers a close pair ("in parallel" means both finalists in one call). The second call has two possible claimants, and the RUNNER-UP path outranks a Part 0 escalation, because a standing FATAL means the winner is already disqualified. If the second call is spent when a runner-up check becomes mandatory, that check cannot run: close pair to the user, NO WINNER autonomously — never an unchecked promotion.
- **Two repetition counters**: Phase 0 REOPEN (one per tournament, shared across every reopen rule here — when a later rule wants a reopen the counter has already spent, it prints "reopen declined — counter spent by <rule>" in the matrix and the Phase 4 checklist, so a suppressed finding, especially an absent-approach one, is never silent) and After-NO-WINNER RE-ENTRY (one per problem). A reopen restarts the 17-call budget (34 for the tournament); a re-entered tournament may not reopen, so its ceiling is 17. Absolute worst case per problem: 34 + 17 = 51 calls. If that alarms you for this problem, it should — recalibrate the mode before starting, not mid-run.
- **Autonomous honesty**: autonomous full mode ends in NO WINNER on every close-pair, all-flawed, sole-survivor, and majority-OPINION branch — a large fraction of realistic runs — potentially spending the full budget to deliver a matrix and no implementation. That is the design, not a failure. When the user is unreachable, prefer lightweight or defer to a session where they are not.
