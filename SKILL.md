# Solution Tournament

A structured generate → score → crossbreed → implement pipeline. The goal is a production-grade solution, not the first plausible one.

**What this process is, honestly.** Every artifact here — candidates, critiques, premortems, the evidence pack, the subagent prompts — is authored by one agent, so no arrangement of internal checks can detect a favorite smuggled through framing quality. The tournament is a discipline that raises the cost of choosing thoughtlessly; it is not an audit, and its output is not objective. Four bias channels exist, none fully mitigated: FRAMING QUALITY (partial counter: cross-advocacy), SELF-SCORING (partial: independent scorers), PACK ERROR — a wrong or missing pack fact yields a fully cited, confidently wrong winner while every mechanism behaves correctly (partial: MEASURED/ESTIMATED tags, red-team pack interrogation) — STRIKE AUTHORITY, the main agent's power to rule citations fake (partial: STRUCK-cell visibility) — and CORRELATED SCORER ERROR, two same-model scorers confidently wrong in the same direction, which produces zero spread, no DISPUTED flag, and a fully decorated wrong matrix; NO internal mechanism counters it (spike results and the user's read of the verbatim field are the only external checks). DISPUTED detects divergence, never shared error: a zero-spread cell is uncontradicted, not corroborated. Sixth: SPIKE CONSTRUCTION — the main agent builds both spikes and chooses how hard to try, and spike results outrank the matrix, so this channel has the highest authority-to-oversight ratio (partial counter: criteria and budgets written for both finalists before either is built, and the red-team marks each spike's construction SUBSTANTIVE or MECHANICAL under its audit duty). Seventh, and largest: MODE SELECTION — choosing lightweight disables more safeguards in one self-assessed sentence than every other channel combined (partial counter: the mode verdict artifact in Calibration). The agent also pre-registers its expected winner in Phase 0, putting its prior on the record before the field exists.

**Definitions used throughout:**

- **User present**: an interactive session where a question can reach the user (e.g. AskUserQuestion). Anything else is autonomous, and an autonomous run's output must say that every safeguard in it was self-administered.
- **Autonomous STOP fallback**: any branch that says "stop and show the user" becomes, when autonomous, STOP — write the field and findings into the decision record with NO WINNER and do not implement. It covers exactly: second collapse, double disqualification wipeout, all-OPINION scoring, any majority-OPINION dimension carrying weight ≥ 0.25 (the weight lever at its most powerful — autonomously, stop rather than proceed on it), every finalist fatally flawed, uncited fatal-flaw claims, an unopposed sole survivor, and the full-mode close pair that red-teams and spikes cannot separate. Three deliberate non-STOP exceptions, each labeled in its own rule: the lightweight close call (decided on self-authored red-team findings plus reversibility, labeled unreviewed), near-miss gates (threshold decides, labeled unreviewed), and plateau-uninformative rounds (treated as close pairs).
- **BINDING vs DISCIPLINE**: BINDING = violation is visible in the output to a reader who has this file (absence of a required artifact is only detectable by someone who knows it was required). DISCIPLINE = honest effort, unverifiable. Anything unlabeled is DISCIPLINE. Never present a DISCIPLINE step as a guarantee.

## Calibration: pick the mode first

- **Lightweight mode** (contained bug, single-file change, reversible decision): n=3, one round, no subagents. Scoring is unblinded self-scoring with an anti-favorite pass — never call it blind. Everything else below still applies.
- **Full tournament** (architecture, cross-cutting change, high blast radius, previous fix failed, data-integrity stakes): n=5 default, subagent scoring, up to 3 rounds.
- **Lightweight is the default.** Full mode needs an explicit trigger. **Mode verdict artifact** (BINDING): the output lists every full-mode trigger — architecture / cross-cutting change / high blast radius / failed prior fix / data-integrity stakes / user request — with a present-or-absent verdict and one line of evidence each, so a reader can contest the classification against the pack. When genuinely unsure, ask — one sentence.
- **The user can always stop it.** A present user may end the tournament at any phase — "just patch it" is an instruction, not a debate opening. Record the field as far as it got, comply, and label the resulting fix with what the tournament had and had not yet established. Every anti-exit rule below binds the AGENT only.
- **Downgrade when the problem deflates; never self-exit after the field exists.** During Phase 0, if the problem turns out trivial, exit the tournament and just fix it, noting why. From Phase 1 onward, exiting is no longer the agent's call — the field exists and scoring it is cheap, and "this deflated" is indistinguishable from "my favorite is the obvious one." Downgrading full → lightweight after Phase 1 is constrained the same way exit is: it must be announced with its reason, it PRESERVES every independent artifact already earned (returned subagent scores stay in the matrix; an already-run skeptic's verdicts stand), and the close-pair route still goes to the user when present — a downgrade forfeits future independence, never past independence.

## Phase 0: Evidence and rubric BEFORE candidates

Order is mandatory: pack → rubric → checkpoint → generation. Criteria or evidence chosen after seeing candidates become rationalizations for a favorite.

1. **Assemble the context pack first** (BINDING): the problem statement, the code and interfaces the problem touches, scale numbers, deadlines, constraints. Every non-quote fact is tagged MEASURED (with the command, file, or trace it came from) or ESTIMATED — a score or FATAL verdict resting solely on an ESTIMATED fact is marked as such in the matrix. Write the pack to a single file and print its SHA-256 (`shasum -a 256 <file>`) into the output BEFORE the first candidate appears; the decision record includes the pack file's content verbatim as an appendix, so any reader can recompute the hash. Be precise about what this detects: an INCONSISTENT record, not a dishonest author — an agent that swaps the pack and reprints the new hash produces a flawless single-authored document. The hash binds the record together; it does not certify the process. Facts added later are allowed only when a subagent's OUTPUT requests one (subagents are single-shot and tool-less, so a request is a line in their report: "FACT REQUEST: ..."); the main agent emits pack-v2 (then v3) with a fresh printed hash and a one-line diff, logs requester and reason, and re-spawns the affected scorer once against the NAMED new version — at most 2 re-spawns per tournament; beyond that, requests are declined and noted in the matrix. Every pack version and hash appears in the record's appendix, every subagent prompt names the version it received, and the matrix states which version each scoring round used — an unversioned pack edit is the one way to break the only reader-verifiable artifact, so there is no such thing as an unversioned pack edit.
2. Restate the problem in one paragraph, including how the current approach fails.
3. **Pre-register the expected winner** (DISCIPLINE — recorded, but self-reported and unverifiable): one sentence — "before generating, I expect some form of X to win." Recorded in the output and decision record; excluded from every subagent prompt. Its value is that the agent must articulate its prior and the user can compare it against the framing they see in the verbatim field; a match between pre-registration and winner is uninformative on its own (an agent could misreport its prior), so no scrutiny asymmetry attaches to it.
4. Define 4–6 scoring dimensions. Defaults (adjust per problem): root-cause resolution 30%, robustness/production-readiness 25%, maintainability/simplicity 20%, performance/cost 15%, implementation risk/reversibility 10%. Weights always sum to 1.0; after any user reweighting, normalize back to 1.0 and show the normalized weights — every threshold in this file assumes that normalization.
5. **Rubric checkpoint** (BINDING when a user is present): show the user the dimensions and ask them to rank or reweight — an approval of pre-filled weights is consent to defaults, not an expression of values, and the output must say which it got ("weights: user-edited" vs "weights: defaults, user-approved" vs "weights: defaults, autonomous run"). Skipping the checkpoint requires pre-authorization that names tournaments specifically, quoted in the output — ambient autonomy settings do not qualify. Weights freeze for the whole tournament; mid-tournament changes happen only at the user's initiative, and then both the before and after matrices are shown.
6. **Disqualification rule** (artifact BINDING, uniformity DISCIPLINE — the per-candidate test results below are visible; that they were applied identically is not falsifiable from the output): name the symptom as a falsifiable test ("this candidate leaves <observable root cause> in place; check: <what to look at>") and apply it to every candidate identically, shown per candidate in the output. Timing — three ordered steps at the Phase 1.5 boundary: (1) main agent applies the DQ test to all candidates and records verdicts; (2) the batched skeptic runs on the full field, removed text included for context; (3) DQ removals and filler verdicts are counted together and the removal branch (regenerate / sole survivor / stop) is taken. Removed text also goes to the red-team packet for audit. A candidate failing it is REMOVED from the field before ranking (n shrinks) — never scored 0. If the diagnosis is VERIFIED (reproduction, trace, log, or measurement in the pack — cite it), removal is final. If it is a HYPOTHESIS, the rule cannot remove anyone: the affected candidate's score is CAPPED AT 4 on the root-cause dimension — and if the rubric has no root-cause dimension, Phase 0 names which dimension inherits the cap when defining the rubric. The cap is applied by the MAIN agent to the returned scores — never written into the scorer prompt, where naming the suspect candidate would anchor its other dimensions and undo the label-scrubbing — and the capped cell is flagged in the matrix with the hypothesis restated beside it and the scorer's original value shown. Removed candidates appear in the final matrix as REMOVED rows carrying the falsifiable test, the cited evidence, and the VERIFIED/HYPOTHESIS call, and their full text goes into the red-team packet so the removal is audited by something other than its author. If removals leave exactly one candidate, the sole-survivor rule (Phase 1.5) applies — scored solo, "ran unopposed", user confirms when present, autonomous = NO WINNER. If the rule removes every candidate, the diagnosis or the rubric is wrong: stop and reopen Phase 0 — at most once; a second wipeout ends the tournament with the field, the rule, and NO WINNER in the record.
7. Read prior decision records: `docs/decisions/NNNN-*.md` via the `docs/decisions/INDEX.md` one-line-per-record index (skip with a note when there is no repo). Records are dated claims: before carrying a rejection forward, verify its blocker still exists.

## Phase 1: Divergent generation (n candidates)

- Each candidate differs from every other on a **named structural axis** (architecture, data model, dependency, algorithm class, where-the-logic-lives). Slot #1 is the obvious approach, named as such. At least one candidate is a credible long shot — the test: could it plausibly win one rubric dimension outright? A field of paraphrases is a failed generation: regenerate once; if the problem genuinely has fewer than n distinct axes, run with what exists (minimum 2) and say so.
- Per candidate: mechanism, what it assumes, what breaks it — **90–150 words each** (countable, checkable; "equal length" is not).
- **Cross-advocacy pass** (DISCIPLINE, full mode only — lightweight skips it, since its unblinded scorer sees the generation reasoning regardless): after drafting all candidates, rewrite each one's mechanism as its strongest advocate would write it, and state in the output that this pass ran. Framing quality is the highest-bandwidth bias channel and no downstream mechanism can detect it; this is the honest-effort counter.
- "What breaks it" names a rung on a fixed severity ladder — data loss / correctness / performance / effort — so severity is comparable across candidates rather than rhetorical.

## Phase 1.5: Skeptic pass (before scoring)

- **One batched skeptic call** (fresh subagent in full mode — see `templates/skeptic.md`; in lightweight mode, write all critiques and premortems before assigning any score — ordering discipline, not independence): attacks ALL candidates in one pass and authors, for each, critique → revision guidance → premortem. The skeptic, not the generator, writes every premortem, in one call, holding severity comparable across candidates: each premortem (≤80 words) names its failure class from the severity ladder plus a likelihood and a detection point ("would surface at integration"), so scorers grade the risk, not the vividness of the story.
- **Filler verdict** (BINDING): a candidate with no plausible path to winning any dimension is DROPPED before scoring, with the verdict text shown in the final matrix as a DROPPED row — a culled field must be visible, never silent. In lightweight mode every DROPPED and REMOVED row additionally carries "self-authored removal", because the skeptic there is the generator wearing a different hat. Precedence when removals land (DQ removals and filler verdicts count together as one number): FIRST the failed-generation rule — more than one removal in the combined pass means regenerate the culled slots once; regenerated slots get the DQ test and an abbreviated skeptic pass (critique + premortem + filler verdict) before scoring. A second collapse — ANY removal of a regenerated slot, either type — means stop and show the user both fields with the verdicts. ONLY on a field past the failed-generation rule (at most one verdict issued, or post-regeneration) does the sole-survivor rule apply — and a sole survivor is still SCORED solo against the rubric (scoring one candidate is nearly free and produces the matrix): it proceeds to Phase 4 only if its weighted total is ≥ 5.0, carries the line "sole survivor — ran unopposed", and is presented to a present user as a decision to confirm. Below 5.0, or in any autonomous run, an unopposed survivor is a NO WINNER outcome: report the field, do not implement.
- **Revision**: each survivor gets one strengthening pass that may not change its named axis. Whether a proposed fix crosses the axis is the skeptic's call, made in the batched call with the axis named — not the generator's call afterward.
- **Show the user the field** (BINDING when a user is present): at the end of Phase 1.5, output the candidates' mechanism texts and premortems verbatim (not summaries). Framing bias is visible to a human reading the raw text and invisible to every mechanism inside the skill. In autonomous runs, the verbatim field goes in the decision record instead.

## Phase 2: Independent adversarial scoring

Not "blind": label-shuffling removes authorship and ordering effects, but nothing hides which candidate is the conventional one, and scorers share the generator's model priors — their agreement is consensus, not evidence. The mechanisms below raise the cost of vibes; they do not turn scores into measurements.

- **Scale and formula** (BINDING): scores are 0–10 per dimension (anchors: 2 = serious deficiency, 5 = adequate with real concerns, 8 = strong with minor concerns). **Weighted total = Σ(weight × score)** with weights summing to 1.0, so totals and all margins live on the 0–10 scale. Forced ranking (1..n, no ties) within each dimension is a calibration device against 7–8 clustering; ranks never enter the total. **Margin, defined once**: the difference between the TOP TWO weighted totals in whatever comparison the current gate names — for decisive gates, the round's best two candidates; for the plateau gate, best offspring vs the carried anchor; the near-miss rule applies to each gate's own quantity. The **carried anchors** are the two parents that entered the current round; the plateau comparison uses whichever of them scores higher in the CURRENT round (they may swap; both totals are shown). Next-round anchor succession is a separate end-of-round computation defined in Phase 3. When totals land within 0.3 points, the tiebreaker is the **weighted mean rank** = Σ(weight × rank), lower wins; if that also ties, a true tie follows the same route as any close margin in the current mode (full: crossbreed; lightweight: close pair to Phase 4).
- **Full mode**: a scoring subagent (see `templates/scorer.md`) receives ONLY the frozen context pack plus the candidates and premortems under neutral labels, ordered by SHA-256 of each mechanism text, computed by the main agent via `shasum -a 256` before spawning the scorer (DISCIPLINE: this removes incidental generation-order effects; it cannot resist deliberate authorship, since the agent writes the hashed text). Two scorers whenever ANY full-mode trigger was architecture, data-integrity, or a failed prior fix; one scorer otherwise. What the second same-model scorer buys, stated plainly: DISPUTED divergence detection and STRUCK-cell recovery — real but narrow, since correlated error passes both. It is kept because it costs one call at the highest-stakes tier; when the choice is between a second scorer and a spike, prefer the spike, which is the only externally grounded artifact in the process; the matrix cell shows BOTH raw scores and their mean (the mean enters the total); a cell where the scorers differ by ≥ 3 points is flagged DISPUTED. DISPUTED has a consequence when the disagreement could move a gate — weight × spread ≥ 1.0 forces one re-score against the pack, and a surviving spread puts the LOWER value in the total and makes the round a close pair regardless of margin; below that trigger DISPUTED is disclosure only, and says so (derivation: max spread on a 0–10 scale is 10, so the trigger is unreachable exactly on dimensions weighted under 0.10); a cell counts as OPINION only when BOTH scorers marked it (one grounded citation covers the cell); the tiebreaker uses the mean of the two scorers' weighted mean ranks; any rank inversion between scorers is surfaced as disagreement — never smoothed. (Median is meaningless below three scorers; use it only at n≥3.) OPINION redistribution is computed per round, and plateau comparisons are valid because the carried anchor is re-scored inside the new round under the same scorer and weights.
- **Fact citation** (DISCIPLINE, with one binding edge): before assigning a dimension's scores, the scorer states which pack facts bear on that dimension — the same fact set for all candidates — then scores against them, citing quote + locator. A cherry-picked true fact can still serve a prior, so this does not guarantee scores follow from evidence; it makes pure vibes expensive. BINDING edge: a score citing a fact that is not actually in the pack is struck and re-scored. A score with no citable fact is marked OPINION at full weight. Name the incentive out loud: declining to cite is a weight lever, so a majority-OPINION dimension is a FINDING surfaced in the matrix, never a silent mechanic. Order of operations, owned by the MAIN agent when scoring returns, entirely inside Phase 2: verify citations — a fake citation strikes the cell, and EVERY struck cell is marked STRUCK in the matrix with the fabricated citation quoted, in both scorer modes; a struck cell takes the other scorer's value, and when no unstruck value exists (one scorer, or both struck) the main agent re-scores and the cell is marked SELF-SCORED — independence degrades visibly, never silently → average the two scorers per cell → a cell is OPINION only if both scorers marked it. Then the redistribution rule, the SOLE exception to the Phase 0 weight freeze: if more than half a dimension's cells are OPINION, redistribution of that dimension's weight (proportional, renormalized to 1.0) happens ONLY with the user's explicit assent at that moment — forbidden in lightweight mode and in autonomous runs (no exogenous check, no weight change), and forbidden past ONE dimension per tournament. Once applied it persists for all remaining rounds, so cross-round comparisons stay under one weight set; both weight sets appear in the record. If EVERY dimension is majority-OPINION, the pack cannot support scoring: NO WINNER from this round — reopen Phase 0's pack (once) or end with NO WINNER.
- **Lightweight mode**: unblinded self-scoring, and the output says so. For each candidate, write the strongest case AGAINST it before any number. Self-scored margins are less trustworthy than subagent-scored ones and nothing compensates for that — which is why the Phase 3 lightweight row sends every close call to the user.
- Show the full matrix — including DROPPED rows — never just the winner.

## Phase 3: Decision gate

Mode precedence table:
- FULL mode: every branch below.
- LIGHTWEIGHT row: never crossbreeds. Margin > 1.0 → winner alone to Phase 4. Margin ≤ 1.0 → both finalists to Phase 4, then the choice goes to the USER with the matrix and red-team findings whenever a user is present (self-scored close calls are exactly where self-scoring fails; do not resolve them alone). Autonomous: decide on red-team findings plus reversibility and label the result "close call, self-scored, unreviewed".

"Close pair" everywhere below and in Phase 4 means two finalists arriving together via any of: lightweight close, plateau, or exhausted rounds. The Phase 2 within-0.3 tiebreaker orders a close pair; it never substitutes for these routes.

- **Decisive**: margin > 1.0 weighted points → the winner alone proceeds to Phase 4.
- **Close** (≤ 1.0): crossbreed round — 3 scoring rounds maximum: the initial round plus up to 2 crossbreed rounds. Round pool = z offspring (default 3) + the top 2 parents, who re-race as anchors. Offspring pass an abbreviated Phase 1.5 (skeptic premortem; filler verdict applies) AND the DQ test before scoring; an offspring inheriting traits from a HYPOTHESIS-capped parent carries the same cap on the same dimension, shown in its row — crossbreeding is not a route for a disqualifying trait to re-enter untested. Each offspring names its inherited traits; one is a **mutation** (one assumption perturbed); and at least one offspring is seeded from the highest-ranked candidate that is NOT the pre-registered favorite, with the excluded mechanism named. The match call is written into the output as a MATCH/NO-MATCH line with one reason; on NO-MATCH, seed from the highest-ranked non-leader and name the leader's mechanism as the excluded one — the exclusion trace never disappears. The pre-registration sentence goes into the RED-TEAM packet (never the scorer packet), and the match call joins the red-team's audit duty, marked SUBSTANTIVE or MECHANICAL — the one self-refereed anti-favorite check moves off its own author without leaking the prior to scoring. Crossbreeding must not become laundering.
- After each crossbreed round, evaluate in this exact order — the FIRST matching rule wins:
  1. **Noise floor**: the CARRIED ANCHORS are the two parents that entered this round with unchanged text. Print each carried anchor's previous and current weighted totals side by side; NOISE = the largest absolute delta between them, in weighted-total points. NOISE needs two unchanged-text re-scores under UNCHANGED weights to be usable — a redistribution round produces no usable NOISE ("noise: weights changed, unusable" → fixed thresholds); with one sample, fixed thresholds and the label "noise: one sample, unusable"; with zero, the round cannot be decisive — close pair. If NOISE > 1.5, this round's scoring cannot support any gate: close pair, reason printed. Anchor movement also reflects the changed comparison field, so NOISE is an upper bound on scorer variance, not an estimate of it — conservative for the plateau gate, harsh for the decisive gate, and that asymmetry is accepted rather than hidden. Otherwise every gate below must clear its fixed threshold AND NOISE. Round 1 has no re-scores; its decisive gate rests on the fixed threshold alone — say so in the matrix.
  2. **Plateau test**: no offspring beat the higher-scoring CARRIED anchor (this round's totals) by more than max(0.5, NOISE) → stop; top two by current totals to Phase 4 together. Plateau outranks the decisive gate deliberately: an anchor that only widened its lead over weak offspring the same agent generated has been flattered, not tested.
  3. **Decisive gate**: margin > max(1.0, NOISE) → that round's winner alone to Phase 4.
  4. **Rounds exhausted** (after round 3): top two to Phase 4 together.
  5. Otherwise: next crossbreed round.
  After the branch is chosen (separately — succession is a computation, not a branch): the two highest-weighted-total candidates of this round, offspring included, become the next round's carried anchors.
- **Near-miss surfacing** (BINDING, symmetric): near-miss is measured against the EFFECTIVE threshold actually applied this round — max(1.0, NOISE) for decisive, max(0.5, NOISE) for plateau — and does not apply to the 0.3 tiebreaker, which is itself the tie rule. Whenever a margin lands within 0.3 points of an effective gate, surface it to the user with the matrix regardless of which side the favorite is on, in the same neutral wording, with the agent's own preference stated separately so the user can discount it. Autonomous: record the near-miss in the decision record with the margin and both sides flagged, take the gate's arithmetic outcome, and label it "near-miss, decided by threshold, unreviewed". The thresholds above are uncalibrated conventions, not truths; near the line, judgment decides, not arithmetic.

## Phase 4: Red-team, spikes, and audit

Routing: a decisive winner is red-teamed alone; a close pair (plateau or exhausted rounds) is red-teamed in parallel. Fresh subagent in full mode (`templates/red-team.md`); in lightweight mode the MAIN agent runs the red-team questions itself — SELF-ADMINISTERED, and any decision resting on those findings (including the autonomous lightweight close call) says the findings were self-authored.

- **Evidence bar for overturning** (BINDING): Phase 2 demands a cited fact to move a score; overturning the whole result demands no less. A fatal-flaw verdict must cite a pack fact or a spike result. A flaw asserted without one is presented to the user alongside both candidates — it does not transfer the crown on the agent's say-so. If a cited fatal flaw stands, the runner-up (already red-teamed if the race was close) is checked the same way; if every finalist is fatally flawed, stop and return the field with findings to the user.
- **Audit duty** (full mode): the red-team subagent also receives the premortems, score citations, and (if any) spike criteria, and marks each SUBSTANTIVE or MECHANICAL. Its marks go in the output. This moves the honesty check off the agent that produced the artifacts.
- **Spike gate** (close races on code problems): before building anything, write down for BOTH finalists — the assumption under test (from its premortem), the pass/fail criterion, and what production conditions the spike does NOT reproduce. Same criterion rigor for both, and the red-team's audit marks each spike's CONSTRUCTION (not just its result) SUBSTANTIVE or MECHANICAL — a spike can overrule the matrix on the specific assumption it tested (a cited standing FATAL is the only other matrix-overruling artifact), so its authorship gets the audit's closest look. Budget: 2 attempts and ≤150 changed lines per spike (countable — wall-clock is not); a spike that exhausts its budget is reported as "risk confirmed expensive to derisk," which is itself evidence. The MAIN agent builds both spikes (the red-team subagent judges results; it never builds). Build in the session scratchpad or a throwaway worktree; delete before Phase 5; never promote spike code. A spike result outranks judgment about the specific assumption it tested and nothing else. Declaring the problem non-spikeable requires naming what could not be built, in the output.
- Standing questions: What happens at 10x? In 6 months, context forgotten? Which single assumption, if false, kills it — and how would we detect that early? Is any part a bandaid wearing a suit (special cases, silenced warnings, magic constants, "temporary" flags)?
- **Close-pair terminal rule** (BINDING): when both finalists survive red-team and spikes do not discriminate (both pass, both fail, or no spikes ran), the tournament has separated all it can: the choice goes to the USER with both red-team reports, the spike criteria and results, and the final matrix. Autonomous: NO WINNER per the uniform fallback — a full-mode close pair is never resolved by the agent's unaided preference. A discriminating spike result or a standing FATAL selects the survivor.

## Phase 5: Implement to production standard

- Enter plan mode first if the change touches multiple files or systems; spikes must already be deleted. Production standard: tests covering the failure mode that motivated the tournament, error handling for the assumptions identified in Phase 1, no TODOs standing in for decisions.
- **Fidelity gate** (artifact BINDING, the assertion itself DISCIPLINE): before the decision record is finalized, restate the winner's named structural axis and mechanism against the NAMED diff hunks that realize it — file plus function per claim, so a reader can spot-check the mapping rather than trust a bare assertion. Building something other than the winner — most temptingly, quietly reverting to the obvious slot-#1 approach — is a re-entry condition, not a footnote. If the winner proves infeasible mid-implementation, that infeasibility is new pack evidence: stop, record it, and re-enter the tournament under the After NO WINNER rule with the runner-up's red-team findings already in hand.
- **Decision record** (BINDING): `docs/decisions/NNNN-<slug>.md` plus a one-line append to `docs/decisions/INDEX.md` (create both if absent; use the project's ADR home if one exists; with no repo, put the record's content in the session output and say there is nowhere durable to write it). Contents: problem, rubric with weights and their provenance (user-edited / defaults-approved / autonomous), pre-registered expectation vs. actual winner, full matrix per round including DROPPED rows, verbatim candidate texts (autonomous runs), red-team findings and audit marks, and the countable costs: candidates generated, subagent calls, rounds, spike attempts. Do not log token guesses as if measured — count what is countable.

## Phase exit checklists (co-authoritative with the prose)

Absence of a required artifact is invisible to a reader who does not know it was required — this list is what makes absence visible. A phase is not exited until its artifacts exist; a missing box is a violation even when every prose rule was "substantially followed". Where a checklist box and the prose conflict, the PROSE governs and the mismatch is reported as a bug in this file. Mode-dependent boxes bind only in the modes that produce them.

- **Exit Phase 0**: pack file + tagged facts + printed hash (v1) · problem restatement · pre-registration sentence · normalized weights + provenance line · DQ falsifiable test authored · decision-record index read (or no-repo note).
- **Exit Phase 1**: n candidates, each with named axis + 90–150w mechanism + assumptions + severity-rung breaks · obvious slot named · long-shot slot named · cross-advocacy statement (full mode).
- **Exit Phase 1.5**: per-candidate DQ verdicts · skeptic critiques + premortems (class/likelihood/detection) · filler verdicts with citations · removal count vs threshold branch taken · verbatim field shown (or in record).
- **Exit Phase 2**: matrix with both raw scores per cell (two-scorer runs; single-scorer and lightweight runs carry one score plus their self-scored labeling), ranks, citations or OPINION marks, STRUCK/SELF-SCORED/DISPUTED flags · weighted totals · pack version named per round.
- **Exit Phase 3**: branch taken named with its rule number · anchor totals + NOISE line (crossbreed rounds only; round 1 states "fixed threshold only") · MATCH/NO-MATCH seeding line (crossbreed rounds) · near-miss handling if within the band.
- **Exit Phase 4**: red-team report(s) with FATAL/CONCERN/FIXABLE classifications + citations · audit marks · spike criteria-before-results (if spiked) · close-pair terminal decision by user or NO WINNER.
- **Exit Phase 5**: tests for the motivating failure · fidelity gate mapping (axis → named diff hunks) · decision record + index line · repairs-applied line (or "none").

## The decision flow, in one place

Ordered conditionals an executing agent must hold; the phase prose and the checklists above are authoritative, this table is the map.

1. Phase 0: pack (tagged facts, file, hash printed) → problem → pre-registration → rubric (weights sum 1.0) → checkpoint → DQ rule authored → records read. Trivial problem discovered here → exit, just fix it.
2. Phase 1: generate n on named axes (regenerate once on paraphrase failure; fewer real axes → run with ≥2).
3. Phase 1.5 boundary, three steps: (a) DQ test all candidates; (b) batched skeptic (critiques, premortems, filler verdicts, axis adjudications); (c) count ALL removals together → more than one: regenerate once (regenerated slots: DQ + abbreviated skeptic; any further removal → STOP) → exactly one survivor: score solo, ≥5.0 and user confirms → Phase 4, else NO WINNER → otherwise show field verbatim, proceed.
4. Phase 2: score (0–10, cite-then-score, forced ranks) → verify citations (STRUCK/SELF-SCORED marks) → average scorers → OPINION marks → majority-OPINION dimension: user assents to redistribution or it stands as a finding; every dimension majority-OPINION → NO WINNER or one pack reopen.
5. Phase 3 — initial round: margin > max(1.0, NOISE where usable) → Phase 4 solo; else crossbreed (full) or Phase 4 pair (lightweight). Crossbreed rounds: apply Phase 3's numbered rules IN THE PROSE (noise floor first, then plateau, decisive, exhaustion) — this map deliberately does not restate the thresholds, because a stale copy here once contradicted them. Anchor succession is the end-of-round computation. Near an effective gate by < 0.3 → surface (user) or label unreviewed (autonomous).
6. Phase 4: red-team (evidence bar for FATAL; audit duty; pack interrogation) → close pair + code → spikes (pre-written criteria, 2 × ≤150 lines) → standing FATAL or discriminating spike selects → otherwise close pair goes to the user (autonomous: NO WINNER); all flawed → STOP.
7. Phase 5: plan mode → implement → fidelity gate (implementation realizes the winner's axis) → tests → decision record + index. Winner infeasible → record it, re-enter once.

## Output format

Every tournament ends with: the rubric (weights + provenance), pre-registration vs. outcome, the per-round matrix (all candidates, DROPPED rows included, OPINION flags and any weight redistribution visible), the decision trail, red-team findings with audit marks, then the implementation. Never present only the winner.

Final self-check (DISCIPLINE — self-administered and labeled as such): reread the artifacts once for box-filling. For EVERY finalist that reached Phase 4 — symmetric, so repair cannot ratchet the winner's record above the field's — a mechanical premortem, an uncited score, or an empty red-team pass is redone AND logged: a "repairs applied" line in the matrix lists each redone artifact, whose it was, and why (correction and disclosure are not in tension; a repaired record with no repair log is the process's own silent-failure channel). For candidates eliminated before Phase 4, disclosure alone suffices. An output with no weakness labels has not been vetted; it has been self-reviewed, which catches obvious lapses and not systematic ones.

## Cost honesty

In full mode, deliberation stays in subagents; only summaries, matrices, and decisions return to the main thread (lightweight mode has no subagents and pays its cost in main-thread context — see the cost table). Decision records ≤1 page plus the verbatim-candidates appendix. The constants in this file (1.0 decisive, 0.5 plateau, 0.3 near-miss, 3 rounds, 2 spike attempts, 150 spike lines, the cap of 4, z=3, 90–150 and ≤80 word bands, the 5.0 sole-survivor floor, the ≥3-point DISPUTED spread, the weight×spread ≥ 1.0 re-score trigger, the 1.5 NOISE ceiling) are conventions chosen to be countable, not measured constants; the countable costs logged per record are what could eventually justify moving them.

## After NO WINNER

Every NO WINNER exit hands the caller: the field (all candidates verbatim), the matrix as far as it got, the findings, and the specific rule that stopped the run. The underlying problem may still be stabilized with a minimal intervention explicitly labeled provisional and tracked as debt — the no-bandaid rule forbids silent bandaids, not declared stopgaps. The tournament may be re-entered exactly once, and only when the pack gains new evidence (a reproduction, a measurement, a user decision) that the stopping rule named as missing.

## When NOT to run this

- **Active incident with live user impact**: stabilize first with the smallest safe intervention, labeled as temporary; tournament the durable fix immediately after, with the incident as Phase 0 evidence. A tournament during the fire is process harming users.
- **The user already decided**: implementing a named choice is not a competition. Note disagreement once if warranted, then build.
- **Trivially reversible changes** (undoable in under a minute, no data touched): just fix it.
- **Special cases that are the correct domain model**: a distinct code path for a genuinely distinct case (leap years, admin users, the empty cart) is design, not bandaging. The bandaid trigger means special-casing a REPORTED FAILING INPUT to dodge its root cause, not modeling real domain structure.
- **Directional or go/no-go decisions**: that is `council`, not a tournament.

Cost to expect (countable units): lightweight = 0 subagent calls but ALL deliberation lands in the main thread — candidates, critiques, premortems, scoring — an unmeasured but real cost (countable in artifacts, not reliably in tokens); to keep that honest, lightweight SKIPS the cross-advocacy pass (its scorer sees the generation reasoning anyway). Worst case a lightweight close call still reaches Phase 4: a self-administered red-team of both finalists plus spikes — but lightweight has an abort the full mode does not: if a lightweight run reaches a SECOND spike attempt, stop, report the field, and take the smallest safe fix labeled provisional (the mode's entry condition was "contained and reversible"; a problem that eats two spike attempts has left that class, and the honest response is to stop calling it lightweight). Full: typically 4–8 subagent calls; hard maximum 14 (1 skeptic + 1 regeneration skeptic pass + up to 2 abbreviated skeptic calls in crossbreed rounds + up to 6 scorer calls at 2 scorers × 3 scoring rounds + 2 red-team + at most 2 fact-request re-spawns — further FACT REQUESTs are declined and noted), plus up to 2 spikes × 2 attempts. Two distinct counters bound repetition: the Phase 0 REOPEN (one per tournament, shared across every reopen rule in this file) and the After NO WINNER RE-ENTRY (one per problem). A reopen restarts the 14-call budget (28 for the tournament); a re-entered tournament may NOT reopen Phase 0, so its ceiling is 14, and the absolute worst case per problem is 28 + 14 = 42 subagent calls. If that number alarms you for the problem at hand, it should — recalibrate the mode. Main-thread cost is held to summaries and matrices. If that price is obviously wrong for the problem, the mode choice is wrong — recalibrate before starting, not mid-run.

## Related skills

- `council` — one-line test: if the deliverable is a chosen implementation, tournament; if it is a direction or go/no-go, council.
- `architecture-decision-records` — the Phase 5 record follows ADR conventions.
- `tech-stack-evaluator` — when candidates are technology choices rather than implementations.
- `verification-loop` — run after Phase 5 before calling the winner done.
- Cheaper neighbors: one artifact needing critique (not competing implementations) → a single adversarial review; a hard tradeoff with no buildable candidates → `hard-call`; testing an existing system's limits → stress testing. The tournament earns its cost only when genuinely different implementations must compete.
