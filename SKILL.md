# Solution Tournament

Generate → score → (full mode: crossbreed) → implement. The goal is a production-grade solution, not the first plausible one.

**Honestly:** one agent authors every artifact here, so no internal check can catch a favorite smuggled through framing. This is a discipline that raises the cost of choosing thoughtlessly, not an audit, and its output is not objective. This section describes; rules live in their phases.

**Single-author caveat (SAC)** — stated once, referenced everywhere as "(SAC)": every self-printed artifact — hashes, ledgers, ticks, tags, re-shown text, recomputed totals, self-administered checks and sweeps — detects an INCONSISTENT record, never a dishonest author. An agent that substitutes content and reprints the matching artifact produces a flawless single-authored document. These mechanisms bind the record to itself and give a reader holding this file something to recompute; they certify nothing about the process. "A reader can check" states an opportunity, not an event that happened.

**Nine bias channels, none fully mitigated:**

| # | Channel | Partial counter |
|---|---|---|
| 1 | FRAMING QUALITY — the same agent writes every candidate's pitch | cross-advocacy pass (full); verbatim field shown to the user — the user is this channel's only real detector |
| 2 | SELF-SCORING — author grades own work | independent scorer subagents (full mode only) |
| 3 | PACK ERROR — a wrong pack fact yields a cited, confidently wrong winner | MEASURED/ESTIMATED tags; red-team pack interrogation |
| 4 | STRIKE AUTHORITY — main agent rules which citations are fake | STRUCK-cell visibility in the matrix |
| 5 | CORRELATED SCORER ERROR — same-model scorers wrong in the same direction: zero spread, no flag | NONE internally. Wider than scoring: the skeptic and red-team are single agents with zero redundancy — accepted in writing because duplicating them doubles cost while sharing priors. Only spikes and the user's read are external |
| 6 | SPIKE CONSTRUCTION AND REPORTING — the builder chooses how hard to try AND transcribes the result; spikes outrank the matrix | criteria written for both before either is built; red-team audits construction; raw command + verbatim output in the record |
| 7 | MODE SELECTION — lightweight disables more safeguards in one self-assessed sentence than most channels combined | mode verdict artifact (Calibration) |
| 8 | FIELD CEILING — nothing here can see an approach never generated | the field-ceiling question, both modes |
| 9 | PACKET INTEGRITY — subagents are ASKED not to use tools; nothing sandboxes them | citation striking catches fabricated citations only; red-team Part 0 asks whether rationale references material absent from the pack |

DISPUTED detects divergence, never shared error: a zero-spread cell is uncontradicted, not corroborated.

**Definitions used throughout:**

- **User present**: an interactive session where a question can reach the user. **UNANSWERED** is mechanical, in two scopes: ROW-LOCAL (an ambiguous or partial reply, or a decline of THIS question → take that row's autonomous branch, labeled "user unreachable in practice"; the run CONTINUES) versus RUN-LOCAL (the session ends, the question channel tool-errors, or the user explicitly declines further questions → re-evaluate the pre-flight abort under Calibration's mid-run rule). A single ambiguous answer is never RUN-LOCAL; anything short of those events means the run WAITS — hesitation is not absence. **AUTONOMOUS** is the separate case where no question can reach the user at all; only RUN-LOCAL events convert a waiting run into an autonomous one.
- **Run-shape disclosure line**, printed at the terminal decision: attended FULL — no line (the baseline: subagent independence AND the user's checks). Attended LIGHTWEIGHT — "self-administered EXCEPT the user's checks" (the rubric checkpoint, objection branch, and decisive confirmation are exogenous). Autonomous LIGHTWEIGHT — "every safeguard in this run was self-administered" (the only shape carrying the unqualified line). Pre-authorized autonomous FULL — "no user check; subagent independence only".
- **Autonomous STOP fallback**: STOP means write the field and findings into the decision record with NO WINNER and do not implement. Where this table disagrees with a phase's prose, the PHASE governs and the mismatch is a bug in this file:

| Branch | User present | Autonomous |
|---|---|---|
| Second collapse (removal of a regenerated slot) | show both fields, user decides | STOP |
| Both-wipeout by disqualification (2nd time) | NO WINNER unconditionally — show field + rule | NO WINNER |
| Every dimension majority-OPINION | NO WINNER this round; reopen iff the single reopen counter is unspent, else end (Phase 2.9 — the counter decides, not a choice) | same |
| Any majority-OPINION dimension | full mode + user assent: redistribute per 2.9; otherwise full weight, close pair (label owned by 2.9) | STOP at weight ≥ 0.25; below: close pair per the mode's rule |
| Every finalist fatally flawed | show findings, user decides | STOP |
| Fatal-flaw claim without citation | CONCERN, not FATAL — proceeds recorded, except where the Phase 4 severity gate binds | same |
| Unopposed sole survivor | ≥ 5.0: user confirms; below: NO WINNER regardless (Phase 1.5) | STOP |
| Full-mode close pair red-team + spikes cannot separate | user picks | STOP |
| Lightweight close call | user picks | ordered procedure in lightweight-mode.md; NO WINNER on any zero-evidence-or-field-integrity failure |
| Autonomous lightweight on a problem with ANY full-mode trigger | n/a — a user present means full mode was available | ABORTED PRE-FLIGHT (Calibration; a mid-run user loss instead follows the mid-run rule) |
| Near-miss within band of an effective gate | surface, user may override | threshold decides, label "unreviewed" |
| Plateau-uninformative / no carried anchor / NOISE > 1.5 / broken removal premise | — | NOT a stop: routes to Phase 4 as a close pair (the other unusable-NOISE causes continue on fixed thresholds — full-mode.md Rule 0.5) |

- **BINDING vs DISCIPLINE**: BINDING = violation visible in the output to a reader holding this file. Two grades — the default is PRESENCE (the artifact exists and can be seen missing); CONTENT-VERIFIABLE means a reader can recompute its truth (totals from printed cells, a pasted command re-run). (SAC.) DISCIPLINE = honest effort, unverifiable. Anything unlabeled is DISCIPLINE. Never present a DISCIPLINE step as a guarantee.

## Calibration: pick the mode first

- **Lightweight** (the DEFAULT — contained bug, single file, reversible): n=3, one round, no subagents, unblinded self-scoring. Rules: this file plus `references/lightweight-mode.md` — read it BEFORE Phase 0 (BINDING). A lightweight run never loads `full-mode.md` or `templates/`.
- **Full** (architecture, cross-cutting, high blast radius, failed prior fix, data-integrity): n=5, subagent scoring, up to 3 rounds. Rules: this file plus `references/full-mode.md` — read it BEFORE Phase 0 (BINDING).
- Full mode needs an explicit trigger — and a trigger recorded PRESENT is SUFFICIENT, not merely necessary: it SELECTS full mode when a user is reachable, and running lightweight over a present trigger requires the user's quoted assent in the mode verdict (bias channel 7 is the agent talking itself into the weaker mode; this sentence is its gate). **Mode verdict artifact** (BINDING): list every trigger — architecture / cross-cutting / high blast radius / failed prior fix / data-integrity / user request — with a present-or-absent verdict and one line of evidence each, plus whether a user is reachable. No reachable user → the mode DROPS to lightweight — a rule — unless the user pre-authorized autonomous full in text quoted into the artifact (autonomous full ends in NO WINNER on most branches; choosing it unprompted spends up to 18 calls on a matrix and no decision). When genuinely unsure, ask — one sentence.
- **Pre-flight abort** (BINDING): (1) evaluated at Phase 0 AND re-evaluated the moment the user becomes RUN-LOCAL unreachable mid-run — mid-run meaning: convert to a rule-determined NO WINNER preserving every earned artifact (never the "do not generate" branch, which is Phase-0-only); re-check before the next subagent call in full mode, at each phase boundary in lightweight. (2) The abort itself: the mode verdict records a DOWNGRADE to lightweight (no reachable user, no quoted pre-authorization) AND any full-mode trigger is present → do not generate at all. This is POLICY, not entailment — a clean lightweight run could reach implementation; the file declines to run the highest-stakes problems in the weakest configuration unattended. Emit the mode verdict, the triggers, and "tournament declined: this configuration terminates in STOP by rule", then take the minimal provisional intervention under After NO WINNER. A PRE-AUTHORIZED autonomous full run is NOT aborted: it proceeds and ends in NO WINNER only on its listed branches.
- **The user can always stop it.** "Just patch it" is an instruction, not a debate opening: record the field so far, comply, label what was and was not established. Every anti-exit rule binds the AGENT only.
- **Downgrade when the problem deflates; never self-exit once the field exists.** In Phase 0 a trivial problem means exit and just fix it, noting why. From Phase 1 on, exit is not the agent's call ("this deflated" is indistinguishable from "my favorite is the obvious one"). A full → lightweight downgrade after Phase 1 must be announced with its reason, PRESERVES every independent artifact already earned (returned scores stay in the matrix; a run skeptic's verdicts stand), and the close-pair route still goes to a present user — a downgrade forfeits future independence, never past independence.

## Phase 0: Evidence and rubric BEFORE candidates

Order is mandatory: pack → rubric → checkpoint → generation. Criteria or evidence chosen after seeing candidates become rationalizations for a favorite.

1. **Pack first** (BINDING): problem statement, the code and interfaces it touches, scale numbers, deadlines, constraints.
   - Every non-quote fact is tagged MEASURED (naming its command, file, or trace) or ESTIMATED. Tags are self-assigned (DISCIPLINE); naming a command is not running it, and a fact mislabeled MEASURED can promote a CONCERN to a FATAL. A score or FATAL resting solely on an ESTIMATED fact says so in the matrix.
   - **Evidence floor** (BINDING). A **decisive gate**:
     (1) requires at least one MEASURED fact on its DECIDING DIMENSION — the dimension whose SIGNED weighted contribution to the leader's margin is largest: weight × (leader's score − runner-up's score), computed on the means that enter the totals; dimensions where the leader scores lower are ineligible, so the floor can never be satisfied by evidence arguing against the winner; equal contributions → both need a fact. **ONE-CANDIDATE selector** (a sole survivor, or a post-FATAL field): the highest-weighted dimension scoring below 5, else the highest-weighted dimension — defined here; the Survivor floor and "Decisive winner falls" import it.
     (1.5) SCORE PROVENANCE gates too: if the deciding dimension holds a SELF-SCORED RECOVERY (a struck-and-replaced cell — NOT ordinary lightweight self-scoring, which would make this unfirable there), a DISPUTED replacement, or a HYPOTHESIS-capped cell FOR THE LEADER, the gate does not fire — close pair (NO WINNER autonomously). The provenance of every deciding-dimension cell prints in the evidence-floor artifact.
     (2) At least ONE of those facts must be RE-RUN IN SESSION before the gate fires. A command-warranted fact re-runs its named command. A file- or trace-warranted fact re-runs by RE-READING the cited location, the exact location recorded and the re-read text quoted — and honestly: a re-read of a location already read this session is ATTESTED-NOT-EXECUTED, so a deciding dimension resting ONLY on already-read file/trace facts does not fire the gate — close pair — unless a location is read for the FIRST time in session or a command-warranted fact is on the dimension. CONFIRMS/CONTRADICTS/AMBIGUOUS apply to re-reads as to command output; a cited location that no longer exists demotes the fact to ESTIMATED.
     (3) The command or location must be THE ONE THE TAG NAMED, not a substitute. Tags freeze before candidates exist, so they cannot be tailored to a written candidate; tailoring to a HELD prior remains possible — in lightweight that residual is DISCIPLINE.
     (4) The printed command must reference an identifier, path, or value named in the fact it re-runs (checkable from the printed command); a re-run whose output would read identically whether the claim were true or false FAILS the floor (that counterfactual is the author's judgment — attested). One checkable, one attested, labeled as such.
     (5) A named command that no longer exists or cannot run demotes the fact to ESTIMATED and the gate does not fire. Run it; paste the command and verbatim output. The run can DISAGREE — that is the point: output CONTRADICTING the claim demotes the fact to ESTIMATED, emits pack-v2 with the diff, the gate does not fire, close pair (NO WINNER autonomously). AMBIGUOUS output = CONTRADICTS, since the adjudicator authored both the claim and the command. A re-run CARRIES across rounds only while the deciding dimension AND both compared candidates are unchanged — an offspring leader/runner-up or a changed dimension needs its own re-run. Nothing re-runnable on the deciding dimension → the gate does not fire: close pair labeled "no MEASURED fact on the deciding dimension", NO WINNER autonomously. A pack with ZERO MEASURED facts anywhere, in an AUTONOMOUS run of either mode, is NO WINNER outright — a label is not a gate, and the zero-evidence branches share one outcome.
   - A **FATAL** requires a MEASURED fact on the dimension THE FLAW ATTACKS, not on the margin's deciding dimension — a data-loss kill needs data-loss evidence. Failing that it is a CONCERN. A FATAL carries the SAME re-run obligation as the decisive gate: the fact's named command re-run in session, verbatim output shown, before the FATAL stands; AMBIGUOUS = CONTRADICTS; a command that no longer executes demotes the FATAL to CONCERN — EXCEPT when the AGENT HAS NO EXECUTION TOOL: an environment-defanged FATAL routes the round to a close pair (user decides; NO WINNER autonomously), because an untested kill-claim must not decay into a politely recorded row. In lightweight this execution requirement is the only part of a FATAL that is not self-attestation.
   - The **sole-survivor 5.0 floor** is a decisive gate with no second candidate: its deciding dimension is the highest-weighted dimension scoring below 5 (equal weights break to the lower score, then alphabetically by rubric name — the terminal-tiebreak convention every selector carries); scoring ≥ 5 everywhere, the highest-weighted dimension. Never inapplicable: an unopposed winner on an all-guesses pack is exactly the case it catches.
   - Write the pack to a file and print its SHA-256 BEFORE the first candidate. **No execution tool** (BINDING): print "hash unavailable — no execution tool" rather than ANY value (an emitted hex string never computed is fabrication); record ZERO re-runnable facts; every decisive gate fails the evidence floor — close pair to the user, NO WINNER autonomously. No filesystem → print the pack verbatim in the output and hash that printed text, saying so; the decision record carries the pack verbatim so a reader can recompute. (SAC.)
   - The pack is frozen at the checkpoint. Late facts: full mode only, under full-mode.md's versioning protocol. Lightweight: reopen or NO WINNER, never a quiet edit.
2. Restate the problem in one paragraph, including how the current approach fails.
3. **Pre-register the expected winner** (DISCIPLINE — self-reported, unverifiable): one sentence — "before generating, I expect some form of X to win." Recorded in the output and decision record; excluded from every SCORER and SKEPTIC prompt; supplied to the red-team packet ONLY when a crossbreed round ran (the MATCH/NO-MATCH audit is the sole reason it needs the prior; otherwise the packet line reads "pre-registration withheld: no MATCH/NO-MATCH call to audit"). When supplied, the leakage is booked: those finalist verdicts are not prior-blind. A match with the winner is uninformative alone; no scrutiny asymmetry attaches.
4. Define 4–6 scoring dimensions. Defaults (adjust per problem): root-cause resolution 30%, robustness/production-readiness 25%, maintainability/simplicity 20%, performance/cost 15%, implementation risk/reversibility 10%. Weights sum to 1.0 and every weight is ABOVE ZERO — a zero-weighted dimension can never be deciding or contested, never trips the ≥ 0.25 stop, yet would still satisfy the floors: a silent wrong answer. A user reweight that zeroes a dimension DROPS it (rubric must still hold 4–6 dimensions, or the reweight is declined with the reason printed). After any reweighting, normalize to 1.0 and show the weights — every threshold assumes that normalization.
5. **Rubric checkpoint** (BINDING when a user is present): show the dimensions; ask the user to rank or reweight. Approval of pre-filled weights is consent to defaults, not an expression of values — the output states which it got: "weights: user-edited" / "defaults, user-approved" / "defaults, autonomous run". Skipping the checkpoint requires pre-authorization that names tournaments specifically, quoted in the output. Weights freeze for the tournament; mid-tournament changes happen only at the user's initiative, showing before and after matrices.
6. **Disqualification rule** (artifact BINDING; identical application DISCIPLINE):
   - Name the symptom as a falsifiable test: "this candidate leaves <observable root cause> in place; check: <what to look at>". Apply to every candidate; show each result.
   - **DQ pre-commitment** (optional; the ONLY thing that lets an autonomous-lightweight removal survive Phase 2.11(c)): at the Phase 1.5 removal step, pre-commit a SURVIVING candidate's row and the score range the removal's premise entails there, under 2.11(b)'s width rule, naming the falsifying matrix result. If the target is dropped by a later verdict in the same pass, RE-POINT once (printed, both targets); a second loss of target makes the removal UNFALSIFIABLE.
   - **VERIFIED diagnosis** (reproduction, trace, log, or measurement in the pack — cite it): a candidate leaving the root cause fully in place is REMOVED before ranking; n shrinks; never scored 0. **Execution bar** (BINDING where an execution tool exists): before the first VERIFIED verdict stands, the cited diagnosis is DEMONSTRATED in session — the cited command or failing test re-run with verbatim output in the record; a cited artifact alone is a HYPOTHESIS verdict, not a VERIFIED one. Removal is the file's most consequential act and unrecoverable within the round, so a misdiagnosis must fail loudly here, not propagate with full confidence. One demonstration covers all removals resting on the same diagnosis; AMBIGUOUS output = CONTRADICTS, demoting the verdict to HYPOTHESIS (the same asymmetry the evidence floor applies). With NO execution tool, every DQ verdict caps at HYPOTHESIS — an untestable kill-claim must not remove, matching the FATAL's no-execution-tool rule. Every VERIFIED removal prints "PARTIAL considered and rejected: <the residual path checked for, and the observable showing it absent>" — the VERIFIED-vs-PARTIAL call is a contestable artifact, not an invisible classification.
   - **PARTIAL** (mechanism fixed, named residual path): NOT removed; takes the HYPOTHESIS cap on the root-cause dimension, residual named in its row. Ambiguous cases resolve to PARTIAL by rule — removal is unrecoverable within the round and 2.11 cannot falsify it.
   - **HYPOTHESIS**: removes no one; the root-cause score is CAPPED AT 4 (if no root-cause dimension exists, Phase 0 names the inheritor). The cap is applied by the MAIN agent to returned scores, never in the scorer prompt (anchoring). Ranks on the capped dimension are VOID for the tiebreaker, which renormalizes over the rest. Two scorers: the cap applies to EACH RAW score before the mean (3 and 8 → 3 and 4, mean 3.5), both originals shown.
   - **Cap accounting**: a HYPOTHESIS or PARTIAL cap is outcome-sized (it can move a rival by weight × max(0, original − 4) — more than the decisive gate when the original is high), so it pre-commits, when applied, the residual path's OBSERVABLE plus a surviving candidate's row and range under 2.11(b)'s width rule. An un-pre-committed cap whose magnitude exceeds the round's margin demotes the round to a close pair (NO WINNER in autonomous lightweight). Every cap's magnitude prints beside it. Full mode: caps join the red-team audit duty.
   - Removed candidates appear in the final matrix as REMOVED rows with the test, cited evidence, and verdict; their full text goes to the red-team packet (full mode).
   - **Precedence at the combined removal pass** (same wording as Phase 1.5): ZERO survivors takes the Phase 0 reopen branch, never regeneration; a second wipeout ends the tournament NO WINNER. The regenerate and sole-survivor rules apply only with at least one survivor.
   - Timing, three ordered steps at the Phase 1.5 boundary: (a) apply the DQ test to all candidates, record verdicts; (b) run the batched skeptic on the full field, removed text included for context; (c) count DQ removals and filler verdicts together and take the removal branch.
7. Read prior decision records: `docs/decisions/NNNN-*.md` via `docs/decisions/INDEX.md` (skip with a note when there is no repo). Records are dated claims: before carrying a rejection forward, verify its blocker still exists — by RE-RUNNING its recorded blocker-check command where the record carries one (verbatim output shown; Phase 5 mandates the command in new records). A rejection whose check no longer shows the blocker, or that carries no runnable check, does not block — it is noted as a dated claim.

## Phase 1: Divergent generation (n per mode)

- Each candidate differs from every other on a **named structural axis** (architecture, data model, dependency, algorithm class, where-the-logic-lives). Slot #1 is the obvious approach, named as such. At least one credible long shot — test: could it plausibly win one rubric dimension outright? A field of paraphrases is a failed generation: regenerate once; fewer than n distinct axes → run with what exists (minimum 2), saying so; fewer than 2 credible axes → NOT tournamentable: exit under the skip floor with the reason printed, generating no field.
- Per candidate: mechanism, what it assumes, what breaks it — **90–150 words each**. "What breaks it" names a rung on the fixed severity ladder — data loss / correctness / performance / effort — so severity is comparable, not rhetorical.
- **Candidate hashes** (RECORD-BINDING; SAC): when the field freezes at the end of Phase 1.5 (post-revision, post-removal), print each survivor's mechanism-text SHA-256 beside its label. The same hashes appear in the scorer packet, the verbatim field shown to the user, and the decision record. This helps the user hold one version of the text — framing (channel 1) has the user as its only real detector.
- Cross-advocacy pass: full mode only (full-mode.md).

## Phase 1.5: Skeptic pass (before scoring)

- **One batched skeptic pass** (full mode: fresh subagent, `templates/skeptic.md`; lightweight: per its mode file): attacks ALL candidates in one pass and authors, per candidate, critique → revision guidance → premortem (≤80 words; failure class from the severity ladder + likelihood + detection point, e.g. "would surface at integration"). The skeptic, never the generator, writes every premortem, holding severity comparable — scorers grade the risk, not the vividness of the story.
- **Filler verdict** (BINDING): a candidate with no plausible path to winning ANY dimension is DROPPED before scoring. The verdict text appears in the final matrix as a DROPPED row — a culled field must be visible, never silent.
- Removal precedence (DQ removals + filler verdicts as one number): ZERO survivors → Phase 0 reopen branch, never regeneration. Then the failed-generation rule: MORE than one removal in the combined pass → regenerate the culled slots once; regenerated slots take the DQ test plus an **abbreviated skeptic pass** — defined once, here: critique + premortem + filler verdict for the new candidates only, no revision round, no re-critique of survivors (crossbreed offspring use this same definition). A second collapse — ANY removal of a regenerated slot, either type — stops the run: show the user both fields with the verdicts.
- **Sole survivor** (reached by one shape only: a two-candidate field losing exactly one): still SCORED solo against the rubric. Proceeds to Phase 4 only at a weighted total ≥ 5.0, carries "sole survivor — ran unopposed", and a present user confirms it as a decision. Below 5.0, or in any autonomous run: NO WINNER — report the field, do not implement.
- **Revision**: each survivor gets one strengthening pass that may not change its named axis; whether a fix crosses the axis is the skeptic's call, made in the batched pass with the axis named.
- **Show the user the field** (BINDING when present): output the mechanism texts and premortems VERBATIM (not summaries), each with its freeze hash.
- **Objection branch** (BINDING when present): showing the field is pointless without a route to act on it. A stated framing objection ("C is described unfairly") forces ONE rewrite of that candidate's mechanism text (axis unchanged), a re-freeze with new hashes, a printed FRAMING OBJECTION row naming what changed — and the rewritten text RE-SHOWN verbatim with its new hash (the closing half of the same exchange; no new interaction). One objection per candidate, bounded at one per LABEL ISSUED (removed and dropped rows are objectable via re-admission), so a user exercising every objection adds at most L exchanges (L = the run's label count). Objection exchanges are user-initiated and sit outside the agent-initiated interaction sums. Rewrites strengthen, never re-scope.
- **Field-mutation rules, stated once for every route**:
  - (M1) ANY candidate whose text changes or that enters the field after the freeze — objection rewrite, user re-admission, regenerated slot, crossbreed offspring — takes the DQ test and the abbreviated skeptic pass before scoring, and is re-frozen with a new hash. A mutated candidate scored against a stale premortem is a silent wrong answer.
  - (M2) A mutated candidate that its own pass then REMOVES shrinks the field with ONE consequence (never the second-collapse STOP, which applies only to Phase 1.5's original passes): the round demotes to a close pair, or to the sole-survivor rule / NO WINNER below two. Post-freeze removals are never silent.
  - (M3) One abbreviated-skeptic slot is RESERVED for this route (the full-mode call ceiling counts it), so the FIRST post-freeze mutation never demotes the round — a safeguard that costs the user their decisive result has a disincentive built in. In full mode, any FURTHER user objection or re-admission past the reserved slot takes a SELF-ADMINISTERED abbreviated pass labeled as such — never a spawn beyond the call ceiling, never a demotion — and the budget exemption is printed on the re-admitted candidate's row.
  - (M4) Mutation budget: ONE AGENT-initiated post-freeze mutation per run, either mode. User objections and re-admissions are EXEMPT (the user outranks a single skeptic verdict as they outrank a framing); regeneration precedes the freeze and is exempt. A second agent-initiated mutation: the candidate scores carrying "no premortem — ungraded risk" and the round demotes to a close pair (full mode); lightweight demotes to a close pair.
  - Re-admission may push the field above n (scored as-is, noted "field: n+1 after re-admission"); it does NOT recompute the removal-count branch. A contested REMOVED/DROPPED row re-enters scoring labeled "re-admitted by user objection" (a HYPOTHESIS-grade DQ concern travels with it as the cap). Autonomous runs: the verbatim field goes in the decision record, plus a line that no objection route ran — the only real detector of channel 1 was absent.

## Phase 2: Adversarial scoring

Not "blind": label-shuffling removes authorship and ordering effects; nothing hides which candidate is conventional, and scorers share the generator's model priors — agreement is consensus, not evidence. These mechanisms raise the cost of vibes; they do not turn scores into measurements.

Run in this order:

0. **Return gate**: (a) Completeness — every label sent was scored, every required field present. (b) **Responsiveness** — each scored dimension quotes a candidate-specific locator (a mechanism element, assumption, or premortem clause unique to THAT candidate, false if pasted under another row), quoted in the matrix for the reader's paste test (the agent's own application is DISCIPLINE; this detects reused generic text, not a specific quote on a generic judgment). (c) **Recompute and correct** — recompute every weighted total from the returned cells before any gate reads one. Discrepancy > 0.05: the recomputation stands, printed as an ARITHMETIC CORRECTION row; a discrepancy on either of the top two rows (of the corrected ordering) demotes the round to a close pair. Failures: a short or malformed return gets ONE re-spawn; a second short return is "incomplete scoring" → close pair. A failed locator test → close pair "unresponsive scoring"; in autonomous lightweight, NO WINNER (a disjunction the agent resolves for itself is not a safeguard). Lightweight adaptations: its mode file.
1. **Scale**: 0–10 per dimension (2 = serious deficiency, 5 = adequate with real concerns, 8 = strong with minor concerns). Weighted total = Σ(weight × score); totals and margins live on the 0–10 scale.
2. **Margin, defined once**: the difference between the TOP TWO weighted totals in whatever comparison the current gate names — decisive gates use the round's best two; the plateau gate uses best offspring vs the carried anchor (full-mode.md).
3. **Who scores**: per the mode file. Both modes follow this numbered procedure, including the forced 1..n ranking (step 10 needs it).
4. **Label order**: candidates ordered by the frozen mechanism SHA-256s from Phase 1.5, also listed in the scorer packet so the scored text is bound to the shown text. DISCIPLINE: removes incidental ordering effects; cannot resist deliberate authorship (SAC).
5. **Cite before scoring**: per dimension, state which pack facts bear on it — the same fact set for all candidates — then score against them with quote + locator. A cherry-picked true fact still serves a prior: this raises the cost of vibes, no more.
6. **Verify citations** (main agent, on return):
   - A citation absent from the pack STRIKES the cell, marked STRUCK with the fabricated citation quoted.
   - Striking VOIDS that scorer's ranks on that dimension; the tiebreaker renormalizes over the rest (as the HYPOTHESIS cap does). A SELF-SCORED recovery does not restore the rank. **Floor**: fewer than 2 dimensions with live ranks → tiebreaker unavailable, round is a close pair. No tie is decided by a rank whose score no longer exists.
   - Recovery, in order (any recovered value on a capped dimension re-applies the cap, both values printed): the other scorer's surviving value → main-agent re-score (marked SELF-SCORED) if budget remains → mark the cell UNSCORED and drop that dimension for EVERY candidate, renormalizing uniformly, round becomes a close pair. **Drop floor**, four ordered steps: (1) identify candidates with COMPLETE pre-drop rows; fewer than two → close pair, floor not attempted. (2) Compute the deciding dimension on the PRE-drop matrix over those candidates. (3) BLOCK the drop if it would leave fewer than 3 surviving dimensions or remove the deciding dimension. (4) Blocked → close pair, no further drops, that candidate's total prints INCOMPUTABLE — never imputed — and is ineligible for top-two selection; fewer than two eligible → NO WINNER autonomously, or the user with the full matrix. Ordering among an eligible close pair falls to the tiebreaker over surviving dimensions; if that cannot separate them either, the choice goes to the user, or NO WINNER autonomously. Never renormalize one candidate alone (it inflates that total against rivals scored on the full rubric). A voided score never silently reverts to the struck value.
7. **Combine scorers**: two-scorer aggregation, DISPUTED, and rank-inversion surfacing are full-mode machinery (full-mode.md). **Re-score budget**: 2 main-agent re-scores per tournament, shared across struck-cell recovery and DISPUTED; a Phase 0 reopen does NOT restart it. The matrix prints the count of main-agent-scored cells — the channel through which independent scoring reverts to self-scoring must be visible.
8. **OPINION**: a score with no citable fact is OPINION at full weight. Two scorers: a cell counts as OPINION only if BOTH marked it (a deliberate unanimity gate — one grounded citation IS evidence; a split prints "OPINION (1 of 2)", visible but not counted). Single scorer: that mark alone suffices, so the safeguard never switches off in the most common configuration. A majority-OPINION dimension is a FINDING in the matrix, never a silent mechanic.
9. **Redistribution** — one of exactly THREE exceptions to the weight freeze (with the user-initiated reweight, Phase 0.5, and the UNSCORED drop, 2.6 — the drop is permitted even in lightweight/autonomous runs because it removes a dimension uniformly rather than reweighting toward one candidate); all three make NOISE unusable next round ("weights changed"): a majority-OPINION dimension's weight may redistribute proportionally (renormalize to 1.0) ONLY with the user's explicit assent, obeying Phase 0.4's above-zero rule (full redistribution = DROP; rubric still 4–6 or declined), forbidden in lightweight and autonomous runs, forbidden past ONE dimension per tournament. Autonomous: at weight ≥ 0.25 the run STOPS (NO WINNER); below, the dimension keeps full weight and the round is a close pair labeled "majority-OPINION below the stop" (label owned here). Once applied it persists all remaining rounds; both weight sets in the record. EVERY dimension majority-OPINION → the pack cannot support scoring: NO WINNER this round — reopen iff the single reopen counter is unspent, else end. A reopened round scores against the REPAIRED pack and MAY produce a winner on its own merits; this round's NO WINNER stands for this round only. A reopened round again all-OPINION ends the run.
10. **Ties**: totals within 0.3 → tiebreaker = **weighted mean rank** Σ(weight × rank), lower wins (two scorers: mean of their weighted mean ranks). Forced ranking (1..n, no ties) exists to break 7–8 clustering; ranks never enter totals. A surviving tie routes like any close margin in the current mode.
11. **Falsify the removals** (after scores exist):
    - a. **Domination-argument filler verdicts**: the argument names one dominator PER RUBRIC DIMENSION; the verdict FAILS if ANY named dominator was scored and did not win its named dimension — one broken leg breaks the argument. → BROKEN REMOVAL PREMISE (e).
    - b. **Cited-fact filler verdicts**: must have pre-committed, at removal time, a SURVIVING candidate's row and the score range the fact ENTAILS there. The range must EXCLUDE at least half the 0–10 scale (width ≤ 5.0 — "0–6" is 6.0 wide, non-compliant) and name the falsifying matrix result, which must be REACHABLE: a falsifier above a HYPOTHESIS cap, on a struck cell, or on a dropped dimension can never occur, and a test that cannot fail is not a test — on a capped row the range binds the ORIGINAL pre-cap value (both print). Unreachable falsifier or width failure → UNFALSIFIABLE (d). The matrix lands outside the range → the verdict FAILS (e). No pre-commitment → UNFALSIFIABLE. Post-hoc contradiction-checking by the verdict's own author is not a test.
    - c. **DQ removals**: UNFALSIFIABLE BY DEFAULT (a removed candidate has no matrix row) unless the removal pre-committed a surviving candidate's row and range (Phase 0.6), checked as in (b). Autonomous lightweight: an un-pre-committed DQ removal is NO WINNER outright — the removing agent does not also get to be the only check on the removal.
    - d. **UNFALSIFIABLE** (any route, including a named target later lost): the removal stands, the round routes to a close pair — and in AUTONOMOUS LIGHTWEIGHT, an UNFALSIFIABLE removal of ANY kind is NO WINNER outright, never a self-resolved close pair. The same event resolves identically on every path.
    - e. **BROKEN REMOVAL PREMISE**: the removal stands (re-scoring mid-stream would unfreeze the field), the round demotes to a close pair, the dropped candidate's verbatim text goes to the user or record with the finding, and no decisive result may be claimed on a field culled on a false premise.
- Show the full matrix — DROPPED and REMOVED rows included — never just the winner.

## Phase 3: Decision gate

Evaluate the routing rules in the order listed — the FIRST matching rule wins, same convention as full-mode.md's crossbreed list. The field-size print (F1) and near-miss surfacing always apply regardless of which rule matched.

- **Rule F — field size**: (F1) PRINT, always: "field reduced: n=X of Y, Z removed" when the field entering this gate is smaller than the mode's n; state the field was whole otherwise. (F2) A ONE-candidate field never enters this gate — Phase 1.5's sole-survivor rule terminates it first; the 5.0 decision runs its OWN one-threshold near-miss sweep in place (solo total, the 5.0 floor, band 0.3, distance; within band → surface to the user; autonomous → "decided by threshold, unreviewed"), and this run shape's Phase 3 checklist line is "2 of 2" (solo sweep line + the floor's evidence-floor artifact). (F3) A TWO-candidate field routes as a close pair regardless of margin, BOTH modes — a "decisive" win over the only remaining rival is a statement about a field of two, not the solution space.
- **Decisive**: margin > 1.0 weighted points → the winner alone proceeds to Phase 4.
- **Close** (≤ 1.0): full mode → crossbreed round (rules, NOISE, and the ordered gate list in full-mode.md — read before entering). Lightweight → its mode file's routing row.
- **Near-miss surfacing** (ALWAYS evaluated, not a routing rule; surfacing BINDING, wording symmetry DISCIPLINE): every numeric threshold named in the mode's authoritative enumeration — full: the Exit Phase 3 list in full-mode.md; lightweight: box 9 of its inventory — is an uncalibrated convention, and any future in-phase threshold must be ADDED to its enumeration (the maintenance rule keeping scope identical). Pre-Phase-0 floors (the skip floor's counts) are outside this machinery: judgment, no band, no surfacing. "Within its band" = |value − effective threshold| ≤ band, inclusive (the gates themselves are strict). Measure against the EFFECTIVE threshold applied (crossbreed rounds: max(1.0, NOISE + 0.5) decisive, max(0.5, NOISE) plateau; the initial round's decisive gate is the fixed 1.0). With 0.3-wide bands on 0–10 gates, identification fires on most realistic runs — "near-miss" signals "worth a look", and the ranked cap is the real selector: at most TWO per run reach the user, one batched question, ranked by PROXIMITY = distance ÷ band (smaller closer) WITHIN class; dimension-bearing [D] outranks dimensionless [X] at any proximity; then higher weight (where one applies), then phase order, then alphabetically by printed threshold name — fully determined, so two agents holding the same identified set surface the same two. Class tokens live beside each name in the enumerations. Identification is DISCIPLINE, but the NAME list is diffable against the enumeration (a silently omitted threshold is visible); the distances are self-computed. The rest are recorded, threshold-decided, "unreviewed". Surfacing wording is identical whichever side the favorite is on, the agent's preference stated separately; autonomous: record with both sides flagged, take the threshold's outcome, label "decided by threshold, unreviewed". Near the line, judgment decides, not arithmetic.
- A close pair REQUIRES two eligible candidates. A rule demoting a round with fewer (a scored sole survivor whose removal premise broke; a drop floor with fewer than two complete rows) has no pair to form: the user's decision with the full matrix, or NO WINNER autonomously. "Close pair" everywhere = the top two by current weighted total arriving at Phase 4 together, by ANY route declining to name a single winner — an open list by construction. The 0.3 tiebreaker orders a close pair; it never substitutes for these routes.

## Phase 4: Red-team, spikes, and audit

Routing: a decisive winner is red-teamed alone; a close pair (any route) in one packet covering both finalists. Full mode: fresh subagent (`templates/red-team.md`), plus the pack-bound limit, absent-approach duty, FATAL evidence bar, audit duty, and spike gate in full-mode.md. Lightweight: the MAIN agent self-administers the standing questions, findings labeled self-authored; no audit exists — Phase 2.11 is the whole protection on its removals.

- **FATAL re-check on return** (BINDING, both modes; actor: the MAIN agent): every FATAL in a returned or self-administered report is re-checked against Phase 0's bar — a MEASURED fact on the attacked dimension, re-run in session. A FATAL citing a SPIKE result satisfies the re-check when the spike's raw command and verbatim output are in the record (a spike IS an in-session run); a pack-fact FATAL takes the re-run. THIS sentence governs over any evidence wording in full-mode.md or the templates. A failing FATAL prints as CONCERN with the demotion reason on its row.
- **Severity gate** (BINDING, both modes): (1) a standing CONCERN or premortem against the candidate about to be implemented, at the DATA-LOSS rung (ANY likelihood) or the CORRECTNESS rung at HIGH likelihood, DEMOTES a decisive result to a close pair (user decides; NO WINNER autonomously). Rung and likelihood come from the FINDING'S AUTHOR, never assigned by the main agent after it knows which candidate it intends to implement. A CONCERN returned without a rung = DATA-LOSS, full stop (full mode — the author is a completed single-shot return). Lightweight: the rung is self-assigned at write time AND must name the premortem clause or pack fact it derives from; an anchor-less rung prints UNRUNGED and takes the DATA-LOSS default. (2) On an ALREADY-close pair the gate still binds: a DATA-LOSS-rung standing concern on the selected finalist must clear one of the routes below before Phase 5, else NO WINNER — one exception: a PRESENT user may accept an uncleared concern as a LABELED OVERRIDE ("user accepted <concern> uncleared" on the decision row); no autonomous override. (3) On a demotion from decisive, the runner-up enters Phase 4 as a finalist and is red-teamed (full mode: within the remaining budget, else close pair per the precedence rule — never an unchecked promotion) and must satisfy the Survivor floor. (4) Two clearing routes: (r1) the pack carries a re-run MEASURED fact showing the named mechanism ABSENT, or (r2) the implementation plan names a MITIGATION for the exact mechanism plus its pre-production DETECTION POINT — a NAMED TEST COMMAND, existing or committed to in Phase 5, printed on the gate's row. Route 2 is SELF-ATTESTED in both modes and labeled; the named command, not the author, keeps it above a label. A CONCERN naming no MECHANISM is UNCLEARABLE by construction (nothing to mitigate, nothing to show absent) and takes the gate's consequence — deliberate: a claim vague enough to be unfalsifiable must not clear the file's top severity gate. No pre-production detection point → cannot clear by route 2 — undetectable-until-production is what the gate exists to stop. (5) Without this gate the file's top severity class reaches production as a politely recorded row.
- **Standing questions**: What happens at 10x? In 6 months, context forgotten? Which single assumption, if false, kills it — and how would we detect that early? Is any part a bandaid wearing a suit (special cases, silenced warnings, magic constants, "temporary" flags)? **Pack interrogation** (both modes; full: red-team Parts 0 and 0.2; lightweight: self-administered and labeled): challenge one MEASURED tag or state that every one names a re-runnable command; disclose explicitly a ZERO-MEASURED pack; print the "packet integrity: checked/concern" row. **Field-ceiling question** (both modes): name one credible approach absent from the Phase 1 field, or state none exists. A credible absent approach reopens Phase 1 once against the shared reopen counter; counter spent → it prints as a standing finding that demotes a decisive result to a close pair. An answer with no consequence would be a label.
- **Decisive winner falls** (BINDING, both modes): when a DECISIVE run's sole finalist takes a standing FATAL, the runner-up is promoted ONLY if it independently satisfies the evidence floor on ITS OWN deciding dimension (recomputed against the new leader gap; one candidate left → the ONE-CANDIDATE selector) and then enters Phase 4 as a finalist itself; otherwise close pair — user when reachable, NO WINNER autonomously. The crown does not pass unexamined.
- **Survivor floor** (BINDING, both modes): a close-pair finalist selected by a standing FATAL or a discriminating spike must satisfy the evidence floor on ITS OWN deciding dimension (post-FATAL: the ONE-CANDIDATE selector) before Phase 5 — the FATAL's evidence killed the rival and licensed nothing about the survivor; nothing reaches implementation without a gate having fired for IT. Failing: user decides, NO WINNER autonomously.
- **Close-pair terminal rule** (BINDING): both finalists survive red-team and spikes do not discriminate (both pass, both fail, or none ran) → the choice goes to the USER with both reports, the spike criteria and results, and the final matrix. A USER-selected finalist is EXEMPT from the Survivor floor (the user outranks every internal gate — design, not oversight), labeled "selected by user; no evidence-floor gate fired for this finalist", with the re-run that WOULD have cleared the floor printed beside it so the user can request it before confirming. Autonomous: NO WINNER — a close pair is never resolved by the agent's unaided preference. A discriminating spike result or a standing FATAL selects the survivor.

## Phase 5: Implement to production standard

- Enter plan mode first if the change touches multiple files or systems; spikes must already be deleted. **No execution tool** (BINDING): a run reaching here unable to run commands (possible via the close-pair terminal's user-selection exemption) prints "tests: NOT RUN — no execution tool" and "route-2 detection: NOT RUN — no execution tool", ships NOTHING, and ends as PARTIAL EXECUTION with the diff labeled PROVISIONAL INTERVENTION. Fabricating either line, or omitting it silently, is the failure this file names everywhere.
- Production standard: tests covering the failure mode that motivated the tournament — the test command with verbatim pass/fail output goes in the decision record (an asserted standard and a red suite look identical on paper). **A suite that does not pass on the motivating failure mode is new pack evidence, not a footnote** — and a route-2 DETECTION command that fails, errors, or is ABSENT FROM THE RECORD routes identically (a command never run neither fails nor errors — absence is the loophole this closes; the gate cleared on that command's promise, its failure un-clears the gate): stop, record the verbatim failure, keep the diff labeled PROVISIONAL INTERVENTION — never merged or deployed, named in the record — and re-enter under After NO WINNER with the runner-up's findings in hand. Disclosure without a branch is how a losing result ships looking complete. Also: error handling for the assumptions identified in Phase 1, and no TODOs standing in for decisions.
- **Fidelity gate** (artifact BINDING, the assertion DISCIPLINE): before the decision record is finalized, restate the winner's named axis and mechanism against the NAMED diff hunks that realize it — file plus function per claim, spot-checkable. Building something other than the winner — most temptingly the obvious slot #1 — is a re-entry condition, not a footnote. Mid-implementation infeasibility is new pack evidence: stop, record it, re-enter under After NO WINNER; the re-entry counter already spent → terminate as "PARTIAL EXECUTION: re-entry exhausted" with the provisional intervention and the mismatch in the record, the user deciding what ships (autonomously, nothing does).
- **Ordering**: the final self-check's repairs and their "repairs applied" line are produced BEFORE the decision record is finalized — the record carries the repaired matrix and the repair log, never an un-repaired matrix with repairs described elsewhere.
- **Decision record** (BINDING): `docs/decisions/NNNN-<slug>.md` plus a one-line append to `docs/decisions/INDEX.md` (create if absent; use the project's ADR home if one exists; no repo → the record's content goes in the session output, saying there is nowhere durable). Contents: problem; rubric with weights and provenance (user-edited / defaults-approved / autonomous / ambiguous-reply — the user answered but resolved no weight: treated as defaults-approved, ambiguity quoted); pre-registered expectation vs actual winner; full matrix per round including DROPPED and REMOVED rows, plus the VERBATIM scorer and red-team returns they were transcribed from — the matrix is a main-agent transcription, and every downstream gate runs on the transcribed text (SAC); the verbatim candidate texts with frozen hashes (autonomous runs); red-team findings and audit marks; the countable costs — candidates generated, subagent calls, rounds, spike attempts. Do not log token guesses as measured. Every REJECTION carried in the record names its **blocker-check command** — "this rejection holds while `<command>` still shows <X>" — so a future tournament re-runs the command instead of judging staleness; a rejection whose blocker is not command-checkable says so and is recorded as a dated claim only, never as a standing block.

## Checklists, ledgers, and degraded execution

Absence of a required artifact is invisible to a reader who does not know it was required; the checklists make it visible. A phase is not exited until its artifacts exist; a missing box is a violation even when every prose rule was "substantially followed". Checklists are artifact inventories (WHAT must exist); the phases hold every rule, threshold, and branch (WHEN and HOW). Full mode: the per-phase Exit checklists, the 48-box applicability table, and the COUNTERS + GATE-ORDER ledgers live in full-mode.md. Lightweight: the 15-box consolidated inventory and its COUNTERS ledger live in lightweight-mode.md. Both modes tag each box @flow (produced when its rule ran) or @late (produced at the exit check); the tag is self-assigned (SAC) — the absent-line automatic strike and the fixed-skeleton diff are the sweep-independent detections.

**Degraded-execution branch** (both modes): fires on TWO STRIKES total in one run, from any of: a LATE REPAIR (a box produced only at the exit check, printed "repaired late: <box>"), an OUT-OF-ORDER or ABSENT gate-order tick (full mode), or a box count printed BELOW its applicable denominator. An ABSENT count line, absent gate-order diff line, entirely absent phase checklist line, or a tick count disagreeing with the Phase 0 pre-committed denominator for a sequence that fired is an AUTOMATIC strike — reader-computable, no sweep needed — and that detection LICENSES the reader to treat the run's conclusions as PARTIAL EXECUTION exactly as if the two-strike terminal had fired: a run that did not print its own count lines has already lost the property "complete" asserts. A tripped run TERMINATES where it stands — no restart, no lighter ruleset: emit the artifacts that exist, label the output "PARTIAL EXECUTION: full ruleset not held", take the close-pair-to-user terminal (NO WINNER autonomously). A trip after implementation begins additionally keeps the diff labeled PROVISIONAL INTERVENTION; a trip before Phase 2 emits the field and findings with NO WINNER regardless of user presence. A trip at Phase 4 does not un-run Phases 0–3; it stops the run from claiming their conclusions. A repaired run continues, but two late repairs mean artifacts are being produced by checklist-prompt rather than by executing the rules — the losing-the-thread signature. An unrepairable box terminates immediately under After NO WINNER. A labeled partial beats an unlabeled "complete" with silently dropped rules.

## Output format

Every tournament ends with: the rubric (weights + provenance), pre-registration vs. outcome, the per-round matrix (all candidates, DROPPED and REMOVED rows, OPINION flags, any redistribution visible), the decision trail, red-team findings with audit marks, then the implementation. ## Cost honesty

In full mode, deliberation stays in subagents; only summaries, matrices, and decisions return to the main thread. Lightweight pays its cost in main-thread context. Decision records ≤ 1 page plus the verbatim-candidates appendix. Every numeric constant in this file is a convention chosen to be countable, not a measured value — and the BENEFIT side is priced nowhere: no estimate exists for how often a tournament changes the outcome versus just fixing the thing, so every cost/benefit judgment here rests on an assumed benefit the file cannot support with data. Constants live in exactly one phase each; read them there (a stale copy here once contradicted the phase that owns the number). **Repetition counters** (both modes): Phase 0 REOPEN (one per tournament, shared across every reopen rule — a later rule wanting a spent counter prints "reopen declined — counter spent by <rule>" in the matrix and the Phase 4 checklist, so a suppressed finding is never silent) and After-NO-WINNER RE-ENTRY (one per problem). Full-mode budget effects: full-mode.md.

**Interaction budgets** live in the mode files. The user's attention is the least-budgeted resource here; every ask is a real interruption, and the terminal safeguard is a person. If the count feels high for the problem, the mode choice is wrong.

## After NO WINNER

Every NO WINNER exit hands the caller: the field (all candidates verbatim), the matrix as far as it got, the findings, and the specific rule that stopped the run. The underlying problem may still be stabilized with a minimal intervention explicitly labeled provisional and tracked as debt — the no-bandaid rule forbids silent bandaids, not declared stopgaps. The tournament may be re-entered exactly once, and only when the pack gains new evidence — so re-entry is REACHABLE only from stops that name missing evidence (a Phase 5 test failure, a route-2 detection failure, mid-implementation infeasibility, a fidelity mismatch) and UNREACHABLE by design from stops that name none (the two-strike termination, a second-collapse STOP, any PARTIAL EXECUTION terminal): those end the run, full stop. "New evidence" means a reproduction, a measurement, or a user decision — specifically the thing the stopping rule named as missing.

## When NOT to run this

- **Active incident with live user impact**: stabilize first with the smallest safe intervention, labeled temporary; tournament the durable fix immediately after, with the incident as Phase 0 evidence.
- **The user already decided**: implementing a named choice is not a competition. Note disagreement once if warranted, then build.
- **Trivially reversible changes** (undoable in under a minute, no data touched): just fix it.
- **Anything below the fixed-load floor** — and this OUTRANKS the proactive bandaid triggers: a 20-line special case for a reported input fires the trigger and clears the floor, and the floor wins. Run the tournament on a small bandaid only when a prior fix for the same symptom already failed — the one trigger the floor does not override. Countable version: one or two files touched, under ~100 changed lines, a test already exists or is trivial to add, and no failed prior attempt. Judge on those counts, never on wall-clock. A lightweight run also costs roughly two dozen distinct artifacts; for a bug whose entire fix plus test is smaller than that list, the artifact count is the wrong trade even when the line floor is technically cleared: fix it and say why.
  Sunk-cost accounting: by the time you read this rule the fixed load is spent; what remains is the MARGINAL cost (lightweight ~5–10k tokens; full ~40–80k plus reading full-mode.md). Judge against the marginal, not the total. One formula, so endpoints cannot be mispaired: overstatement factor = total / marginal = fixed/marginal + 1, never below 1.0 (a printed factor under 1.0 is an arithmetic error). Pair smallest fixed with largest marginal for the low end and the reverse for the high end. Current figures (recompute from the Cost table on any material edit — do not quote stale): LIGHTWEIGHT fixed 19–28k, marginal 5–10k → 2.9x to 6.6x; fixed share 66–85%. FULL fixed 25–36k, marginal 40–80k → 1.3x to 1.9x; fixed share 24–47%. Quoting lightweight's factor at a full-mode decision overstates that decision's sunk cost several-fold — recompute, never quote. If the fix is smaller than the marginal spend, the tournament costs more than the mistake it prevents. Attention is the scarcer resource: a tournament that interrupts the user twice to settle a ten-minute change has already lost.
- **Special cases that are the correct domain model**: a distinct code path for a genuinely distinct case (leap years, admin users, the empty cart) is design, not bandaging. The bandaid trigger means special-casing a REPORTED FAILING INPUT to dodge its root cause.
- **Directional or go/no-go decisions**: that is `council`, not a tournament.

**Cost to expect** (countable units; conventions, not measurements). Fixed load, measured post-restructure (`wc -c`/`wc -w`, 2026-08-12; recount on every material edit — every previous estimate erred optimistic): LIGHTWEIGHT loads this file (~9.8k words / 63k chars) plus `references/lightweight-mode.md` (~2.1k words / 14k chars) ≈ 19–28k tokens at 2.8–4.0 chars/token (markdown tables tokenize dense; plan on the top of the band). FULL loads this file plus `references/full-mode.md` (~5.9k words / 36k chars) ≈ 25–36k tokens, plus the templates at spawn time. Marginal spend and per-mode call/interaction arithmetic: each mode file's Cost section. An agent that cannot hold this file's counters and ordered gates WILL drop steps — the ledgers (mode files) exist for that, and the degraded-execution branch above is the honest terminal when they fail.
