# Solution Tournament

Generate → score → crossbreed → implement. The goal is a production-grade solution, not the first plausible one.

**Honestly:** one agent authors every artifact here, so no internal check can catch a favorite smuggled through framing. This is a discipline that raises the cost of choosing thoughtlessly, not an audit, and its output is not objective. This section describes; it binds nothing — rules live in their phases.

**Nine bias channels, none fully mitigated:**

| # | Channel | Partial counter |
|---|---|---|
| 1 | FRAMING QUALITY — the same agent writes every candidate's pitch | cross-advocacy pass; verbatim field shown to the user |
| 2 | SELF-SCORING — author grades own work | independent scorer subagents (full mode only) |
| 3 | PACK ERROR — a wrong pack fact yields a fully cited, confidently wrong winner | MEASURED/ESTIMATED tags; red-team pack interrogation |
| 4 | STRIKE AUTHORITY — main agent rules which citations are fake | STRUCK-cell visibility in the matrix |
| 5 | CORRELATED SCORER ERROR — same-model scorers wrong in the same direction: zero spread, no flag, decorated wrong matrix | NONE internally. Wider than scoring: the skeptic (who removes candidates) and red-team (whose FATAL overturns) are single agents with zero redundancy — more authority, less oversight, accepted in writing because duplicating them doubles cost while sharing priors. Only spikes and the user's read are external |
| 6 | SPIKE CONSTRUCTION — the builder chooses how hard to try, and spikes outrank the matrix | criteria written for both before either is built; red-team audits construction |
| 7 | MODE SELECTION — lightweight disables more safeguards in one self-assessed sentence than most channels combined | mode verdict artifact (Calibration) |
| 8 | FIELD CEILING — nothing here can see a better approach that was never generated | red-team's absent-approach duty, which can reopen Phase 1 |
| 9 | PACKET INTEGRITY — subagents are ASKED not to use tools and to reason only from the pack; nothing sandboxes them. A scorer reasoning from outside knowledge while citing genuine pack lines is undetectable | citation striking catches fabricated citations only; red-team Part 0 asks whether any scoring rationale references material absent from the pack |

DISPUTED detects divergence, never shared error: a zero-spread cell is uncontradicted, not corroborated.

**Definitions used throughout:**

- **User present**: an interactive session where a question can reach the user (e.g. AskUserQuestion). Anything else is autonomous. Two kinds of run carry the top-line statement "every safeguard in this run was self-administered": every autonomous run, and EVERY lightweight run regardless of user presence — lightweight self-scores, self-skeptics, and self-red-teams, so a clean decisive lightweight output otherwise reads as corroborated when one agent authored all of it.
- **Autonomous STOP fallback**: STOP means write the field and findings into the decision record with NO WINNER and do not implement. One row per branch, no exceptions hidden in prose. **Where this table and a phase's prose disagree, the PHASE governs and the mismatch is reported as a bug in this file** — the table is a convenience index, not a second rulebook:

| Branch | User present | Autonomous |
|---|---|---|
| Second collapse (removal of a regenerated slot) | show both fields, user decides | STOP |
| Both-wipeout by disqualification (2nd time) | NO WINNER, unconditionally — show field + rule | NO WINNER |
| Every dimension majority-OPINION | show, user decides | STOP |
| Any majority-OPINION dimension at weight ≥ 0.25 | user assents or not | STOP |
| Every finalist fatally flawed | show findings, user decides | STOP |
| Fatal-flaw claim without a citation | CONCERN, not FATAL: it kills nothing and the result proceeds unchanged (a winner stands; a close pair goes to its terminal rule), concern shown | same — proceed with the concern recorded |
| Unopposed sole survivor (or scoring < 5.0) | user confirms | STOP |
| Full-mode close pair red-team + spikes cannot separate | user picks | STOP |
| Lightweight close call | user picks | decide on self-authored findings + reversibility, label "unreviewed" |
| Near-miss within 0.3 of an effective gate | surface, user may override | threshold decides, label "unreviewed" |
| Plateau-uninformative / unusable NOISE / no carried anchor / broken removal premise | — | NOT a stop: routes to Phase 4 as a close pair, where the close-pair row above governs |

- **BINDING vs DISCIPLINE**: BINDING = violation is visible in the output to a reader who has this file (absence of a required artifact is only detectable by someone who knows it was required). DISCIPLINE = honest effort, unverifiable. Anything unlabeled is DISCIPLINE. Never present a DISCIPLINE step as a guarantee.

## Calibration: pick the mode first

- **Lightweight** (contained bug, single file, reversible): n=3, one round, no subagents, unblinded self-scoring with an anti-favorite pass — never called blind. Everything else applies.
- **Full** (architecture, cross-cutting, high blast radius, failed prior fix, data-integrity): n=5, subagent scoring, up to 3 rounds.
- **Lightweight is the default.** Full mode needs an explicit trigger. **Mode verdict artifact** (BINDING): the output lists every full-mode trigger — architecture / cross-cutting change / high blast radius / failed prior fix / data-integrity stakes / user request — with a present-or-absent verdict and one line of evidence each, so a reader can contest the classification against the pack. It also states whether a user is reachable; when no user is reachable, the mode DROPS to lightweight — a rule, not a suggestion — unless the user pre-authorized autonomous full mode in text quoted into the artifact. A disjunction the agent resolves for itself is not a safeguard, and autonomous full mode ends in NO WINNER on most branches, so choosing it unprompted is choosing to spend up to 16 calls on a matrix and no decision. When genuinely unsure, ask — one sentence.
- **The user can always stop it.** "Just patch it" is an instruction, not a debate opening: record the field so far, comply, label what the tournament had and had not established. Every anti-exit rule binds the AGENT only.
- **Downgrade when the problem deflates; never self-exit once the field exists.** In Phase 0, a trivial problem means exit and just fix it, noting why. From Phase 1 on, exit is not the agent's call: scoring the field is cheap, and "this deflated" is indistinguishable from "my favorite is the obvious one." Downgrading full → lightweight after Phase 1 is constrained the same way exit is: it must be announced with its reason, it PRESERVES every independent artifact already earned (returned subagent scores stay in the matrix; an already-run skeptic's verdicts stand), and the close-pair route still goes to the user when present — a downgrade forfeits future independence, never past independence.

## Phase 0: Evidence and rubric BEFORE candidates

Order is mandatory: pack → rubric → checkpoint → generation. Criteria or evidence chosen after seeing candidates become rationalizations for a favorite.

1. **Pack first** (BINDING): problem statement, the code and interfaces it touches, scale numbers, deadlines, constraints.
   - Every non-quote fact is tagged MEASURED (naming its command, file, or trace) or ESTIMATED (DISCIPLINE — the tag is self-assigned, and naming a command is not running it; a fact mislabeled MEASURED can promote a CONCERN to a FATAL); a score or FATAL resting solely on an ESTIMATED fact says so in the matrix. The red-team must challenge at least one MEASURED tag or state that every one names a re-runnable command, and must report explicitly when the pack contains ZERO MEASURED facts. **Evidence floor** (BINDING): a decisive gate, and any FATAL, requires at least one MEASURED fact bearing on the DECIDING DIMENSION — defined arithmetically as the dimension whose weighted score difference contributes most to the margin (weight × score gap between the top two); if two contribute equally, both need one; without it the round is a close pair labeled "all-ESTIMATED pack". The citation apparatus otherwise runs perfectly on the agent's own guesses and produces a fully cited winner grounded in nothing.
   - Write the pack to a file and print its SHA-256 BEFORE the first candidate appears; the decision record carries the pack verbatim so any reader can recompute. This detects an INCONSISTENT record, not a dishonest author — an agent that swaps the pack and reprints the hash produces a flawless single-authored document. The hash binds the record together; it does not certify the process.
   - The pack is frozen at the checkpoint. Later facts are allowed only when a subagent's OUTPUT requests one (subagents are single-shot and tool-less, so a request is a line in their report: "FACT REQUEST: ..."). The main agent then emits pack-v2 (then v3) with a fresh printed hash and a one-line diff, logs requester and reason, and re-spawns the affected scorer once against the NAMED version — at most 2 re-spawns; beyond that requests are declined and noted. Every version and hash appears in the record, every prompt names its version, and the matrix states which version each round used: there is no such thing as an unversioned pack edit.
2. Restate the problem in one paragraph, including how the current approach fails.
3. **Pre-register the expected winner** (DISCIPLINE — recorded, but self-reported and unverifiable): one sentence — "before generating, I expect some form of X to win." Recorded in the output and decision record; excluded from every subagent prompt. Its value: the agent must articulate its prior, and the user can compare it against the framing in the verbatim field. A match with the winner is uninformative alone (the prior is misreportable), so no scrutiny asymmetry attaches.
4. Define 4–6 scoring dimensions. Defaults (adjust per problem): root-cause resolution 30%, robustness/production-readiness 25%, maintainability/simplicity 20%, performance/cost 15%, implementation risk/reversibility 10%. Weights always sum to 1.0; after any user reweighting, normalize back to 1.0 and show the normalized weights — every threshold in this file assumes that normalization.
5. **Rubric checkpoint** (BINDING when a user is present): show the user the dimensions and ask them to rank or reweight — an approval of pre-filled weights is consent to defaults, not an expression of values, and the output must say which it got ("weights: user-edited" vs "weights: defaults, user-approved" vs "weights: defaults, autonomous run"). Skipping the checkpoint requires pre-authorization that names tournaments specifically, quoted in the output — ambient autonomy settings do not qualify. Weights freeze for the whole tournament; mid-tournament changes happen only at the user's initiative, and then both the before and after matrices are shown.
6. **Disqualification rule** (artifact BINDING; uniformity DISCIPLINE — the per-candidate results are visible, identical application is not falsifiable from the output):
   - Name the symptom as a falsifiable test: "this candidate leaves <observable root cause> in place; check: <what to look at>". Apply it to every candidate and show each result.
   - **VERIFIED diagnosis** (reproduction, trace, log, or measurement in the pack — cite it): a failing candidate is REMOVED from the field before ranking, n shrinks. Never scored 0.
   - **HYPOTHESIS diagnosis**: the rule removes no one. The candidate's root-cause dimension score is CAPPED AT 4 (if the rubric has no root-cause dimension, Phase 0 names which dimension inherits the cap). The cap is applied by the MAIN agent to returned scores — never in the scorer prompt, where naming the suspect would anchor its other dimensions — flagged in the matrix with the hypothesis and the scorer's original value. Ranks on the capped dimension are VOID: that dimension contributes no rank to the tiebreaker, which renormalizes over the rest, so a capped candidate never wins a tie on a rank the cap was meant to neutralize.
   - Removed candidates appear in the final matrix as REMOVED rows with the test, the cited evidence, and the VERIFIED/HYPOTHESIS call; their full text goes to the red-team packet so the removal is audited by someone other than its author.
   - **Precedence when the combined removal pass lands** (identical wording in Phase 1.5): ZERO survivors takes the Phase 0 reopen branch and never the regenerate branch — the diagnosis or rubric is wrong, so reopen Phase 0 once, and a second wipeout ends the tournament with the field, the rule, and NO WINNER. The regenerate and sole-survivor rules apply only when at least one candidate survives.
   - Timing: three ordered steps at the Phase 1.5 boundary — (a) apply the DQ test to all candidates and record verdicts; (b) run the batched skeptic on the full field, removed text included for context; (c) count DQ removals and filler verdicts together and take the removal branch.
7. Read prior decision records: `docs/decisions/NNNN-*.md` via the `docs/decisions/INDEX.md` one-line-per-record index (skip with a note when there is no repo). Records are dated claims: before carrying a rejection forward, verify its blocker still exists.

## Phase 1: Divergent generation (n candidates)

- Each candidate differs from every other on a **named structural axis** (architecture, data model, dependency, algorithm class, where-the-logic-lives). Slot #1 is the obvious approach, named as such. At least one candidate is a credible long shot — the test: could it plausibly win one rubric dimension outright? A field of paraphrases is a failed generation: regenerate once; if the problem genuinely has fewer than n distinct axes, run with what exists (minimum 2) and say so.
- Per candidate: mechanism, what it assumes, what breaks it — **90–150 words each** (countable, checkable; "equal length" is not). **Candidate hashes** (RECORD-BINDING — binds the record to itself, not the author; see the caveat below): when the field is frozen at the end of Phase 1.5 (post-revision, post-removal), print each surviving candidate's mechanism-text SHA-256 next to its label. The same hashes appear in the scorer packet, in the verbatim field shown to the user, and in the decision record. Same caveat as the pack hash, and it matters more here: this detects transcription drift between the shown and recorded text, NOT a dishonest author — one agent prints both the text and its hash, and no reader ever sees the packet a subagent actually received, so a substituted candidate with a re-printed hash is undetectable. Framing quality is the highest-bandwidth bias channel, the user is its only real detector, and this mechanism helps the user hold one version of the text rather than proving anything.
- **Cross-advocacy pass** (DISCIPLINE, full mode only — lightweight skips it, since its unblinded scorer sees the generation reasoning regardless): after drafting all candidates, rewrite each one's mechanism as its strongest advocate would write it, and state in the output that this pass ran. Framing quality is the highest-bandwidth bias channel and no downstream mechanism can detect it; this is the honest-effort counter.
- "What breaks it" names a rung on a fixed severity ladder — data loss / correctness / performance / effort — so severity is comparable across candidates rather than rhetorical.

## Phase 1.5: Skeptic pass (before scoring)

- **One batched skeptic call** (fresh subagent in full mode — see `templates/skeptic.md`; in lightweight mode, write all critiques and premortems before assigning any score — ordering discipline, not independence): attacks ALL candidates in one pass and authors, for each, critique → revision guidance → premortem. The skeptic, not the generator, writes every premortem, in one call, holding severity comparable across candidates: each premortem (≤80 words) names its failure class from the severity ladder plus a likelihood and a detection point ("would surface at integration"), so scorers grade the risk, not the vividness of the story.
- **Filler verdict** (BINDING): a candidate with no plausible path to winning ANY dimension is DROPPED before scoring.
  - The verdict text appears in the final matrix as a DROPPED row: a culled field must be visible, never silent. In lightweight mode every DROPPED and REMOVED row also carries "self-authored removal" — the skeptic there is the generator wearing a different hat.
  - Removal precedence (DQ removals and filler verdicts count together as one number): ZERO survivors takes the Phase 0 reopen branch and never the regenerate branch (Phase 0.6); the rules here apply only when at least one candidate survives. Then FIRST the failed-generation rule — more than one removal in the combined pass means regenerate the culled slots once, and regenerated slots get the DQ test plus an **abbreviated skeptic pass** — defined once, here: critique + premortem + filler verdict for the new candidates only, no revision round, no re-critique of surviving candidates. Phase 3's crossbreed offspring use this same definition. A second collapse — ANY removal of a regenerated slot, either type — means stop and show the user both fields with the verdicts.
  - Only past that rule does the sole-survivor rule apply: a lone survivor is still SCORED solo against the rubric (scoring one candidate is nearly free and produces the matrix). It proceeds to Phase 4 only at a weighted total ≥ 5.0, carries the line "sole survivor — ran unopposed", and a present user confirms it as a decision. Below 5.0, or in any autonomous run, an unopposed survivor is NO WINNER: report the field, do not implement.
- **Revision**: each survivor gets one strengthening pass that may not change its named axis. Whether a proposed fix crosses the axis is the skeptic's call, made in the batched call with the axis named — not the generator's call afterward.
- **Show the user the field** (BINDING when a user is present): at the end of Phase 1.5, output the candidates' mechanism texts and premortems verbatim (not summaries), each with its SHA-256 as printed at freeze. Framing bias is visible to a human reading the raw text and invisible to every mechanism inside the skill. In autonomous runs, the verbatim field goes in the decision record instead.

## Phase 2: Adversarial scoring (independent only in full mode)

Not "blind": label-shuffling removes authorship and ordering effects, but nothing hides which candidate is the conventional one, and scorers share the generator's model priors — their agreement is consensus, not evidence. The mechanisms below raise the cost of vibes; they do not turn scores into measurements.

**Scoring procedure — run in this order.**

0. **Completeness gate on return**: confirm the subagent scored every label sent and produced every required field, AND that the return is responsive: each scored dimension carries at least one candidate-specific locator — naming a mechanism element, assumption, or premortem clause unique to THAT candidate, such that the sentence would be false if pasted under another candidate's row. Generic rationale that would fit any candidate fails. Shaped-but-hollow is the likeliest low-effort failure and the one a presence check misses; an unresponsive return demotes the round to a close pair labeled "unresponsive scoring". A short or malformed return gets ONE re-spawn; a second short return has a named outcome per artifact, never a generic one:
   - **Scorer**: round is a close pair labeled "incomplete scoring".
   - **Skeptic**: its candidates carry "no premortem — ungraded risk" in the matrix and the round is demoted to a close pair.
   - **Red-team**: on a close pair, drop to the surviving finalist's report and treat the pair as unseparated (user decides, or NO WINNER autonomously); on a DECISIVE winner there is no pair to fall back on, so the winner cannot be confirmed — user decides with the partial report when present, NO WINNER when autonomous. A partial red-team is never an implicit pass; it is the only artifact that can overturn the matrix.

1. **Scale**: 0–10 per dimension (2 = serious deficiency, 5 = adequate with real concerns, 8 = strong with minor concerns). **Weighted total = Σ(weight × score)**, weights summing to 1.0, so totals and margins live on the 0–10 scale.
2. **Margin, defined once**: the difference between the TOP TWO weighted totals in whatever comparison the current gate names — decisive gates use the round's best two; the plateau gate uses best offspring vs the carried anchor. The **carried anchors** are the two parents that entered the current round; the plateau comparison uses whichever scores higher in the CURRENT round (both totals shown). Next-round succession is a separate end-of-round computation in Phase 3.
3. **Who scores**: full mode spawns a scoring subagent (`templates/scorer.md`) receiving ONLY the frozen pack plus candidates and premortems under neutral labels. Two scorers whenever ANY full-mode trigger was architecture, data-integrity, or a failed prior fix; one otherwise. What the second same-model scorer buys, plainly: DISPUTED divergence and STRUCK-cell recovery — real but narrow, since correlated error passes both. When the choice is a second scorer or a spike, prefer the spike: it is the only externally grounded artifact here. Lightweight mode self-scores unblinded, says so in the output, and follows the same numbered procedure as a scorer subagent — including the forced 1..n ranking, which the tiebreaker in step 10 needs and which matters MORE here (n=3 self-scoring is exactly where 7–8 clustering happens) — writing the strongest case AGAINST each candidate before assigning any number.
4. **Label order**: candidates are ordered by the frozen mechanism-text SHA-256s from Phase 1.5, which are also listed in the scorer packet so the scored text is bound to the shown text. DISCIPLINE: this removes incidental generation-order effects; it cannot resist deliberate authorship, since the agent writes the hashed text.
5. **Cite before scoring**: for each dimension, state which pack facts bear on it — the same fact set for all candidates — then score against them with quote + locator. A cherry-picked true fact still serves a prior, so this raises the cost of vibes; it does not make scores follow from evidence.
6. **Verify citations** (main agent, on return):
   - A citation absent from the pack STRIKES the cell. Struck cells are marked STRUCK in the matrix with the fabricated citation quoted, in both scorer modes.
   - Striking VOIDS that scorer's ranks on that dimension; the tiebreaker renormalizes over the remaining dimensions, exactly as the HYPOTHESIS cap does. No tie is decided by a rank whose score no longer exists.
   - Recovery, in order: take the other scorer's value if one survives → else re-score (main agent, marked SELF-SCORED) if re-score budget remains → else mark the cell UNSCORED, exclude that dimension's weight from this candidate's total (renormalizing the rest), and make the round a close pair. A voided score never silently reverts to the struck value.
7. **Combine scorers**:
   - The cell shows BOTH raw scores and their mean; the mean enters the total. Spread ≥ 3 points flags DISPUTED.
   - **Re-score budget**: 2 main-agent re-scores per tournament, shared across both paths (struck-cell recovery and DISPUTED). The matrix prints the count of main-agent-scored cells — the channel through which independent scoring reverts to self-scoring must be visible.
   - **Precedence**: a cell that is both struck and DISPUTED resolves striking first, then re-examines for DISPUTED only if two values still exist.
   - **DISPUTED consequence** (when the disagreement could move a gate — weight × spread ≥ 1.0): one re-score against the pack, which REPLACES the cell rather than averaging into it. "Surviving spread" is measured between the re-score and the FARTHER original: still ≥ 3 → the cell takes the lower of the two originals and the round becomes a close pair regardless of margin; under 3 → the re-score stands alone and the round proceeds.
   - Below that trigger, DISPUTED is disclosure only. Derivation: max spread on a 0–10 scale is 10, so the trigger is unreachable exactly on dimensions weighted under 0.10. Past the budget, qualifying cells take the lower value directly.
   - Rank inversions between scorers are surfaced as disagreement, never smoothed.
8. **OPINION**: a score with no citable fact is OPINION at full weight; a cell counts as OPINION only if both scorers marked it — and with a SINGLE scorer (lightweight, or the one-scorer full tier), that scorer's mark alone makes the cell OPINION, so the safeguard never silently switches off in the most common configuration. Declining to cite is a weight lever, so a majority-OPINION dimension is a FINDING in the matrix, never a silent mechanic.
9. **Redistribution** — one of exactly TWO exceptions to the Phase 0 weight freeze (the other: a user-initiated mid-tournament reweight, Phase 0.5); either makes NOISE unusable for the following round under rule 1's "weights changed" clause: a majority-OPINION dimension's weight may be redistributed proportionally (renormalize to 1.0) ONLY with the user's explicit assent, forbidden in lightweight and autonomous runs, and forbidden past ONE dimension per tournament. Once applied it persists for all remaining rounds so cross-round comparisons stay under one weight set; both weight sets appear in the record. If EVERY dimension is majority-OPINION, the pack cannot support scoring: NO WINNER this round — reopen the pack once, or end.
10. **Ties**: when totals land within 0.3 points, the tiebreaker is **weighted mean rank** = Σ(weight × rank), lower wins (with two scorers, the mean of their weighted mean ranks). Forced ranking (1..n, no ties) exists to break 7–8 clustering; ranks never enter the total. A surviving tie routes like any close margin in the current mode.
11. **Falsify the removals** (after scores exist): every removal is re-checked against the matrix. A filler verdict's domination argument fails if its named dominator was scored and did not win that dimension; if the named dominator was itself removed and has no matrix row, the verdict is UNFALSIFIABLE, not broken; a cited-fact verdict fails if the matrix contradicts the fact's implication; DQ removals are UNFALSIFIABLE BY DEFAULT (a candidate removed before ranking has no matrix row to contradict anything) and carry that label unless the matrix holds a row directly testing the removal's premise. Any failure is a BROKEN REMOVAL PREMISE — the removal stands (re-scoring mid-stream would unfreeze the field), but the round is demoted to a close pair, the dropped candidate's verbatim text goes to the user or the record with the finding, and no decisive result may be claimed on a field culled on a false premise. Removals that cannot be falsified this way are labeled UNFALSIFIABLE REMOVAL in the matrix, so the reader knows which culls were never tested.

- Show the full matrix — including DROPPED and REMOVED rows — never just the winner.

## Phase 3: Decision gate

Mode precedence table:
- FULL mode: every branch below.
- LIGHTWEIGHT row: never crossbreeds. Margin > 1.0 → winner alone to Phase 4. Margin ≤ 1.0 → both finalists to Phase 4, then the choice goes to the USER with the matrix and red-team findings whenever a user is present (self-scored close calls are exactly where self-scoring fails; do not resolve them alone). Autonomous: decide on red-team findings plus reversibility and label the result "close call, self-scored, unreviewed".

"Close pair" everywhere below and in Phase 4 means the top two by current weighted total arriving at Phase 4 together, by ANY route that declines to name a single winner — lightweight close, plateau, exhausted rounds, unusable or excessive NOISE, no surviving carried anchor, or a broken removal premise. The list is open by construction: any rule in this file that says "close pair" produces one. The Phase 2 within-0.3 tiebreaker orders a close pair; it never substitutes for these routes.

- **Decisive**: margin > 1.0 weighted points → the winner alone proceeds to Phase 4.
- **Close** (≤ 1.0): crossbreed round. Maximum 3 scoring rounds — the initial round plus up to 2 crossbreed rounds.
  - Pool = z offspring (default 3) + the top 2 parents, who re-race as carried anchors.
  - Offspring pass the abbreviated skeptic pass (defined in Phase 1.5) and the DQ test before scoring. That pass may also remove a CARRIED ANCHOR whose premise the last round's scores undercut — the only route by which an anchor leaves the field.
  - Crossbreed rounds do NOT inherit Phase 1.5's regenerate-once machinery (offspring already are a regeneration): losing one offspring proceeds with the rest; losing more than one, or any anchor, makes the round a close pair on the survivors. A round that cannot field a real contest does not name a winner.
  - Each offspring names its inherited traits; one is a **mutation** (a single assumption perturbed); and at least one is seeded from the highest-ranked candidate that is NOT the pre-registered favorite, with the excluded mechanism named. The MATCH/NO-MATCH call is printed with one reason; on NO-MATCH, seed from the highest-ranked non-leader and name the leader's mechanism as excluded. The pre-registration goes to the RED-TEAM packet only (never the scorer's), and the match call joins the red-team's audit duty — moving the one self-refereed anti-favorite check off its own author without leaking the prior into scoring.
  - An offspring inheriting from a HYPOTHESIS-capped parent carries the same cap on the same dimension, shown in its row: crossbreeding is not a route for a disqualifying trait to re-enter untested.
- The INITIAL round has no re-scores, so its decisive gate rests on the fixed threshold alone — the matrix says so.
- After each crossbreed round, evaluate in this exact order — the FIRST matching rule wins:
  1. **Noise floor**: the CARRIED ANCHORS are the two parents that entered this round with unchanged text. For each carried anchor compute |current total − previous total|; NOISE = the larger of those two values, in weighted-total points (it is a per-anchor re-score delta, never the gap between the two anchors). NOISE needs two unchanged-text re-scores under UNCHANGED weights AND the SAME pack version to be usable — a redistribution round or a pack-version bump between rounds produces no usable NOISE ("noise: weights changed, unusable" / "noise: pack version changed, unusable" → fixed thresholds), because re-scoring the same text against changed evidence measures re-evaluation, not scorer variance; with one sample, fixed thresholds and the label "noise: one sample, unusable"; with zero, the round cannot be decisive — close pair. If NOISE > 1.5, this round's scoring cannot support any gate: close pair, reason printed. If NO carried anchor survived the round (both drew removals), the plateau test has no referent: close pair by default. Otherwise every gate below must clear its fixed threshold AND NOISE. 
  2. **Plateau test**: no offspring beat the higher-scoring CARRIED anchor (this round's totals) by more than max(0.5, NOISE) → stop; top two by current totals to Phase 4 together. Plateau outranks the decisive gate deliberately: an anchor that only widened its lead over weak offspring the same agent generated has been flattered, not tested.
  3. **Decisive gate**: margin > max(1.0, NOISE) → that round's winner alone to Phase 4.
  4. **Rounds exhausted** (after round 3): top two to Phase 4 together.
  5. Otherwise: next crossbreed round.
  After the branch is chosen (separately — succession is a computation, not a branch): the two highest-weighted-total candidates of this round, offspring included, become the next round's carried anchors.
- **Near-miss surfacing** (surfacing BINDING; the symmetry of its wording DISCIPLINE — a reader sees that a near-miss was surfaced, never that the wording would have been identical with the favorite on the other side): EVERY numeric threshold in this file is an uncalibrated convention, so every decision resting on one surfaces when the value lands near it — not just the gates. Bands: 0.3 on any 0–10 scale quantity (decisive margin, plateau delta, the 5.0 sole-survivor floor, the 3-point DISPUTED spread, the 0.3 tiebreak band itself, weight×spread 1.0), 0.2 on NOISE (including the 1.5 ceiling), and one unit on any integer counter (removals, rounds, attempts, re-spawns). Measure against the EFFECTIVE threshold actually applied — max(1.0, NOISE) for decisive, max(0.5, NOISE) for plateau. Surfacing is identical in wording whichever side the favorite is on, with the agent's own preference stated separately so the user can discount it; autonomously, record the near-miss with both sides flagged, take the threshold's outcome, and label it "decided by threshold, unreviewed". Near the line, judgment decides, not arithmetic.

## Phase 4: Red-team, spikes, and audit

Routing: a decisive winner is red-teamed alone; a close pair (by any route — see Phase 3) is red-teamed in one packet covering both finalists. Fresh subagent in full mode (`templates/red-team.md`); in lightweight mode the MAIN agent runs the red-team questions itself — SELF-ADMINISTERED, and any decision resting on those findings (including the autonomous lightweight close call) says the findings were self-authored.

- **The red-team is pack-bound, and that is a stated limit**: it reasons over the pack, so a flaw real in the code but absent from the pack cannot be FATAL — it degrades to CONCERN and transfers nothing. Escape hatch: when the red-team's Part 0 names a fact it would want verified, the MAIN agent may run READ-ONLY verification (read the file, run the existing test, query the log) and return the result as a pack-v2 fact, after which the red-team may escalate CONCERN to FATAL on it. An unverified Part 0 concern is a required matrix row, never prose — pack blind spots are otherwise invisible to the only mechanism that can overturn the matrix.
- **Absent-approach duty**: the red-team names one credible approach missing from the Phase 1 field, or states none exists. A named absent approach that could plausibly win a rubric dimension reopens Phase 1 once, charged to the tournament's single reopen counter — the field ceiling is the one bias no internal scoring can catch, so the only agent with fresh eyes is asked directly.
- **Evidence bar for overturning** (BINDING): Phase 2 demands a cited fact to move a score; overturning the whole result demands no less. A fatal-flaw verdict must cite a pack fact or a spike result. A flaw asserted without one is presented to the user alongside both candidates — it does not transfer the crown on the agent's say-so. If a cited fatal flaw stands, the runner-up (already red-teamed if the race was close) is checked the same way; if every finalist is fatally flawed, stop and return the field with findings to the user.
- **Audit duty** (full mode): the red-team subagent also receives the premortems, score citations, and (if any) spike criteria, and marks each SUBSTANTIVE or MECHANICAL. Its marks go in the output. This moves the honesty check off the agent that produced the artifacts.
- **Spike gate** (FULL-mode close races on code problems; lightweight never spikes):
  - Before building anything, write down for BOTH finalists: the assumption under test (from its premortem), the pass/fail criterion, and what production conditions the spike does NOT reproduce. Same criterion rigor for both.
  - Budget 2 attempts and ≤150 changed lines per spike (countable — wall-clock is not). A spike that exhausts its budget reports "risk confirmed expensive to derisk", which is itself evidence.
  - The MAIN agent builds both spikes; the red-team judges results and never builds. Build in the session scratchpad or a throwaway worktree, delete before Phase 5, never promote spike code.
  - A spike result outranks judgment about the specific assumption it tested and nothing else. A cited standing FATAL is the only other artifact that can overrule the matrix, so the red-team's audit marks each spike's CONSTRUCTION as well as its result.
  - Declaring a problem non-spikeable requires naming what could not be built, in the output.
- Standing questions: What happens at 10x? In 6 months, context forgotten? Which single assumption, if false, kills it — and how would we detect that early? Is any part a bandaid wearing a suit (special cases, silenced warnings, magic constants, "temporary" flags)?
- **Close-pair terminal rule** (BINDING): when both finalists survive red-team and spikes do not discriminate (both pass, both fail, or no spikes ran), the tournament has separated all it can: the choice goes to the USER with both red-team reports, the spike criteria and results, and the final matrix. Autonomous: NO WINNER per the uniform fallback — a full-mode close pair is never resolved by the agent's unaided preference. A discriminating spike result or a standing FATAL selects the survivor.

## Phase 5: Implement to production standard

- Enter plan mode first if the change touches multiple files or systems; spikes must already be deleted. Production standard: tests covering the failure mode that motivated the tournament, error handling for the assumptions identified in Phase 1, no TODOs standing in for decisions.
- **Fidelity gate** (artifact BINDING, the assertion itself DISCIPLINE): before the decision record is finalized, restate the winner's named structural axis and mechanism against the NAMED diff hunks that realize it — file plus function per claim, so a reader can spot-check the mapping rather than trust a bare assertion. Building something other than the winner — most temptingly, quietly reverting to the obvious slot-#1 approach — is a re-entry condition, not a footnote. If the winner proves infeasible mid-implementation, that infeasibility is new pack evidence: stop, record it, and re-enter the tournament under the After NO WINNER rule with the runner-up's red-team findings already in hand.
- **Decision record** (BINDING): `docs/decisions/NNNN-<slug>.md` plus a one-line append to `docs/decisions/INDEX.md` (create both if absent; use the project's ADR home if one exists; with no repo, put the record's content in the session output and say there is nowhere durable to write it). Contents: problem, rubric with weights and their provenance (user-edited / defaults-approved / autonomous), pre-registered expectation vs. actual winner, full matrix per round including DROPPED rows, verbatim candidate texts with their frozen hashes (autonomous runs), red-team findings and audit marks, and the countable costs: candidates generated, subagent calls, rounds, spike attempts. Do not log token guesses as if measured — count what is countable.

## Phase exit checklists (co-authoritative with the prose)

Absence of a required artifact is invisible to a reader who does not know it was required — this list is what makes absence visible to a reader who has this file and the full output. It is a self-administered inventory in the same self-authored output; it catches dropped steps, not determined omission. A phase is not exited until its artifacts exist; a missing box is a violation even when every prose rule was "substantially followed". Division of authority, so no conflict is possible: these checklists are pure artifact inventories (WHAT must exist); every rule, threshold, and branch lives in the prose (WHEN and HOW). Mode-dependent boxes bind only in the modes that produce them.

- **Exit Phase 0**: pack file + tagged facts + printed hash (v1) · problem restatement · pre-registration sentence · normalized weights + provenance line · DQ falsifiable test authored · decision-record index read (or no-repo note).
- **Exit Phase 1**: n candidates, each with named axis + 90–150w mechanism + assumptions + severity-rung breaks · obvious slot named · long-shot slot named · cross-advocacy statement (full mode).
- **Exit Phase 1.5**: frozen candidate hashes printed · per-candidate DQ verdicts · skeptic critiques + premortems (class/likelihood/detection) · filler verdicts with citation or domination argument · removal count vs threshold branch taken · verbatim field shown (or in record).
- **Exit Phase 2**: matrix with both raw scores per cell (two-scorer runs; single-scorer and lightweight runs carry one score plus their self-scored labeling), ranks, citations or OPINION marks, STRUCK/SELF-SCORED/DISPUTED/OPINION flags · DROPPED and REMOVED rows with their verdicts · removal-falsification results · weighted totals · pack version named per round.
- **Exit Phase 3**: branch taken named with its rule number · anchor totals + NOISE line (crossbreed rounds only; round 1 states "fixed threshold only") · MATCH/NO-MATCH seeding line (crossbreed rounds) · near-miss handling if within the band.
- **Exit Phase 4**: any declined-reopen line · red-team report(s) with FATAL/CONCERN/FIXABLE classifications + citations · audit marks · spike criteria-before-results (if spiked) · close-pair terminal decision by user or NO WINNER.
- **Exit Phase 5**: tests for the motivating failure · fidelity gate mapping (axis → named diff hunks) · decision record + index line · repairs-applied line (or "none").

## Operator spine (traversal order; every rule lives in the section pointed to)

No thresholds are restated here — a stale copy once contradicted the rules it summarized. The order decision points arrive, each with its governing section: 1. Mode verdict, user reachability → Calibration. 2. Pack, pre-registration, rubric checkpoint, DQ authoring → Phase 0. 3. Generate; diversity check → Phase 1. 4. DQ verdicts, skeptic, removal-count branch, field shown → Phase 1.5. 5. Score; citation verification; DISPUTED/OPINION handling → Phase 2. 6. Gates (initial-round rule vs crossbreed rules); anchor succession; near-miss → Phase 3. 7. Red-team incl. absent-approach duty and audit; spikes (full mode) → Phase 4. 8. Close-pair terminal decision → Phase 4. 9. Fidelity gate, decision record → Phase 5. At every STOP: the After NO WINNER section. The exit checklists say WHAT must exist; the prose says WHEN and HOW.

## Output format

Every tournament ends with: the rubric (weights + provenance), pre-registration vs. outcome, the per-round matrix (all candidates, DROPPED and REMOVED rows included, OPINION flags and any weight redistribution visible), the decision trail, red-team findings with audit marks, then the implementation. Never present only the winner.

Final self-check (DISCIPLINE — self-administered and labeled as such): reread the artifacts once for box-filling. For EVERY finalist that reached Phase 4 — symmetric, so repair cannot ratchet the winner's record above the field's — a mechanical premortem, an uncited score, or an empty red-team pass is redone AND logged: a "repairs applied" line in the matrix lists each redone artifact, whose it was, and why (correction and disclosure are not in tension; a repaired record with no repair log is the process's own silent-failure channel). For candidates eliminated before Phase 4, disclosure alone suffices. An output with no weakness labels has not been vetted; it has been self-reviewed, which catches obvious lapses and not systematic ones.

## Cost honesty

In full mode, deliberation stays in subagents; only summaries, matrices, and decisions return to the main thread (lightweight mode has no subagents and pays its cost in main-thread context — see the cost table). Decision records ≤1 page plus the verbatim-candidates appendix. The constants in this file (1.0 decisive, 0.5 plateau, 0.3 near-miss, 3 rounds, 2 spike attempts, 150 spike lines, the cap of 4, z=3, 90–150 and ≤80 word bands, the 5.0 sole-survivor floor, the ≥3-point DISPUTED spread, the weight×spread ≥ 1.0 re-score trigger, the 1.5 NOISE ceiling) are conventions chosen to be countable, not measured constants; the countable costs logged per record are what could eventually justify moving them.

## After NO WINNER

Every NO WINNER exit hands the caller: the field (all candidates verbatim), the matrix as far as it got, the findings, and the specific rule that stopped the run. The underlying problem may still be stabilized with a minimal intervention explicitly labeled provisional and tracked as debt — the no-bandaid rule forbids silent bandaids, not declared stopgaps. The tournament may be re-entered exactly once, and only when the pack gains new evidence (a reproduction, a measurement, a user decision) that the stopping rule named as missing.

## When NOT to run this

- **Active incident with live user impact**: stabilize first with the smallest safe intervention, labeled as temporary; tournament the durable fix immediately after, with the incident as Phase 0 evidence. A tournament during the fire is process harming users.
- **The user already decided**: implementing a named choice is not a competition. Note disagreement once if warranted, then build.
- **Trivially reversible changes** (undoable in under a minute, no data touched): just fix it.
- **Anything below the fixed-load floor**: the skill costs ~7–9k tokens to load plus ~5–10k to run lightweight, and 2–4 user interruptions, before it decides anything. If the fix itself is smaller than that — a contained change you could write and verify in well under an hour, with no failed prior attempt — the tournament costs more than the mistake it prevents. Just fix it and say why the tournament was skipped. Attention is the scarcer resource: a tournament that interrupts the user twice to settle a ten-minute change has already lost.
- **Special cases that are the correct domain model**: a distinct code path for a genuinely distinct case (leap years, admin users, the empty cart) is design, not bandaging. The bandaid trigger means special-casing a REPORTED FAILING INPUT to dodge its root cause, not modeling real domain structure.
- **Directional or go/no-go decisions**: that is `council`, not a tournament.

**Cost to expect** (countable units; every number here is a convention, not a measurement). Both modes first pay a fixed load: this file (~4.5k words) plus the three templates (~1k words) ≈ 7–9k tokens by the usual word-to-token ratio (ESTIMATED, same derivation style as below), before a single candidate exists — the largest single line item for lightweight, unavoidable in either mode. The user's attention is the least-budgeted resource here: lightweight asks for 2–4 interactions (rubric checkpoint, verbatim field, and a close-pair or sole-survivor decision when they arise), full mode 3–8 — universal near-miss surfacing means several thresholds can trip in one run, and each trip is an interruption. If that count feels high for the problem, the mode choice is wrong. Every one is a real interruption; the terminal safeguard is a person:

- **Lightweight**: 0 subagent calls, but ALL deliberation lands in the main thread. Countable artifacts: 3 candidates × (90–150w mechanism + assumptions + breaks) + 3 critiques + 3 premortems (≤80w) + ~5 dimensions × 3 cited scores + matrix + red-team questions ≈ 2,000–3,500 words of output, so roughly 5–10k tokens of context including the reasoning around it (ESTIMATED — derived from the word bands above, not measured). Refusing to guess would be honest; refusing to bound is not useful. To keep it honest, lightweight skips the cross-advocacy pass (its scorer sees the generation reasoning anyway) and NEVER spikes: a symmetric spike comparison costs two builds, and a problem worth two builds has left the "contained and reversible" class. A lightweight close pair that red-team plus reversibility cannot separate goes to the user, or autonomously takes the smallest safe fix labeled provisional.
- **Full**: main-thread context stays near the lightweight figure (summaries, matrices, decisions only — deliberation lives in subagents, which pay their own context separately). 4 subagent calls on the common path (skeptic + scorer + red-team, +1 scorer at the two-scorer tier); 6–8 when a crossbreed round runs. Derived from the branch structure, not surveyed — no usage data exists yet.
- **Hard maximum 16 calls**: 1 skeptic + 1 regeneration skeptic + up to 2 abbreviated crossbreed skeptics + up to 6 scorers (2 × 3 rounds) + 2 red-team (one packet covers a close pair — "in parallel" means both finalists in one call, not two — leaving the second call for the Part 0 escalation re-spawn or the runner-up path) + up to 2 fact-request re-spawns (further requests declined and noted) + up to 2 completeness-gate re-spawns from ONE shared pool, allocated red-team > scorer > skeptic (the red-team's partial outcome is harshest, so it has first claim); with the pool empty, any further malformed return takes its named partial outcome immediately. DISPUTED and struck-cell re-scores are main-agent actions, not calls. That is 16, not 14 — the ceiling is 16.
- **Two repetition counters**: Phase 0 REOPEN (one per tournament, shared across every reopen rule here — when a later rule wants a reopen the counter has already spent, it prints "reopen declined — counter spent by <rule>" in the matrix and the Phase 4 checklist, so a suppressed finding, especially an absent-approach one, is never silent) and After-NO-WINNER RE-ENTRY (one per problem). A reopen restarts the 16-call budget (32 for the tournament); a re-entered tournament may not reopen, so its ceiling is 16. Absolute worst case per problem: 32 + 16 = 48 calls. If that alarms you for this problem, it should — recalibrate the mode before starting, not mid-run.
- **Autonomous honesty**: autonomous full mode ends in NO WINNER on every close-pair, all-flawed, sole-survivor, and majority-OPINION branch — a large fraction of realistic runs — potentially spending the full budget to deliver a matrix and no implementation. That is the design, not a failure. When the user is unreachable, prefer lightweight or defer to a session where they are not.

## Related skills

- `council` — one-line test: if the deliverable is a chosen implementation, tournament; if it is a direction or go/no-go, council.
- `architecture-decision-records` — the Phase 5 record follows ADR conventions.
- `tech-stack-evaluator` — when candidates are technology choices rather than implementations.
- `verification-loop` — run after Phase 5 before calling the winner done.
- Cheaper neighbors: one artifact needing critique (not competing implementations) → a single adversarial review; a hard tradeoff with no buildable candidates → `hard-call`; testing an existing system's limits → stress testing. The tournament earns its cost only when genuinely different implementations must compete.
